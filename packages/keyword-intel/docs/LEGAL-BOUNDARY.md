# LEGAL-BOUNDARY — commerce-keyword-intel

**작성일:** 2026-07-23

> 이 문서는 "이 모듈이 왜 합법인가"와 "**넘으면 안 되는 선**"을 명시한다.
> blueprint-review 감사에서 원안 파이프라인을 DO-NOT-BUILD로 만든 위법 요소들이
> 이 모듈에 **다시 스며들지 않도록** 하는 방어선이다.

---

## 1. 왜 이 모듈은 합법 원자인가

| 원안의 위법 요소 | 이 모듈의 처리 |
|---|---|
| 샤오홍슈/틱톡 **스크래핑 다운로드** (저작권법 §136 비친고죄) | ❌ 없음. 네이버 **공식 API**만 호출 |
| 메타 API **우회/에뮬레이터** (플랫폼 ToS 위반) | ❌ 없음. 배포 기능 자체가 이 모듈에 없음 |
| GPT-4V **크로스매칭** bait-and-switch (부정경쟁방지법) | ❌ 없음. 상품 매칭/전환 기능 없음 |
| 무검수 광고 대량생성 (식품표시광고법 §8) | ❌ 없음. 광고 생성 기능 없음 |
| 홈쇼핑 **낙수 트리거** (자체 데이터로 반증) | ❌ 계약·코어에서 배제. "참고 지표"로만 |

**즉 이 모듈은 "사실 데이터를 공식 채널로 조회·가공"하는 것이 전부다.** 그래서 합법이다.

---

## 2. 넘으면 안 되는 선 (이 선을 넘으면 다시 위법 지대)

### 🚧 경계 1 — 스크래핑으로 "보강"하지 말 것
네이버 API가 안 주는 데이터(예: 경쟁사 상세페이지 원문, 홈쇼핑 편성표)를 크롤링으로 채우고 싶어질 수 있다.
그 순간 이 모듈은 원안의 위법 스크래퍼로 되돌아간다. **API가 안 주면 그 데이터는 이 모듈의 범위 밖이다.**

### 🚧 경계 2 — 데이터 재판매/재배포 (D1-5에서 확정 필수)
네이버 오픈API 약관은 통상 **수집 결과의 원본 재판매·제3자 제공·검색결과 그대로 노출**을 제한한다.
- 계약의 `compliance.resaleRestricted` 는 **약관 확인 전까지 `true`(보수적)** 로 둔다.
- 셀러에게 리포트를 팔고 싶다면, "네이버 원본 데이터 판매"가 아니라 "**자체 가공 인사이트/스코어 제공**"으로
  성격이 바뀌어야 하며, 그조차 약관 원문(D1-5)으로 허용 범위를 확인한 뒤에만 진행한다.
- ⚠️ 이 항목은 **미검증**이다. 2026-07-23 자동 실측 시도 결과: 약관 원문
  (`developers.naver.com/products/terms`) 접근이 전 경로 차단(WebFetch·웹아카이브·프록시 11종·검색 무색인)되어
  독립 검증 실패. 리서처가 보고한 조항 인용(7.3③ 허용범위 초과 저장·캐시 금지 / 7.3⑥ 제3자 재제공 금지 /
  8.1 결과데이터 권리 회사·원저작자 귀속 / 검색특약 2.1 독립노출·변조 금지)은 **미검증 참고 정보**로만
  취급한다. 사람이 로그인 브라우저로 원문 확인(IMPLEMENTATION.md §0 D1-5 절차) 전 SaaS/재판매 착수 금지.

### 🚧 경계 3 — "모니터링 SaaS"로의 무단 확장
재설계 문서(blueprint-review)가 지적: 약관이 **경쟁 데이터 상시 모니터링 서비스** 구축을 제한할 소지.
대시보드/알림 SaaS는 D1-5 통과 전까지 보류(ARCHITECTURE §7 참조).

### 🚧 경계 4 — 호출 한도 우회 금지
다중 계정·프록시로 일일 한도를 우회하면 약관 위반이자 계정 정지 사유.
`budget/` 영속 카운터로 **단일 앱 한도 내**에서만 동작한다(IMPLEMENTATION Phase 2).

### 🚧 경계 5 — 스코어를 "자동 실행"에 연결 금지
opportunity 스코어가 높다고 자동으로 제조/발주/광고를 트리거하지 않는다.
낙수가 반증됐듯 **지표와 수익은 별개**다. 스코어는 사람 판단의 입력일 뿐이다.

## 3. 런타임까지 전파되는 컴플라이언스

계약(`KeywordSignal.compliance`)이 약관 제약을 데이터에 실어 하위 모듈로 전달한다:

```ts
compliance: {
  resaleRestricted: boolean;   // D1-5 확정. 확정 전 기본 true
  cacheTtlHours: number;       // 약관 허용 캐시 기간. 확정 전 보수적으로 24h
}
```

소비 모듈은 이 필드를 무시할 수 없다 — 예컨대 `resaleRestricted=true`인 신호를 외부 판매 화면에
원본 그대로 노출하면 계약 위반임을 코드 리뷰에서 잡을 수 있게 한다.

---

## 4. D1-5 실측 전까지의 기본 자세

| 항목 | 확정 전 기본값 | 근거 |
|---|---|---|
| 원본 재판매 | 금지(`resaleRestricted=true`) | 보수적 기본값 |
| 캐시 TTL | 24시간 | 보수적 기본값 |
| 제3자 제공 | 금지 | 보수적 기본값 |
| 모니터링 SaaS | 보류 | 재설계 문서 지적 |

> **원칙:** 확실하지 않으면 더 좁게 잡는다. 약관을 실측(D1-5)해 근거가 생긴 뒤에만 경계를 넓힌다.
> 이것이 원안 설계서의 "저작권은 나중에 재확인" 방식과 정반대다 —
> 여기서는 **경계를 먼저 좁게 코드에 박아두고**, 근거가 확인된 만큼만 연다.
