# Hanmadi 학습 관리 — 구현 계약

2026-09-30. 사용자 승인 범위: 데이터셋 버전, 검색 품질 평가, 의미 검색, 파인튜닝 작업 관리. 실제 유료 학습 및 운영 모델 승격은 관리자의 명시적 실행으로만 진행한다.

## 구조

게시 교재 → 불변 데이터셋 → 검색 평가/임베딩 인덱스 → 앱 참고자료 검색.
별도 가중치 학습 권한을 확인한 관리자 교재 → 출처별 train/validation/test → LiteLLM Managed Files → Fine-tuning job → 결과 확인 → 검수 후 허용된 모델 별칭 적용.

번역 후보는 기존 동의 범위에 따라 검색용 데이터셋에만 들어간다. 가중치 학습에는 포함하지 않는다. 데이터셋은 현재 자료 revision을 기록한다. 원본 수정·게시 내림·철회 시 관련 버전과 인덱스를 무효화한다. 철회된 데이터셋의 표현은 제거한다. 운영 모델이 해당 버전을 사용 중이면 기본 모델로 돌아간다.

## 관리자 화면 계획

기존 파랑 #3157D5, 잉크 #182B49, 배경 #F5F7FC, 종이 #FFFFFF, 게시 초록 #166A55를 유지한다. 시스템 한글 글꼴, 왼쪽 정렬, 기존 화면의 제목 크기를 재사용한다.

`학습 관리`: 상단에는 실제 게시 교재와 언어별 빈 구간, 이어서 `자료 버전 만들기 → 검색 평가 → 의미 검색 적용 → 모델 추가 학습` 순서로 편집한다. 자료 버전과 작업 이력은 표 대신 모바일에서도 읽을 수 있는 행 목록을 사용한다. 빈 자료와 미설정 공급자는 해야 할 일을 표시하고 성공처럼 보이는 샘플 수치를 넣지 않는다.

## 운영 경계

소유자 인증·same-origin 검사·CAS를 재사용한다. 실행한 비용 작업은 자동 재시도하지 않는다. 중복 시작은 CAS로 차단한다. 제출 중 응답이 끊기면 결과 미확인으로 남기고 관리자 확인 전 재제출을 막는다. 제공자 실패 본문에는 비밀/원문이 있을 수 있으므로 저장·출력하지 않는다.

기존 공개 gateway의 추론 경로는 변경하지 않는다. 학습 전용 LiteLLM 주소/키/모델과 실제 학습 지원/라이선스 조건은 운영자가 별도 설정한다. 학습 기능 미설정이어도 자료 버전과 어휘 검색 평가는 동작한다.

공식 문서 확인: [Managed Fine-tuning](https://docs.litellm.ai/docs/proxy/managed_finetuning), [Fine-tuning](https://docs.litellm.ai/docs/fine_tuning), [Embeddings](https://docs.litellm.ai/docs/embedding/supported_embedding). 일반 fine-tuning 문서와 Managed 문서의 라이선스 설명이 다르므로 설치 버전/지원 경로를 확인해야 한다. 이 구현은 Managed Files의 `target_model_names`와 모델 별칭 경로를 사용한다.

## 서버 설정

환경변수는 Hanmadi 서버의 비밀 관리 설정에만 둔다. `NEXT_PUBLIC_` 이름을 사용하지 않는다. 운영 주소는 HTTPS만 허용한다. 개발용 localhost HTTP는 테스트에서만 사용한다.

| 변수 | 용도 |
|---|---|
| `HANMADI_EMBEDDING_BASE_URL` | `/embeddings`를 제공하는 LiteLLM 기본 주소. 예: `https://embedding.example/v1` |
| `HANMADI_EMBEDDING_API_KEY` | 해당 임베딩 모델만 허용한 서버 키 |
| `HANMADI_EMBEDDING_MODEL` | 설치된 gateway의 임베딩 모델 별칭 |
| `HANMADI_EMBEDDING_MIN_SCORE` | 새 인덱스에 고정할 코사인 최소 점수. 기본 0.45, 0~1. 실제 질문셋으로 조정하며 보편적인 품질 기준은 아님 |
| `HANMADI_TRAINING_BASE_URL` | Managed `/files`, `/fine_tuning/jobs` 및 조회·취소를 지원하는 별도 주소 |
| `HANMADI_TRAINING_API_KEY` | 학습 경로와 대상 모델에 권한이 있는 서버 키 |
| `HANMADI_TRAINING_MODEL` | 실제 파인튜닝을 지원하는 제공자의 LiteLLM 모델 별칭. 기존 추론 별칭과 별개 |
| `HANMADI_TRAINING_MIN_EXAMPLES` | 제공자·모델의 공식 요구사항에서 확인한 최소 **train 분할** 예제 수. 없으면 준비·실행 차단 |
| `HANMADI_TRAINING_ENABLED` | `true`일 때만 관리자가 유료 학습 시작 가능. 기본 비활성 |
| `HANMADI_TRAINED_MODELS` | 검수 대상 결과 모델 ID → 앱 추론용 별칭의 JSON 객체. 예: `{"provider-result-id":"hanmadi-reviewed-v1"}` |

제공자 자격·모델 지원·Managed 경로 및 설치 버전의 라이선스·학습 비용/예산은 실제 운영 연결 전에 확인한다. 공용 추론 gateway에 학습·관리 경로를 무조건 공개하지 않는다. 마스터 키는 브라우저에 전달하지 않는다. 요청당 20초 타임아웃, 관리 화면의 비용 관련 작업은 하루 40회로 제한하며 **금액 상한은 제공자 예산 설정으로 별도 관리**한다.

## 관리자 사용 순서

1. 기존 `자료 만들기`에서 사용권이 있는 원문으로 교재를 작성하고 언어·뜻·한글 발음·난이도를 검수해 게시한다. YouTube 검색 결과는 자료 준비 목록이며 영상·자막을 자동 다운로드하지 않는다.
2. `학습 관리`에서 게시 교재를 선택해 이름 있는 버전을 만든다. 검색용 버전은 번역 공유 동의를 받은 교재도 포함할 수 있다. 모델 학습용은 외부 가중치 학습·데이터 전송 권한을 별도로 확인한 관리자 교재만 허용한다. 확인 시각도 버전에 기록한다.
3. 기대 교재가 있는 질문과 `참고 자료가 없어야 함` 질문을 작성한다. 어휘 검색 평가를 기준으로 삼고, 인덱스 생성 → 의미 검색 평가 → 모두 통과한 버전을 앱에 적용한다. 평가 질문·인덱스가 바뀌면 재평가가 필요하다. 원본 변경 시 즉시 어휘 검색으로 돌아간다.
4. 모델 학습용 버전을 고르고 학습·검증·시험 JSONL을 확인한다. `학습 작업 준비`는 로컬 기록만 만든다. `학습 시작`의 비용·전송 확인 이후에만 Managed Files로 train/validation을 전송하고 학습 작업을 제출한다. 시험셋은 제공자에 보내지 않는다.
5. `상태 조회`로 완료 여부를 확인한다. 시험셋을 이용해 기본 모델과 비교하고 결과를 검수 기록에 남긴다. 학습 성공 상태만으로 품질 향상을 주장하지 않는다.
6. 운영자가 결과 모델을 앱 gateway의 별칭으로 등록하고 앱 키에서 사용할 수 있도록 한 뒤 `HANMADI_TRAINED_MODELS`에 등록한다. `검수 모델 앱에 적용`은 앱 키의 `/models` 가시성까지 확인한다. 실제 추론 형식·품질은 시험셋 검수에서 확인해야 한다.
7. 적용 범위는 해당 버전의 **언어·레벨·상황과 일치하는 기본 AI 대화**다. 개인이 선택한 모델, 관리자 초안 생성, 번역 출력 형식은 기존 모델을 유지한다. `기본 AI 모델로 복원`으로 즉시 해제할 수 있다.

학습 JSONL은 뜻 → 목표 언어 표현·한국어 뜻·한글 발음의 3개 메시지 예제다. 다중 턴 대화 기록 학습이나 자동 품질 채점 기능은 아니다. 앱의 레벨별·상황별 수업은 기존 게시 교재 경로를 계속 사용하고, AI 대화·번역의 참고 자료 검색은 선택한 인덱스를 사용한다. 의미 검색 적용 시 검색 대상은 **선택한 버전에 들어간 자료**이므로 필요한 언어·상황을 포함시킨다.

## 데이터와 상태 전이

- 기존 knowledge 저장소의 선택 필드 `learning`을 추가한다. 기존 자료는 마이그레이션 없이 읽는다. 개발은 기존 파일 저장소, 운영은 기존 Redis CAS 경로를 사용하며 별도 벡터 DB를 요구하지 않는다.
- 데이터셋은 게시 교재의 ID·revision·표현 스냅샷·SHA-256 digest·분할을 저장한다. 한 버전 최대 120개 표현, 12개 버전, 40개 평가 질문, 최근 30개 평가 기록, 30개 학습 작업으로 제한한다. 임베딩 차원은 최대 3072다.
- 같은 YouTube URL, 같은 정규화 원문 해시, 같은 언어의 동일 표현이 연결된 교재는 한 출처 그룹으로 묶는다. 그룹을 결정적으로 정렬해 약 10%씩 시험/검증에 배정하되 각각 최소 한 그룹을 보장한다. 최소 3개 출처 그룹이 필요하다. 원문 해시는 새 AI 초안 생성 시 서버에서 기록하고 편집으로 바꿀 수 없다. 기존 교재나 수동 교재에서 누락된 출처의 동일성까지 추정하지는 않는다.
- 작업 상태: `prepared → submitting → submitted → succeeded/failed/cancelled`. 제출 결과를 확정할 수 없으면 `unknown`. CAS가 같은 작업의 중복 제출을 막는다. 의도적으로 새 버전을 만들고 새 작업을 시작하는 것은 별도 관리자 실행이다.
- 제공자 결과 모델이 바뀌거나 성공 상태가 해제되면 기존 검수와 적용을 해제한다. 새 결과에는 재검수가 필요하다.
- 원본 수정·게시 취소는 관련 버전과 인덱스를 무효화하고 적용 모델을 해제한다. 번역 공유 철회는 연결 스냅샷의 표현과 평가 정답도 지운다. 이미 진행 중인 요청이나 외부에 보낸 자료를 소급 삭제하는 기능은 아니다. 번역 공유 후보는 애초에 가중치 학습에서 제외한다.
- 종료되고 앱에 적용 중이 아닌 작업은 `작업 기록 삭제`로 로컬 관리 기록을 지울 수 있다. 연결 작업이 없어야 자료 버전도 삭제할 수 있다. **제공자 파일·모델은 삭제하지 않는다.** 별도 제공자 보관 정책과 콘솔 정리가 필요하다.

## 실패·복구

- 학습 제출 응답이 끊겨도 자동 재제출하지 않는다. `상태 조회`는 원격 최근 최대 100개 작업 중 저장된 `training_file`과 정확히 일치하는 단일 작업을 찾고, 작업 ID와 파일 ID를 함께 검증해 연결한다.
- 업로드 응답이 끊겨 파일 ID를 받지 못했거나 최근 목록에서 일치 작업을 확정할 수 없으면 화면에 실패를 표시한다. 제공자 콘솔에서 파일·작업을 확인하고 필요하면 취소·삭제한다. 확인되지 않은 작업을 임의로 성공·실패 처리하지 않는다. 원격 작업을 수동 연결하는 UI는 이번 범위에 없다.
- 원본이 학습 중 바뀌면 앱 적용은 차단되지만 제공자에서 이미 시작된 학습은 계속될 수 있다. `상태 조회` 후 `학습 취소`를 사용하고 제공자 결과를 확인한다. 취소는 이미 발생한 비용의 환불을 뜻하지 않는다.
- 임베딩 연결/응답 오류는 숨기지 않고 요청 오류로 알린다. 관리자는 `어휘 검색으로 복원`할 수 있다. 설정이 바뀌면 새 인덱스를 만들고 재평가한다. 최소 점수는 인덱스에 저장되므로 환경변수 변경만으로 검증된 인덱스의 검색 기준이 달라지지 않는다.
- 제공자 오류 본문·키·원문을 일반 오류 로그/관리 기록에 저장하지 않는다. 상태·일반 오류 메시지와 작업/파일 식별자만 유지한다.

검증 명령: 앱 디렉터리에서 `npm test`, TypeScript 검사, 변경 파일 ESLint, `npm run test:v2`, `npm run build`.

브라우저 검증은 격리한 실제 Next 서버/저장소와 로컬 공급자 fixture를 사용한다. 자료 버전 생성, 검색 평가, 의미 검색의 실제 API 연결, train/validation 업로드와 시험셋 제외, 동시 중복 제출 차단, 응답 유실 복구, 취소, 검수 기록과 앱 적용, 언어·레벨·상황 범위, 원본 변경·회수, 320~1440px 화면을 확인한다. 기존 수업·번역·계정 격리·YouTube 검색도 같은 테스트에서 확인한다.

실제 임베딩/파인튜닝 제공자 호출, 실제 모델 학습 품질, 운영 학습 전용 서버 설정과 배포는 이 검증의 증거가 아니다. 이 변경은 구현 PR로 제공하며 운영 머지·배포와 실제 유료 학습 실행은 구분한다.
