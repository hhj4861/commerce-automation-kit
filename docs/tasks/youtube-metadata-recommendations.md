# 영상 기반 게시 문구 추천

- 목표: 첨부 MP4 또는 제작실 최종 영상의 실제 화면·자막·음성을 분석하고, 최근 3개월 YouTube 공개 자료를 참고한 한국어 제목·설명·해시태그 3안을 제공한다.
- 담당/범위: 현재 Codex 세션 단독. `apps/shopshorts`의 추천 화면, 작업 큐, 공식 API 어댑터, 검증. 자동 게시·운영 배포는 포함하지 않는다.
- 기준: origin/main `f84182f`, 브랜치 `feat/youtube-metadata-recommendations`. worker/Claude OFF.
- 완료 조건: 입력 파일 검증, 실제 영상 분석, 달력 기준 3개월 검색, 조회수/날짜 원본 보존, 형식 불확실성 표시, 모든 태그 # 형식, 재접속 가능한 작업/결과, 복사 및 게시 초안 적용, 기존 업로드 검수 유지. 관련 테스트와 브라우저 검증, 커밋·push·PR.
- 구현 선택: 기존 제작 워커/프로젝트 저장소 재사용. Gemini 영상 입력 + YouTube Data API, 비공식 스크래핑 없음. 공개 API가 쇼츠 여부를 반환하지 않으므로 짧은 영상은 쇼츠 후보로 표시하고 확정 표본으로 세지 않는다. 참조 부족 시 과장 없이 명시한다.
- 화면 계획: 기존 Noto Sans KR/DM Sans, 배경 #f7f7f4·흰색·잉크 #242622·강조 #ff6b4a·확인 #277e64 유지. 왼쪽 영상/분석, 오른쪽 추천 문구의 넓은 읽기 영역. 입력→진행→추천→출처 순서, 모바일 단일 열. 장식 카드 대신 추천안 선택과 복사/초안 적용을 중심에 둔다. 별도 브랜드나 신규 UI 체계를 만들지 않는다.
- 확인한 공식 문서: https://ai.google.dev/gemini-api/docs/video-understanding , https://developers.google.com/youtube/v3/docs/search/list , https://developers.google.com/youtube/v3/docs/videos , https://support.google.com/youtube/answer/15424877 (2026-10-11).

## 사용 흐름과 운영 연결

- `/metadata`: MP4 첨부 또는 제작실 최종 영상 선택 → 분석 요청 → 진행 단계 → 추천 3안 → 복사. 제작실 5단계와 기본/모바일 메뉴에서 진입한다.
- 제작실 영상은 선택한 추천안을 게시 초안에 저장한다. 실제 업로드는 기존 검수 확인과 별도 업로드 동작을 유지한다. 최종 영상 키가 바뀌면 이전 추천의 초안 적용을 차단한다.
- 추천 전용 작업은 일반 제작 목록에서 제외하고 이 화면의 이전 첨부 영상 목록에 표시한다. 서버에 저장된 작업 ID로 새로고침/재접속해 결과를 확인한다.
- 실제 MP4를 ffprobe로 검사한 뒤 Gemini의 영상 입력으로 전송한다. 파일명·대본만으로 영상 확인을 대체하지 않는다. 50MB 이하, 1초~10분; 전체 영상 분석은 모델의 샘플링/인식 정확도 한계가 있으므로 관찰 시점과 불확실성을 보여 준다.
- 제작 워커에 `GEMINI_API_KEY`, `YOUTUBE_API_KEY`, `ffprobe` 필요. `SHOPSHORTS_METADATA_MODEL` 선택값, 기본 `gemini-2.5-flash`. 기존 중앙 비밀관리의 키 바인딩을 재사용하며 키를 프런트엔드에 전달하지 않는다. 신규 Secret·권한 변경은 하지 않았다.
- 요청당 영상 분석 1회 + 문구 생성 1회, YouTube 검색 최대 2회 + 상세 조회 최대 1회. 네트워크/쿼터/인식 실패는 작업 실패로 남기며 조작한 수치나 비공식 수집으로 대체하지 않는다.
- 달력 기준 최근 3개월만 조회한다. 조회수/날짜/제목/공개 설명/공개 해시태그는 실제 API 응답에서 보존한다. 추천 모델이 외부 영상 ID·수치·날짜를 새로 생성해 대체할 수 없다. 공개 API에는 확정 Shorts 필드가 없어 3분 이하 후보는 형식 미확인으로 표시한다. 일반 영상 표본은 3분 초과로 한정됨을 표시한다.
- 새 추천 요청은 새로 조사한다. 저장 결과에는 확인일을 표시하고 30일이 지났으면 다시 조사하라는 안내를 표시한다. 주기적인 자동 모니터링은 추가하지 않았다.
- Pages 코드와 제작 워커 코드가 모두 필요하다. 구 워커는 metadata capability를 보내지 않아 실행 버튼이 비활성화된다. PR 승인/머지/배포 및 실제 연결 점검 전까지 운영에 적용됐다고 보고하지 않는다.

## 검증 기록 (2026-10-11~12)

- 관련 API·heartbeat·상태·권한 회귀와 신규 기능을 묶은 32개 검사 전부 통과. 그중 추가 테스트 12개 통과: 달력 월 경계, 기간/형식 필터, 공개 해시태그와 스튜디오 키워드 구분, 실제 장면 시점 요구, 공식 API 조회, 실패 투명화, 임의 참조/수치 방지, 업로드/작업/CAS/worker 권한, 초안 적용과 게시 검수, 영상 변경, 문구 길이 한도.
- 전체 앱: 변경본 384개 중 376 통과 / 5 실패 / 3 skip. 기준 커밋 f84182f도 372개 중 364 통과 / 같은 5 실패 / 3 skip. 신규 테스트 12개 외 실패 집합이 동일함을 확인했다.
- 기준/변경본 공통 실패: studio-local의 기존 렌더 3개, studio-timeline의 음악 렌더 1개, visual-direction의 자동 요약 렌더 1개. 앞의 4건은 기존 웹툰 구성 검증 실패, 마지막 1건은 Node 22 이상이 필요한 기존 모션 테스트를 Node 20에서 실행한 환경 제한이며 이번 기능 범위에서 수정하지 않았다.
- 초기 검증 중 의존성 누락과 긴 TMPDIR의 tsx 소켓 경로 오류를 확인했다. 의존성을 설치하고 `/private/tmp/ss-meta-20261011` 심볼릭 링크를 통해 iCloud 작업 폴더를 사용해 같은 조건으로 재검증했다. 산출물 실제 저장소는 iCloud다.
- 실제 첨부된 삿포로 영상의 로컬 검사: 40.041667초, 1080×1920, 오디오 있음. 외부 전송 없이 ffprobe로 확인했다.
- 브라우저 통합 검증: 기존 최종 영상 선택 → 실제 작업 API → 실제 워커 실행 분기/ffprobe → 테스트 공급자 응답 → 진행/완료/3안 전환/출처·한계 표시 → 선택한 제목·해시태그가 게시 초안에 저장됨. privacy=private, upload=null 유지 확인. 390px 모바일 가로 넘침 없음. 화면 캡처는 브라우저 도구에서 확인했다.
- 복사 버튼 성공 알림은 확인했으나 도구의 클립보드 읽기에서 내용 일치를 확인하지 못했으므로 클립보드 저장은 미검증으로 남긴다.
- 신규 파일 선택의 브라우저 업로드는 사용자 권한 요청이 거절되어 실행하지 않았다. 이 동작은 다른 경로로 우회하지 않았다. 업로드 API의 입력/권한/상태 검증은 별도의 합성 바이트 단위 테스트로만 확인했다.
- 이 작업 환경에 Gemini/YouTube 키가 없어 실제 외부 분석/조사 호출은 하지 못했다. 테스트 자료 기반 E2E를 실제 인기 영상 조사 완료로 표현하지 않는다.
