# B-ci — 드라마 CI

- 목표·담당: Codex 작업 B, `ci/drama-tests`에서 드라마 두 패키지 CI와 runner 설치 안내만 변경.
- 기준: `30dba8d`, atomworks `ad94eaef54dbb0babe3b5916ca6122a5cc841545`.
- 완료 조건: 워크플로 문법·설치·시험·타입체크 검증, 본인 변경 커밋·push, `feat/drama-regression-pilot` 대상 PR. 머지·secret 생성 금지.
- 설계: macOS의 AppleSDGothicNeo로 미디어 시험 생략 방지, workspace 한정 `npm ci`, 별도 runtime lock 유지. 인증 누락은 명시 실패.
- 검증: Node 22.23.3에서 series 269/269, runner 22/22 통과(실패·skip 0). 두 타입체크, atomworks 3개 SDK 설치·빌드, preflight, README commit/lock 대조, YAML 파싱·전체 shell 문법·secret 누락 exit 1 검증 통과. actionlint 미설치로 전용 lint 미수행.
- 재시도 근거: 최초 runtime 설치는 다른 worktree로 연결된 CLI의 chmod가 EPERM으로 차단됐다. 해당 worktree를 변경하지 않고 작업 폴더의 무시되는 `node_modules/.drama-ci-validation`에 상대 배치를 재현하고, 작업 전용 SDK 사본으로 동일 설치·시험 명령을 성공시켰다. 최초 Ruby 검증 도구도 US-ASCII 인코딩 오류 후 UTF-8을 명시하여 통과했다.
- 현재 결과: 변경 범위는 workflow·runner README·이 작업 기록 3개다. 루트 설치는 관련 workspace만 선택했고 lockfile 변경은 없다. 최종 커밋·PR·명령 증거는 요청된 `20261012-drama-orch/B-ci-report.md`에 기록한다.
- 남은 한계: 실제 호스티드 Actions와 private token checkout은 미확인. 기존 commerce lock 설치에서 npm audit 8건(moderate 3/high 3/critical 2)을 보고했으며 자동 수정하지 않았다.
- 다음 사용자 결정: atomworks만 Contents read 권한을 가진 `ATOMWORKS_READ_TOKEN` 제공 또는 읽기 전용 deploy key 선택 후 PR CI 확인. secret 생성·머지는 하지 않는다.
