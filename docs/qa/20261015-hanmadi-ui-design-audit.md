# Hanmadi — UI Design 진단 및 개선 우선순위

진단일: 2026-10-15. 범위: 학습자 웹의 스터디(회화·단어·음악), AI 대화, 번역, 내 표현, 단어장. 앱 코드를 변경하는 작업이 아니라 디자인·상호작용 진단이다.

## 결론

브랜드색을 바꾸기보다 **작성한 내용 보존 → 첫 화면에서 입력 가능 → 음악의 듣기·연습 동선 연결**을 먼저 개선해야 한다. 메뉴와 PC 화면 틀은 PR #257에서 개선됐지만 아직 운영에 적용되지 않았다. 그 개편안에도 미전송 초안 삭제와 입력창 발견성 문제가 남아 있다.

실제 사용자 이탈률이나 사용성 점수를 측정한 결과는 아니다. 아래 우선순위는 관찰한 동작과 과업 방해 정도를 바탕으로 한 설계 판단이다.

## 진단 기준과 확인 범위

- 적용: 설치된 `ui-design@claude-code-workflows` 1.0.5의 visual-design-foundations, interaction-design, responsive-design, accessibility-compliance, design-system-patterns.
- 운영: <https://hanmadi-lake.vercel.app/study>. 개인 Chrome에서 기존 로그인 상태로 직접 관찰. 기본 1728×828, 모바일 390×844, 작은 화면 320×568 확인. 임시 viewport는 진단 후 원래 크기로 복원했다.
- 운영 코드 비교 기준: `origin/deploy/hanmadi`의 `566480da47b19f76a812fecc6ea3291c5567b719`(PR #258). 실제 화면의 5개 메뉴·음악 목록 흐름과 대조했다. 이 ref 조회만으로 Vercel이 동일 SHA를 실행한다고 단정하지 않는다.
- 미배포 개편안: [PR #257](https://github.com/hhj4861/commerce-automation-kit/pull/257), `37fd9cd5b2c1c43d49ea4fab50a4c922425e1983`, 진단 시 OPEN/미머지. 소스와 해당 리비전의 기존 캡처·E2E 증거를 재사용했다. 이번에 개편안의 전체 E2E를 재실행한 것은 아니다.
- 그 이후 main에는 PR #256의 음악 수집 학습 연결이 반영됐다(`57da80519d5428f82634f83dadb00412204178df`). PR #257의 기존 CI가 이 통합 조합까지 검증한 것으로 취급하지 않는다.
- 외부 AI 호출, 음성 녹음, 진도 완료, 단어 저장·삭제, 설정 변경은 진단 과정에서 수행하지 않았다. 미전송 초안에 공개적인 테스트 문장을 입력하고 메뉴만 이동했다.
- 이번 범위에서 실기기 키보드, VoiceOver/TalkBack, 200% 확대, 오프라인, 네이티브 앱은 검증하지 않았다. WCAG 전체 준수 판정도 아니다.

## 우선순위

| ID | 우선 | 개선점 | 근거/사용자 영향 | 개편안 #257 상태 |
|---|---|---|---|---|
| D01 | P1 | 메뉴 이동 시 미전송 문장 보존 | AI 대화 → 문장 입력 → 스터디 → AI 대화에서 입력값이 빈 문자열로 바뀜 | 삭제 로직이 그대로 남음 |
| D02 | P1 | 대화·번역 입력을 첫 화면으로 | 390px에서 AI 입력창이 본문 아래. 320×568에서는 AI 시작·음성·텍스트 입력이 모두 첫 화면 밖 | 화면 틀만 바뀌고 입력 배치는 유지 |
| D03 | P1 | 음악을 듣기·연습·복습 단계로 나누기 | 4줄 곡에서 본문 3,724px, 한 줄 연습 카드 시작 y≈2,186px. 가사에서 연습을 골라도 아래 카드 변화가 멀리 있음 | 변경 범위 밖. 최신 음악 흐름과 함께 개선 필요 |
| D04 | P2 | 탐색 계층과 PC 공간 활용 | 운영은 5개 하단 메뉴·두 단계 탭·410px 프레임 | 4개 메뉴/보관함/PC 왼쪽 메뉴로 개선됨. 운영 미적용 |
| D05 | P2 | 키보드 탐색과 화면 전환 안내 | 주요 메뉴가 본문 뒤 DOM에 있고, 개편안은 이를 시각적으로 왼쪽에 배치. 전환 시 스크롤 초기화만 수행 | 건너뛰기·포커스 동선 추가 검토 필요 |
| D06 | P2 | 작은 보조 글자·터치 영역 정리 | 운영 하단 메뉴 11px. 일부 회화 필터 폭 37.6px, details 높이 38px | 주요 메뉴는 개선됐으나 세부 조작은 별도 정리 필요 |
| D07 | P2 | 웹·Flutter 공통 디자인 기준 정리 | CSS의 개별 색·크기 값과 후행 덮어쓰기 중심. 두 UI에서 상태별 모양이 달라질 위험 | 전용 CSS는 분리됐지만 공통 토큰 공급원은 없음 |
| D08 | P3 | 진도와 고급 설정의 문구·강조 정리 | ‘0/8 학습 완료’의 범위가 짧게만 표시됨. 기본 Gemini 선택이 초기 대화 화면의 큰 조작으로 노출 | 별도 개선 필요 |

P1: 핵심 과업이나 작성 내용에 직접 영향. P2: 탐색·접근성·확장성 개선. P3: 이해·표현 다듬기. 이 순위는 보안 취약점 등급을 뜻하지 않는다.

## D01 — 작성한 말이 메뉴 이동으로 사라진다

### 확인한 동작

1. 운영에서 AI 대화를 연다.
2. ‘말이 막히면 한국어로 도움 요청’에 `카페에서 커피 주문을 연습하고 싶어요`를 입력한다. 보내기는 누르지 않는다.
3. 스터디를 누른 뒤 AI 대화로 돌아온다.
4. 입력값이 `''`가 된다. 안내·취소 선택은 보이지 않는다.

운영 코드 `v2-app.tsx:1968`과 개편안 `v2-app.tsx:1934` 모두 대화 이외 메뉴로 이동할 때 `setChatInput("")`를 실행한다.

### 개선안과 완료 기준

- 메뉴 이동 중 미전송 초안은 메모리에서 유지한다. 로그아웃·언어 변경·명시적 ‘새 대화’에서의 삭제 기준은 따로 정한다.
- 삭제가 필요한 경우 무엇이 사라지는지 먼저 안내하고 사용자가 취소할 수 있게 한다.
- 전송 실패와 응답 대기 중 작성한 다음 문장의 기존 보존 동작도 유지한다.
- **완료 기준:** 입력 → 다른 메뉴 → 복귀 후 문장이 그대로 있고, 계정/언어 간 초안이 섞이지 않는다.
- 대화 원문을 화면 이탈 시 지우는 현재 안내와 초안 보관 기준을 명확히 구분한다. 해결책으로 전체 대화를 기기 영구 저장소에 무조건 저장하지 않는다.

## D02 — 핵심 입력보다 소개·설정이 먼저 보인다

운영의 첫 진입 위치에서 DOM 사각형을 측정했다. y는 viewport 위에서부터의 CSS 픽셀이다. 본문 밖 요소는 스크롤하면 접근 가능하므로 ‘기능이 없다’는 의미가 아니다.

| 화면 | 크기 | 본문 하단 | 조작 위치 |
|---|---|---:|---|
| AI 대화 | 390×844 | 775 | AI 먼저 말하기 y≈609, 마이크 y≈721/높이 76, 텍스트 입력 y≈919, 보내기 y≈977 |
| AI 대화 | 320×568 | 499 | AI 먼저 말하기 y≈604, 마이크 y≈716, 텍스트 입력 y≈914 |
| 번역 | 390×844 | 775 | 마이크 y≈552, 접힌 직접 입력 항목 y≈733/높이 38 |
| 번역 | 320×568 | 499 | 마이크 y≈552, 직접 입력 항목 y≈733 |

### 개선안과 완료 기준

- AI 대화: 제목·안내를 압축하고 하단에 입력창·보내기·마이크를 함께 둔다. ‘AI가 먼저 말하기’는 대화 시작 제안으로 배치하고 모델 설정은 고급 설정으로 옮긴다.
- 번역: ‘말하기 / 직접 입력’을 같은 수준의 선택으로 노출한다. 결과가 없을 때 두 안내 카드를 간결하게 줄여 입력을 먼저 보여준다.
- 입력 컨트롤을 고정할 경우 하단 메뉴·안전 영역·화면 키보드·오류 안내를 고려해 본문에 해당 높이만큼 공간을 둔다. 고정 자체가 목적은 아니다.
- **완료 기준:** 320×568과 390×844 첫 화면에서 텍스트/음성 중 입력 방법을 발견하고 시작할 수 있다. 키보드를 열어도 현재 입력과 보내기가 가려지지 않는다. 키보드 조건은 후속 실기기 검증 대상이다.

## D03 — 음악에서 가사와 연습 카드가 멀다

390×844의 운영 영어 연습곡 `A Little Step`에서 본문 높이는 711px, 전체 스크롤 높이는 3,724px이었다. ‘연습곡 한 줄 연습’ 영역은 y≈2,186px에서 시작했다. 4개 순서 설명은 이동 가능한 탭이 아니라 정적인 목록이다.

운영 `v2-original-music.tsx:91`의 `move()`는 선택한 줄을 저장하고 피드백을 바꾼다. `:123`의 ‘N번 줄 단어·회화 연습’으로 이 함수를 호출하지만 학습 영역으로 이동하거나 포커스를 옮기는 처리는 이 경로에 없다. 이번 진단에서 이 버튼을 눌러 운영 진도를 변경하지는 않았다.

- 듣기·따라 부르기·단어/회화·뜻 복습을 구분하고 현재 단계·선택한 줄을 가까이 표시한다.
- 곡을 들으면서 연습하는 경우 작은 플레이어와 현재 줄을 유지하고, 긴 전체 가사는 선택적으로 펼친다.
- ‘이 줄 연습’을 누르면 가까운 영역 또는 명확한 화면에서 해당 줄의 과제를 보여준다. 노래 구간 재생과 발음 듣기 구분은 유지한다.
- **완료 기준:** 가사에서 줄 선택 → 해당 줄 연습 → 단어/회화 저장 → 다음 줄이 왕복 스크롤 없이 이어진다. 기존 음악 진도·곡별 저장·재생 중복 방지 검증을 유지한다.

## D04–D08 — 탐색·접근성·공통 디자인

### 메뉴와 화면 폭

운영 PC는 1728×828에서도 앱 프레임이 410×748px이다. 메뉴는 5개이며 11px 글자를 사용한다. #257의 4개 주요 메뉴·보관함 통합·PC 왼쪽 탐색은 이 문제에 맞는 방향이다. 이를 새로 다시 설계하기보다 남은 P1을 함께 검토해야 한다. 실제 머지·배포는 이번 진단 범위에 포함하지 않는다.

### 키보드와 포커스

개편안의 주요 메뉴는 `</main>` 뒤에 렌더링되고 CSS Grid로 왼쪽에 배치된다. 본문으로 바로 가기 링크가 없고, 일반 메뉴 전환 효과는 `scrollTo()` 중심이다. 실제 Tab/스크린리더 순서가 과업에 적합한지 확인하고, 주요 메뉴/본문으로 건너뛰기와 새 화면 제목 안내를 제공한다. **시각적 순서와 DOM 순서가 다르다는 이유만으로 WCAG 위반이라고 단정하지 않는다.**

### 읽기와 조작 크기

- 주요 조작 44×44px 이상을 한마디의 편안한 터치 목표로 삼고, 보조 글자와 경계·포커스를 함께 점검한다.
- WCAG 2.2 AA 2.5.8의 기본 기준은 24×24 CSS px이며 간격·인라인 등 예외가 있다. 44px 미만이라는 이유로 AA 위반으로 보고하지 않았다.
- 소스의 대표 불투명 색 조합을 계산하면 파랑 `#3157d5`/흰색은 약 6.08:1, 보조 글자 `#5a6980`/`#fbfcfe`는 약 5.43:1, 본문 `#182b49`/흰색은 약 14.18:1이다. 이 샘플은 대비가 양호하다. 모든 상태·투명도·실제 합성 배경을 검사한 결과는 아니다.

### Flutter를 함께 관리할 디자인 기준

운영 `study.css`는 2,346줄이며 정규식으로 추출한 서로 다른 hex 리터럴 85종, `font-size` 선언 값 29종이 있다. alpha·기능별 배경도 포함한 원시 코드 통계이며 ‘브랜드색 85개’나 그 자체의 결함 수가 아니다. `word-study.css`에도 별도 값이 존재한다.

- 색의 원시값 → 본문/보조/표면/경계/성공/오류 같은 의미 → 버튼/입력/탭의 사용 규칙을 정한다.
- 타이포·간격·모서리·아이콘·터치 영역과 loading/empty/error/focus/disabled 상태를 공통으로 문서화한다.
- 같은 기준에서 CSS와 Flutter Theme를 만들되 React와 Flutter의 컴포넌트 구현은 각 플랫폼에 맞춘다. 실제 앱이나 토큰 생성기를 이번에 구현한 것은 아니다.
- 진도 문구는 ‘레벨 1 · 8개 상황 중 0개 완료’처럼 범위를 드러내고, 오늘 할 일과 누적 진도를 분리한다. 기능 선택이 없는 모델명 표시는 고급 설정으로 낮추는 것을 권한다.

## 유지할 좋은 부분

- 단어 스터디의 ‘5개 익히기 → 뜻 퀴즈 → 헷갈린 단어 복습’ 흐름과 뜻을 먼저 숨기는 방식.
- 빈 단어장의 이유 설명 및 ‘스터디에서 단어 찾기’ 행동 연결. 빈 내 표현 화면에도 번역으로 이어지는 행동이 있어 다음 할 일이 명확하다.
- 사용자가 직접 선택하는 저장, 실패 시 재시도, 음악 원음과 학습 발음 음성의 구분.
- #257의 주요 메뉴 버튼 크기·선택 상태·반응형 레이아웃·reduced-motion 보완. 해당 커밋의 이전 탐색 E2E는 6개 크기/84개 상태 확인을 통과했다. 이것이 전체 접근성 인증을 뜻하지 않는다.

## 권장 실행 순서

1. **입력 보존·입력 동선:** D01과 D02를 한 묶음으로 보완한다. 미전송 초안·전송 실패·메뉴 왕복·키보드 가림 조건을 검증한다.
2. **음악 학습 과업:** 최신 음악 수집 흐름 위에서 D03을 개선한다. 듣기와 줄별 연습 전환을 먼저 해결한다.
3. **공통 기준 확정:** #257 탐색안, 키보드 동선, 글자·터치 기준을 정리한 뒤 Flutter 화면에도 같은 기준을 적용한다.
