# Hanmadi 일시 LLM 장애 대응 검증 — 2026-10-02

## 원인과 적용 상태

운영 관리자 PR #120 배포 후 2026-10-01 23:15–23:17 UTC의 gateway 로그를 읽기 전용으로 조사했다. `/v1/chat/completions`의 HTTP 503 세 건과 Gemini `UNAVAILABLE` 응답이 확인됐다. 제공자 메시지는 “This model is currently experiencing high demand.”였다. 같은 구간에서 인증 오류·429·할당량 제한은 확인되지 않았다. 당시 모델 별칭은 `hanmadi-chat`, 설정 모델은 `gemini/gemini-flash-lite-latest`다. 모델 변경이나 서버 설정 변경은 수행하지 않았다.

로컬 Google Cloud 인증 갱신 후 기존 IAP로 연결했다. 직접 SSH는 시간 초과됐고 IAP 조회는 성공했다. 키·사용자 대화·원본 오류 전체를 문서나 로그에 저장하지 않았다.

이 변경은 작업 브랜치의 후속 수정이며 **운영 미반영**이다. 운영 진단 기능과 일일 예약은 이전 PR #120으로 배포된 상태다. 후속 PR 및 배포 PR의 사용자 승인이 필요하다.

## 수정

- 회화, 내 말 변환, 번역은 명확한 HTTP 503에 한해 1초 뒤 같은 모델·동일 요청으로 한 번 재시도한다.
- 재시도와 내용 보정이 기존 최대 두 호출을 공유한다. 재시도 후 잘못된 답변이 와도 세 번째 요청을 하지 않으며 잘못된 답변을 반환하지 않는다.
- 인증, 할당량 제한, 시간 초과, 불명확한 네트워크 실패는 자동 재시도하지 않는다. 모델 자동 전환도 없다.
- 실제 LiteLLM 오류 코드를 안전한 유형과 한국어 안내로 바꾼다. 비밀이나 제공자 원문은 노출하지 않는다.
- 진단은 503, 인증, 사용량 제한, 시간 초과와 일반 실패를 구분한다. 일시 장애 복구는 품질 보정과 다른 경고로 남기며 실제 호출·실패 횟수를 유지한다.
- 일시 장애 뒤 받은 잘못된 내용은 최종 품질 실패로 표시한다. 첫 요청 실패 횟수도 보존한다.

Google 공식 근거: https://ai.google.dev/gemini-api/docs/troubleshooting — 일시적인 503에 지연 후 재시도를 권고한다. 이 구현은 무제한 재시도가 아닌 한 번의 대기·재시도로 한정한다.

## 검증

- 전체 단위 검사 193개 통과 후 최종 분류 회귀를 추가했다. 변경 영향 범위의 진단 검사 10개도 통과했다.
- 앱에 설치된 TypeScript 실행기로 타입 검사 통과; 수정 파일 ESLint 통과; production build 통과.
- 관리자 브라우저 E2E: 로그인/권한/CSRF, 4개 언어, 지속 503 최대 호출 제한, 503 후 복구 표시, 품질 보정 구분, 결과 저장/새로고침, 일일 중복 방지와 수동 횟수 상한 통과.
- 320/390/1440px에서 수평 넘침 없음. 390px 캡처의 상세 경고·버튼 표시 직접 확인.
- 실제 서버의 기존 한마디 가상 키를 서버 메모리에만 유지하는 IAP 중계로 앱 생성기·검증기를 실호출했다. 고정 카페 레벨1 예문만 사용했으며 검색 자료는 주입하지 않았다. 12개 검사 단계, 총 16회 모델 호출, 호출 실패 0회. 영어·일본어·태국어는 일부 내용 보정 뒤 경고, 스페인어는 최초 응답으로 모두 통과했다.
- 실제 테스트의 영어 첫 회화 9.98초에는 SSH 중계 시작 비용이 포함됐다. 나머지 단계는 약 0.83~2.62초였다. 이는 Vercel 사용자 체감 속도나 운영 코드 반영 증거가 아니다.
- 실모델 시험에서 503이 재발하지 않아 일시 장애 재시도 자체의 성공/실패 경로는 모의 공급자 E2E로 검증했다. 재시도가 제공자 장애를 항상 해결하거나 모든 상황의 답변 정확도를 보장하지 않는다.

산출물: 사용자 지정 iCloud 작업 루트의 `commerce-automation-kit/hanmadi-transient-errors-20261002/` (`unit.log`, `build.log`, `live-provider.json`, `e2e/result.json`, 화면 캡처). 실제 타이머 예약의 첫 실행 여부는 이 조사에서 별도로 검증하지 않았다. TTS와 개인 구독 인증은 이번 범위 밖이다.

## PR #122 CI 보완

- 전체 사용자 E2E의 예전 `503 → 502` 기대값을 새 계약 `503 → 503`으로 갱신하고, 한국어 일시 장애 안내·정확히 두 호출·실패 표현 미저장을 함께 확인한다.
- 언어 흐름 CI는 연속 라이트/다크 전환 뒤 글자색과 hover 배경의 서로 다른 테마 값을 측정해 대비 검사에 실패했다. 동일 코드를 로컬 Chrome에서 수정 없이 실행하면 전체 검사가 통과했다. CSS를 바꾸거나 대비 기준을 낮추지 않고, 미디어 전환 후 최대 5초 내 실제 대비 4.5 이상 적용을 기다린다. 지속적인 대비 불량은 그대로 실패한다.

- 보완 후 전체 v2 사용자 E2E와 언어/레벨/음성 흐름 E2E가 모두 종료 코드 0으로 통과했다. 로그·캡처는 같은 산출물 루트의 `ci-followup/`에 저장했다.
