# Hanmadi 문맥 검수의 중복 참조 검증 — 2026-10-03

## 문제와 변경

신규 24개 합성 사례의 실제 평가에서 중복 후보 네 개가 같은 배치의 후보와 비슷하다는 이유로 기존 자료 `referenceIndex=0`을 잘못 지목했다. 숫자는 유효했지만 연결된 기존 문장은 다른 의도였다. 해당 실평가 원본과 기대 라벨은 변경하지 않았다.

v10은 기존 자료에 `kind=corpus`와 원문·뜻·상황의 SHA-256 기반 ID를 부여한다. 후보 index와 기존 자료 ID는 분리한다. LLM이 중복이라고 주장하면 ID뿐 아니라 인용한 원문·뜻·상황까지 공급된 자료와 정확히 일치해야 한다. 숫자만 있는 중복 주장은 해당 행만 `invalid_reference`로 보류한다. 이전 응답 형식의 참조 없는 pass/uncertain은 호환하며, 저장 필드 `referenceIndex`는 검증된 ID에서 파생한다.

참조 형식이 맞아도 의미가 같다는 증거는 아니다. 중복 주장에만 JEV가 후보와 해당 기존 문장을 직접 비교한다. LLM의 판정·설명은 이 비교 입력에 넣지 않는다. 기존 신뢰도 기준(confidence ≥ 0.85 및 선택 확률 ≥ 0.9)을 그대로 사용한다.

- `duplicate`: 비교 결과·모델·확률을 기록하고 `matchedReference`를 표시한다. 후보는 기존 정책대로 사람 검토 대기다.
- `distinct`/`uncertain`/호출 오류: 기존 LLM 주장은 감사용으로 보존하되 확정된 중복 대상처럼 표시하지 않는다. 자동 통과시키지 않고 검토 대기로 남긴다.
- 잘못된 ID·후보 ID·인용 내용 변조: JEV 참조 비교를 보내지 않는다. 정상 형제 후보의 검수 결과는 유지한다.
- 정상 후보끼리의 마지막 JEV 중복 비교와 기존의 확실한 실패·완전 중복 거부는 유지한다.

## 비용·실행 경계

중복 주장 수가 1~6개일 때 한 배치 요청으로 추가 비교한다. 추가 요청은 최대 1회이며 기존 SDK의 12초 제한과 재시도 없음 정책을 따른다. 주장 없으면 추가 호출은 0회다. 요청 수·사용 토큰에 추가 비교를 포함하고, 실패해 사용량을 모르면 0으로 꾸미지 않고 null로 기록한다.

평가 도구는 새 단계를 `reference`로 구분한다. 품질 평가의 기존 12회 승인 상한은 늘리지 않았다. 한 배치는 최대 4회가 필요하므로 네 배치가 상한에 도달해 조기 중단될 수 있다. 기존 채택/보류 기준과 별도로 `referenceEvidenceComplete` 및 미확인 참조 수를 보고한다. 참조 검증 장애가 나면 현재 배치의 정상 후보 처리를 마친 뒤 다음 평가 배치를 진행하지 않는다.

이번 검증은 모두 기록 재생·가짜 전송 응답이다. 실제 JEV/LLM 호출, 키 발급, 추가 비용, 운영 배포는 수행하지 않았다. ID·문장 결합은 결정적으로 검증하지만 JEV 의미 판정 자체의 정확성을 보장하지 않는다. 두 모델이 같은 오판을 할 가능성은 남으며 실제 품질 검증에는 별도 고정 사례·사람 검수가 필요하다.
