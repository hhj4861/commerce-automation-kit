## 실제 브라우저 → 운영 API → Dify 회화 검증

Chromium 모바일 390×844, Asia/Seoul 시간대에서 정상 PIN 로그인으로 검증했다.
로그인 직후 언어 선택 진입을 확인했다. 그 뒤 일반 학생 API로 생성한
독립 검증용 학생의 학습 범위만 사용했다. 기존 튜터·학생 학습 결과는
수정하지 않았고, 운영 응답이나 인증 쿠키를 위조하지 않았다.

| 항목 | 결과 |
|---|---|
| 태국어 6문항 → 입문 → 실제 회화 2턴 | 통과, 두 회화 응답 HTTP 200, 태국어 원문 포함 |
| 일본어 6문항 → 중급 연습 → 실제 회화 2턴 | 통과, 두 응답 HTTP 200, 일본어 원문 포함 |
| 한국어 6문항 → 기초 → 실제 회화 2턴 | 통과, 두 응답 HTTP 200 |
| 언어별 회화 이어가기 | 각 두 번째 응답에서 동일 conversation ID 유지 |
| 난이도 피드백 → 학습 계획 | 세 언어 모두 HTTP 200, confirmed=true |
| 서버 저장·재방문 | 세 언어 모두 새로고침 후 단계·주간 계획 유지 |
| 하루 15분·주 5회 계획 | 날짜별 수업·학습 시간·회화 과제·복습 표시 확인 |
| 일본어 음성 합성 | HTTP 200, 53,542 bytes |
| 한국어 확인 문제 | 첫 저장 saved=true, 같은 날 두 번째 저장 saved=false |
| 모바일 | 가로 넘침 없음, pageerror 없음 |
| 잘못된 Origin / 미인증 진단 | 각각 403 / 401 |
| 정리 | 검증용 학생 삭제 HTTP 200/ok=true, 로그아웃, 브라우저 종료 exit 0 |

스크린샷은 [태국어 학습 계획](assets/20260928-hanmadi-th-plan.png)과
[일본어 레벨별 회화](assets/20260928-hanmadi-ja-conversation.png)에 저장했다.
실제 렌더 이미지를 열어 문구·한글 발음·모바일 배치를 확인했다.

진단 단계는 문제 점수와 사용자 체감 난이도로 정한다. AI 자체의 공인
숙련도 평가나 발음 채점이 아니다. 실제 AI 응답에서 한글 발음 줄에 태국어
문자가 일부 섞이거나 일본어 발음 줄에 한국어 뜻이 섞이는 기존 생성 품질
한계가 관찰됐다. 원문 언어 응답·연결·단계 적용 통과와 언어학적 정확성은
구분한다. 이번 배포에서 모델·프롬프트 품질 개선을 추가로 변경하지 않았다.

실제 마이크 녹음·청음 평가는 포함하지 않았다. 음성은 합성 API의 정상
응답과 비어 있지 않은 바이트를 확인했다. 학생 삭제 API는 학생과 기존
퍼즐 진행을 삭제하지만 별도 언어 학습 이벤트와 Dify 대화까지 지우는
기능은 아니다. 이 검증에서 만든 비개인 synthetic 학습 이벤트·대화는
각 서버의 기존 보관 정책을 따르며, 삭제된 학생 링크로는 접근할 수 없다.

## 완료 훅 정리

과거 입력 프로세스 뒤 거절된 셸 호출은 검증된 새 판정기로 공식 reconcile이
`declined` / `exit_code: null`로 복구했다. 실제 앞선 프로세스 종료 1도 그대로
기록했다. 복구 코드 16개 테스트와 설치 바이트 재현 검증이 통과했다.
코드는 `fix/task-finish-stdin-refusal` 브랜치에 커밋·푸시됐고 로컬에 적용됐다.
그 브랜치는 main에 머지하지 않았다.

이후 드러난 최초 배포 JSON 누락은 비밀 값 부재·본인 소유를 확인해
현재 프로젝트 브랜치의 `cd2bcb7`로 커밋·푸시했다. Terraform 상태나 다른
세션 산출물은 포함하지 않았다. 최종 Stop 결과는 실제 훅 실행과 구분한다.
