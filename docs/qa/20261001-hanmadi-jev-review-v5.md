# Hanmadi JEV 검토 대기·중복 비교 v5

상태: 구현·오프라인·CI 브라우저 검증 완료. [PR #114](https://github.com/hhj4861/commerce-automation-kit/pull/114)에서 검토 중. main·운영 미반영. 유료 모델 호출, 키 변경, 자료 게시, 파인튜닝 없음.

## 문제와 변경

기존 v4 품질 평가에서 유용한 표현 3개가 낮은 신뢰도의 `duplicate`/`unreliable` 판정으로 제외됐다. 잘못된 뜻이나 관찰 실패를 가진 앞선 후보가 정상 후보의 중복 근거로 섞이는 문제도 있었다.

- 1차 JEV는 후보별 품질·상황·기존 자료와의 중복만 평가한다. 질문의 `earlierCandidates`를 제거하고 다른 후보를 참조로 쓰지 않도록 경계를 명시한다.
- 기존 채택 기준(confidence ≥ 0.85, useful 확률 ≥ 0.90)을 유지한다. 부정 판정도 confidence ≥ 0.85와 해당 choice 확률 ≥ 0.90을 모두 충족해야 확정 제외한다. 부족하면 원 분류를 보존하고 검토 대기로 둔다.
- 기존 자료와 정확히 같은 표현은 신뢰도와 무관하게 제외한다. 같은 배치에서도 앞서 최종 통과한 표현과 정확히 같으면 제외한다. 검토 대기·탈락 후보를 정확 중복 근거로 삼지 않는다.
- 1차를 확실히 통과한 후보끼리만 2차 JEV에서 앞→뒤 쌍을 비교한다. 최대 6후보/15쌍을 **추가 요청 1회**로 묶는다. 쌍이 없으면 1차만 호출한다.
- 앱은 원 순서로 최종 통과한 앞 후보와의 비교만 사용한다. 앞 후보가 검토 대기·제외되면 해당 쌍의 응답을 보존하되 `used: false`로 표시하고 뒤 후보 판정에 사용하지 않는다. 확실한 중복은 제외, 중복 여부가 애매하면 검토 대기다.
- API 오류·429·잘못된 응답은 전체 평가 실패로 표시하고 초안을 저장하지 않는다. 1차 통과만으로 우회하지 않는다. 재시도 시 영상 분석 캐시는 재사용하지만 JEV 평가는 다시 실행한다.

## 저장·UI·이전 자료

`VideoJudgment`에 선택적 `disposition`, `reason`, `evaluation`, `comparisons`를 추가했다. 기존 `choice`는 정확/배치 중복 보정 이후의 유효 분류를 유지하며, `evaluation`에는 1차 원분류·confidence·전체 확률 분포를 보관한다. 쌍 비교의 원분류·확률·참조 index·사용 여부도 보존하고, 2차 응답의 모델 이름은 `comparisonModel`로 기록한다.

자료에는 통과/검토 대기 표현만 저장한다. 하나라도 검토 대기이면 초안 전체가 사람 검토 대상이며 게시 전 검색 학습·파인튜닝 데이터·이후 영상의 비교 자료에 넣지 않는다. 검수·게시 단계는 기존 절차를 유지한다.

`unitEvidenceIndices`는 **처음 저장한 표현 순서 → 원본 분석/근거 index**이다. 사람 편집 이후 표현에 대한 최신 검증 결과가 아니다. 기존 `videoReview` 보존 정책을 유지하며, 초안 화면에는 “저장 당시 JEV 판정”임을 명시한다. 자료 준비 목록과 검수 화면에서 분류·처리 상태·이유를 확인할 수 있다.

새 필드는 선택적이다. v4 저장 자료는 기존 통과/검토/제외 상태로 표시하고 소급 변경하지 않는다. rubric `hanmadi-video-jev-v5`로 캐시·멱등 키를 분리한다. v4 결과 캐시를 v5 평가 완료로 취급하지 않으며, 같은 영상을 v5로 다시 준비하면 새 작업으로 처리된다.

## 호출·동시 처리 한도

영상 선택 최대 10개, 동시 분석 3개, 하루 새 분석 50개는 유지한다. JEV는 영상당 최대 2요청, 각 12초이며 자동 재시도는 없다. 평가·저장 lock은 25초에서 45초로 조정했다. 다른 영상의 lock 획득 대기는 기존 15초이며, 획득하지 못하면 `running` 응답으로 대기를 알리고 클라이언트가 이어서 확인한다. 원영상 작업/분석 슬롯 150초와 API 150초 제한은 유지한다.

현재 운영 전용 키의 10RPM 제약에서 10개 영상이 모두 2차 평가를 필요로 하면 최대 20요청이므로 429가 발생할 수 있다. 운영 키 권한·RPM·예산은 바꾸지 않았다. UI는 실패/재시도를 표시하며 원영상 분석은 재사용한다. 2차 평가의 실사용 비용·지연·분류 품질은 이번 작업에서 측정하지 않았다.
