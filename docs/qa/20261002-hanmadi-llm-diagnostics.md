## 저장·동시성·호출 상한

- 기존 `v2Driver`의 운영 Redis에 언어당 최근 10회 보관. UI 읽기/새로고침은 LLM을 호출하지 않는다.
- CAS로 실행 시작을 먼저 기록하고 언어별 동시 실행을 거부한다. 수동은 언어당 UTC 날짜 기준 2회, 자동은 날짜당 1회. 실행 실패도 예산을 소비한다. 자동 중복 호출은 모델 호출 없이 건너뛴다.
- 1회는 3개 검사, 각각 현재 앱 정책의 최대 2회 completion. 언어당 최대 6회, 예약 전체 최대 24회, 수동+자동을 모두 사용하면 하루 최대 72회 completion이다. 검색의 임베딩 호출은 별도이며 의미 검색이 켜져 있으면 비용이 추가될 수 있다.
- 자동 실행은 4개 언어를 병렬로 시작하고, 각 언어의 세 검사는 순차 실행한다. 정상 completion 동시 호출은 최대 4개이다.
- 실행 중 프로세스가 종료되면 기록을 남긴다. 10분이 지난 실행은 중단으로 표시하며, 새 실행이 이전 완료 결과를 덮어쓰지 못하도록 ID·lease를 확인한다. 최근 결과가 36시간을 넘으면 다시 진단할 것을 표시한다(조회 시점 기준).
- 관리자 POST는 소유자 세션+같은 Origin을 요구한다. 일반 학습자·초대 튜터·인증 없는 요청은 실행·조회할 수 없다. 예약 경로는 정확한 Bearer 비밀 비교로 별도 보호한다.

## 예약 설정과 운영 적용 절차

1. PR 승인 후 지정 커밋을 실제 관리자 배포에 반영한다. 관리자 전용과 학습 앱 모두 예약 경로를 인식하지만 **예약 실행은 한 프로젝트에서만 활성화**한다. 같은 Redis를 쓰면 중복 요청은 날짜 키로 차단된다.
2. 해당 Vercel 프로젝트의 비밀 설정에 32자 이상 임의 `CRON_SECRET`, `HANMADI_DIAGNOSTICS_ENABLED=true`를 등록한다. 값은 소스·문서·산출물에 기록하지 않는다. 운영 Redis와 LiteLLM 연결은 기존 서버 설정을 사용한다. 활성화되지 않으면 UI가 자동 진단 미설정으로 표시한다.
3. `vercel.json`은 `17 0 * * *`(UTC, KST 09시대)에 `/api/study/diagnostics/cron`을 호출한다. 실제 실행 시각은 요금제의 정밀도 제한을 받는다. API는 환경변수 설정 여부만 보여주므로 실제 예약 등록/실행은 Vercel 설정과 실행 기록을 따로 확인한다.
4. 배포 후 소유자 로그인 → 언어별 수동 검사 → 저장 결과 재조회, 예약 경로 인증·중복 방지와 첫 실제 자동 실행 기록을 확인한다. 로컬 fixture 테스트 성공을 운영 모델 검증이나 스케줄 실행 성공으로 보고하지 않는다.
