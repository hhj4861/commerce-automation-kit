# Hanmadi 언어별 레벨 체크와 맞춤 학습

## 적용 범위

사용자 요청: 언어 선택 후 레벨을 확인하고, 그 결과에 맞게 AI 회화와 학습 일정을 조절한다. 진단 방식은 사용자가 선택한 **짧은 문제 + 텍스트 회화**다.

작업 브랜치: `feat/hanmadi-adaptive-learning`. 구현·검증 후 PR로 전달하며, PR별 명시적 머지 승인 전에는 main·운영 사이트에 적용하지 않는다.

## 학습 흐름

1. 로그인 → 언어 선택. 해당 언어의 기록이 없으면 `/assessment`로 이동한다.
2. 한국어 설명의 6문항(인사·어휘·요청·과거·이유·상황 이해)에 답한다. ‘모르겠어요’를 선택할 수 있다. 하루 10/15/20분, 주 3/5/7회를 고른다.
3. 정답 수 0~2개는 입문, 3~4개는 기초, 5~6개는 중급 연습을 임시 시작점으로 정한다.
4. AI와 실제 텍스트 응답을 두 번 주고받고 ‘어려워요·적당해요·쉬워요’를 선택한다. 현재 단계에서 한 단계씩 조절하며 범위를 벗어나지 않는다. 최초 회화 확인 전에는 학습 계획으로 건너뛰지 않는다.
5. 확정한 단계·학습 시간·횟수에 맞는 1주 계획과 주제별 연습 과제를 제시한다. 입문은 표현 따라 말하기, 기초는 문장 바꾸기, 중급 연습은 이유 설명·대안 질문 같은 역할극으로 이어진다.
6. 확인 문제의 하루 첫 응답으로 복습을 배치한다. 틀린 문제는 다음 학습 일정에 우선 배치하고, 맞힌 표현은 단계별 1/2/3일 간격을 사용한다. 오늘 확인한 수업은 그대로 유지한다. 놓친 날짜를 숙제로 누적하지 않는다.
7. 언어 변경·새로고침·다른 기기 로그인 후에도 서버 기록을 이어간다. 재진단은 해당 언어의 새 시작점을 만들며 다른 언어 기록은 유지한다.

## 판단과 저장의 경계

- 6문항 점수와 **학습자의 회화 체감**을 결합하는 시작점 진단이다. AI는 대화와 교정을 제공하지만 자유 답안에 공인 점수나 발음 점수를 부여하지 않는다. CEFR/JLPT/TOPIK 등급으로 표시하지 않는다.
- 당일 AI 응답이 두 번 이상 기록돼야 난이도 피드백을 저장할 수 있다. 피드백은 언어별 하루 한 번, 재진단은 학습자별 UTC 하루 10번까지다.
- 기존 PIN 계정 또는 저장된 비공개 학생 링크의 식별자에 언어를 결합한다. 같은 PIN 계정을 공유하면 같은 학습 기록을 사용한다. 개별 학생은 개인 링크를 사용한다.
- 명시적인 학생 링크는 튜터 자신의 학습 기록으로 대체하지 않는다. 로그인한 튜터는 담당 학생에만 접근하며, 비로그인 학생은 기존 비공개 링크 방식으로 접근한다.
- 운영은 기존 Redis를 사용한다. 로컬은 `.data/tutors.json` 드라이버를 사용한다. 운영에서 Redis가 없으면 파일 저장으로 성공한 척하지 않는다.
- 저장 키: `hanmadi:learning:v1:{actorHash}:{language}`. 진단·회화 응답 횟수·난이도 피드백·퀴즈 결과를 필드 단위 이벤트로 저장한다. 새 기록은 `HSETNX`로 중복 요청을 막는다. 회화 텍스트는 새 학습 기록에 저장하지 않는다. 기존 Dify의 대화 저장·동의 정책은 유지한다.
- 서버에서 저장된 레벨을 읽어 AI 요청에 적용한다. 브라우저가 다른 레벨을 보내도 적용하지 않는다. 진단/난이도 버전이 바뀌면 오래된 대화 요청은 409로 거부한다.
- Dify 기존 입력 계약인 `입문/초급/중급`을 사용한다. UI의 기초는 초급에, 중급 연습은 중급에 대응한다. 기존 앱·키·DSL을 바꾸지 않아도 전달되는 상황 지침과 레벨이 반영된다. LiteLLM 직접 연결에도 같은 학습 과제를 전달한다.
- 기존 API 클라이언트의 미진단 회화 요청은 기존 계약을 유지한다. 새 웹 로그인 흐름에서는 먼저 진단하도록 안내한다. 익명 사용자는 정적 수업 미리보기를 볼 수 있지만 개인 계획을 저장하거나 유료 AI를 호출할 수 없다.

## 검증

- 단위 테스트 24개: 3개 언어 채점, 불완전·비정상 답안 거부, 재진단 격리, 단계 상하한, 시간대·월 경계·주간 횟수·시간 배분, 첫 응답 복습, 오늘 일정 유지, 지난 일정 비누적, Dify/LiteLLM 입력·대화 범위.
- 타입 검사, 변경 TypeScript/TSX ESLint, production build 통과.
- Playwright 모바일 390×844: 로그인 → 세 언어 진단 → 회화 두 차례 → 피드백 → 서버 저장된 계획, 새로고침, UI 퀴즈 저장, 클라이언트 레벨 변조 방지, 다른 언어 재진단 격리, 오래된 버전 409, 중복 퀴즈 저장 방지, 계정·학생 격리, 인증/Origin 검증, 진단 횟수 제한.
- `test:dify`: 로컬 Next → 합성 Dify, 3개 언어·레벨, 회화 계속/새 대화, 사용자 격리, 저장 동의, STT → 회화 → TTS 통과. CI에서는 같은 스크립트가 실제 Dify·LiteLLM 컨테이너와 합성 모델을 사용한다.
- `test:conversation`: 기존 LiteLLM 경로의 3개 언어·튜터/학생 인증·입력 제한·실패 응답·동시 사용량 제한·음성 회귀 통과.
- Chrome에서 진단 문항과 학습 계획 화면을 시각 확인했다. 검증용 로컬 브라우저 탭을 닫았다. 로컬 테스트에는 합성 계정/내용만 사용하고 운영 비밀이나 학습자 기록을 복사하지 않았다.

이번 작업에서 운영 AI 모델을 이용한 학습 효과 평가나 교육 전문가의 문항 타당도 검증은 수행하지 않았다. 운영 배포 후에는 기존 계정으로 새 진단을 마치고 실제 Dify 응답의 단계별 차이를 확인해야 한다.
