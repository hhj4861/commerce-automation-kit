# JEV v2.2와 기존 Codex 런타임 검수 비교 — 2026-10-04

**고정 3건의 최종 판정은 JEV와 Codex가 모두 held / held / rejected로 같았다. 이 비교에서 JEV의 추가적인 검출 효과는 확인하지 못했다.** 또한 첫 사례를 전체적으로 “정상”이라고 붙인 잠정 라벨을 재검토해야 한다. 다음은 위치까지 직접 뒷받침하는 근거와 독립 검토 라벨을 갖춘 비교 세트를 만든 뒤, 적용 범위를 결정하는 것이다. 운영 활성화는 계속 보류한다.

## 비교 조건

- 사용자 “계속해줘”에 따라 기존 Shopshorts `createCodexGenerator` 어댑터를 검수 역할로 호출했다. 원래부터 존재하는 별도 LLM 검수 API를 재현한 것이 아니라, 기존 **생성용 런타임을 사용하는 비교군**이다. 제품 소스·운영 호출 경로는 변경하지 않았다.
- 기존 ChatGPT 구독 로그인, `provider-default`. 로컬 설정은 `gpt-6-astra`, reasoning `high`였으며 모델을 별도 지정하지 않았다. 응답 이벤트에 실제 resolved model ID가 없어 설정값과 실제 관측 모델을 구분한다. API 키 환경변수는 기존 어댑터의 허용 목록에 없어 전달되지 않았다. API 과금 경로로 전환하지 않았다.
- 기존 v2.2 3건의 candidate/evidence/11문항 기준을 그대로 제공했다. 정답 라벨과 JEV 결과는 LLM 입력에서 제외했다. 외부 검색·쉘·MCP·앱·하위 에이전트는 기존 draftOnly 제한을 사용했다. CLI는 read-only/ephemeral이며 관측한 완료 item은 agent_message와 진단 error뿐이다.
- LLM은 각 항목의 선택·참조 근거 ID·짧은 이유만 반환한다. 자체 생성 확신 수치를 확률처럼 사용하지 않았다. reject 우선, 없으면 uncertain 보류, 나머지 통과로 집계했다. JEV는 기존 confidence .8/probability .8/margin .2를 적용한다. **의미 기준은 같지만 신뢰도 보정이 같은 비교가 아니다.** LLM은 전체 질문 묶음을 보고 추론하며 JEV의 질문별 처리 방식과도 다르다.
- 계획 SHA-256 `42d814d0c376d31d8aeb0a77e3c100499f388ff51bb727996e4e96fceea931c2`. Codex 신규 호출 3회, 재호출 0, JEV 신규 호출 0. JEV 값은 직전 실평가 기록을 사용한다.

## 결과와 라벨 재검토

| 기존 잠정 라벨 | JEV v2.2 | Codex 검수 | Codex가 명시한 주요 이유 |
|---|---|---|---|
| 정상 → accepted 기대 | held | held | 핵심 도서관 용도는 지지하지만, 소재지가 안양이라는 문장이 발췌에 명시되지 않음 |
| 근거 부족 → held 기대 | held | held | 위치 근거와 지붕의 음향 설계 목적 근거가 부족함 |
| 모순 → rejected 기대 | rejected | rejected | 도서관·독서 공간이라는 출처 설명이 후보 답변을 직접 반박함 |

첫 사례의 핵심 answer는 두 모델 모두 pass를 선택했다. JEV는 낮은 신뢰도로 보류했고, Codex는 해당 답변을 지지했다. 전체 후보에서는 Codex도 location을 uncertain으로 판정했다. 제공 자료에 “안양파빌리온”, “안양공공예술프로젝트”라는 명칭은 있으나 소재지를 직접 적은 문장은 없다. 이름으로 위치를 추론할 수 있는지에 대한 기준과 라벨을 독립 검토해야 한다.

따라서 이전 보고의 **“정상 후보 과보류가 확정됐다”는 해석은 유보**한다. 첫 사례는 핵심 설명에 근거가 있다는 뜻의 잠정 supported였고, 모든 필드가 확실히 지지되는 정답 사례라는 검증은 없었다. JEV가 여러 필드를 낮은 신뢰도로 보류한 사실은 그대로지만, 최종 held가 오판이라고 이 데이터만으로 단정할 수 없다. 원래 라벨·원응답을 사후 변경해 점수를 높이지 않았으며, 2/3 같은 수치를 검증된 정확도로 사용하지 않는다.

Codex는 첫 사례에서 location 한 항목만 uncertain이었다. JEV는 support 9개가 수치 기준에 미달했다. 이 차이는 검토 근거를 설명하는 방식과 신뢰도 정책 차이이며, 곧바로 Codex의 일반적인 정확도 우위를 뜻하지 않는다. 독립 인간 라벨·새로운 주제·블라인드 확장 평가가 없다.

- JEV 기존 서버 bridge 경과: **2,246 / 493 / 450ms**. 서버 프로세스 시작과 모델 호출을 포함하며 SSH 왕복은 제외한다. 측정 경계가 다르므로 정밀한 속도 배수나 p95 비교는 하지 않는다.
- Codex 보고 사용량: 입력 **71,549**, 출력 **2,149**, cached input **0**, 별도 reasoning_output_tokens 필드 합계 **437**. reasoning 토큰을 출력에 임의로 더해 비용을 산출하지 않았다. 전역/런타임 지침을 포함한 CLI 사용량이므로 순수 사용자 프롬프트 크기와 다르다.

## 실행 진단과 보존

첫 호출은 CLI exit 0, turn.completed 1회 및 유효 JSON을 반환했지만, 비교 실행기의 관찰기가 `item.completed/error` 2개를 금지된 실행으로 취급해 exit 1로 중단했다. 그 응답을 버리거나 다시 호출하지 않았다. 후속 실행기는 진단을 별도 보존하며 미실행 2건만 이어 처리했고 exit 0으로 종료했다.

후속 두 호출의 오류 이벤트는 로컬 `mcp_servers.socar-grafana.oauth_client_id` 미지원 설정 경고였다. 관련 설정 값·인증정보를 읽거나 설정을 바꾸지 않았다. 첫 호출의 오류 원문은 초기 관찰기에 수집되지 않아 동일 경고였다고 확정할 수 없다. 이 한계를 기록하며, 세 모델 호출 모두 정상 종료·유효 11항목 응답을 확인했다. 검색 결과나 외부 도구 실행 item은 관측하지 않았다.
