# Hanmadi 언어 선택·한글 발음 개선 검증

## 변경 범위

로그인 성공 직후 한국어·태국어·일본어 선택 화면으로 이동한다. 선택한 언어로 학습·AI 회화를 진행하며, 상단 메뉴 이동과 새로고침 및 언어 매개변수가 없는 `/learn`, `/conversation`에서도 선택을 유지한다. 기본 홈은 학습 화면으로 연결하고 기존 튜터 허브는 `/tutor`에 보존했다.

원인은 두 가지였다. 기존 학습 화면의 언어 상태가 컴포넌트 안에서만 바뀌었고, 상단 AI 회화 링크에는 언어가 없어 `/conversation`이 한국어를 기본값으로 선택했다. Dify 지침도 한국어 설명 중심의 응답을 허용했다.

- `/languages` → `/api/learning-language` 폼으로 비밀이 아닌 언어 선호를 HttpOnly/SameSite=Lax 쿠키에 저장한다. 운영에서는 Secure다.
- 명시적인 URL 언어를 우선하고, 없으면 브라우저 저장값을 쓴다. 둘 다 없으면 한국어로 추정하지 않고 선택 화면으로 보낸다.
- 로그인·로그아웃은 언어 쿠키를 지운다. 새 로그인은 항상 언어를 선택하며, 계정 간 언어가 자동 승계되지 않는다. 여러 기기 간 계정 동기화 기능은 아니다.
- 언어 선택을 거쳐도 유효한 학생 링크와 회화 수업 매개변수는 유지한다. 복귀 경로는 `/learn`과 `/conversation`만 허용한다. 언어 쿠키로 회화 접근 권한을 부여하지 않는다.
- 언어 변경 시 회화 컴포넌트가 새로 마운트되어 이전 언어의 대화를 이어 쓰지 않는다.
- 일본어·태국어 각 12개 학습 표현과 퀴즈 보기, 회화 시작 표현에 한글 발음을 표시한다. 기존 원문·로마자·뜻도 유지한다.
- 태국어·일본어 학습 중에는 한국어 전용 수업 메뉴를 주 학습 메뉴에서 감추고 튜터 도구에 보존한다.
- LiteLLM 직접 지침, Dify에 전달하는 상황 정보 및 Dify DSL 지침에 원문 → 한글 발음 → 한국어 뜻을 명시한다. 마지막 질문도 학습 언어로 하도록 한다.

브라우저 검증 서버는 합성 PIN·가짜 Dify를 사용하며 운영 비밀을 복사하지 않는다. 기존 통합 검사의 인증 쿠키 추출도 다중 Set-Cookie에서 `hanmadi_tutor`를 고르도록 수정했다. 언어 선택 폼은 same-origin referrer 정책을 사용해 브라우저의 Origin 검사를 통과하면서 외부 사이트에 학생 링크를 전송하지 않는다. 테스트 후 임시 서버·브라우저는 종료했다.

## 발음 표기의 범위

한글은 읽기 보조이며 IPA나 정확한 성조 표기가 아니다. 태국어 성조 및 일본어 장음·억양을 완전히 표현하지 못한다는 안내를 화면에 표시한다. 동적 AI 발음 표기의 정확성 전수를 보장하지 않는다. 예를 들어 기존 Dify 지침을 사용한 실응답에서는 태국어 원문 앞에 한국어 소개가 붙고 발음 누락도 관찰됐다. 새 지침 실모델 시험에서는 요구 형식이 나왔지만 지속적인 수업 품질 검토가 필요하다.

자료 참고: [일본국제교류기금 이로도리 입문](https://www.jpf.or.kr/irodori/starter/pdf), [KOTRA 태국 출장자료의 생활회화](https://dl.kotra.or.kr/pyxis-api/1/digital-files/c16960ef-f813-018a-e053-b46464899664). 보조 한글 표기는 이 프로젝트가 작성했으며 해당 기관이 모든 표기를 검수했다는 뜻은 아니다.

## 반영 상태와 배포 절차

이 결과는 `feat/hanmadi-language-flow` 구현 브랜치의 검증 기록이다. 운영 웹 배포와 Dify 게시본은 아직 변경하지 않았다. PR별 사용자 머지 승인 규칙을 따른다.

승인 후에는 PR 머지 → Hanmadi 운영 빌드/배포 → 기존 Hanmadi Dify 앱의 LLM system 지침을 이 PR의 DSL과 동일하게 갱신·게시 → 운영 로그인부터 세 언어 회화/한글 발음 재검증 순서로 적용한다. 새 Dify 앱이나 새 앱 키를 만들 필요는 없다. 기존 대화는 새 대화로 시작해 변경된 지침을 확인한다.
