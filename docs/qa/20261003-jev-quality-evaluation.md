## 실행 경로와 한도

`apps/hanmadi/scripts/video-jev-quality-evaluation.mjs`는 현재 `judgeVideo`를 그대로 호출한다. JEV 5항목 판정 → 불확실 후보의 `hanmadi-chat` 검수 → 통과 후보의 JEV 의미 중복 비교다. 운영 프롬프트·임계값·모델 선택·사람 승인 로직을 변경하지 않는다.

- 기본 실행/`--plan`: API와 자격 조회 없이 사례 수·기준·자료 및 판정 소스 해시를 출력한다.
- 실호출: `--live --max-requests N` 필수, 1~12회. 배치당 최대 JEV 2회 + LLM 1회, 4개 배치 순차 실행. 실제 네트워크 전 한도를 검사하고 재시도하지 않는다. 한도/통신 오류와 검수 오류를 결과에 남기며 후속 배치를 중단한다. 한 배치 내 정상 후보의 후속 중복 판정은 운영 함수의 원래 동작을 따른다.
- 전용 `HANMADI_JEV_API_KEY`, `LITELLM_API_KEY`, `LITELLM_BASE_URL`, `LITELLM_MODEL=hanmadi-chat` 필요. 선택적 `HANMADI_VIDEO_REVIEW_MODEL`도 `hanmadi-chat`만 허용한다. 임시 키의 모델 범위·서버 지출 한도는 운영 담당자가 별도로 설정해야 한다. 요청 수 제한이 달러 지출 제한을 대신하지 않는다.
- 입력은 합성 `unit`과 학습 상황만 전달한다. ID·기대 결과·유형·라벨 근거는 모델에 보내지 않는다. 사용자 초안·동영상·개인 데이터를 읽거나 저장하지 않는다.
- 요청별 단계·모델·HTTP 상태·소요 시간·토큰 수, 언어별/유형별 결과, 최종 판정과 원래 JEV 체크를 기록한다. `rawQualityDisposition`은 원래 체크의 결합 결과이며 별도 실행한 JEV 단독 비교 실험이 아니다.
- 제공자 응답 원문·키·헤더·예외 본문은 결과에 보관하지 않는다. 토큰 미확인은 `unknownRequests`로 남긴다. 비용은 추정하지 않고 `actualCostUsd: null`; 실행 뒤 해당 임시 키의 서버 원장으로 따로 대조한다.

```sh
cd apps/hanmadi
npm run test:jev-quality -- --plan
# 별도 범위·예산으로 발급한 키를 안전하게 환경에 주입한 뒤에만:
npm run test:jev-quality -- --live --max-requests 12
```

출력은 운영 판정 함수의 진단 이벤트와 마지막 `hanmadi_jev_quality_result`가 함께 있는 줄 단위 JSON이다. 로그 파일이 필요하면 사용자 공용 iCloud 작업 루트의 이 작업 전용 하위 폴더로 보낸다. 키 파일은 이 위치에 만들지 않는다. 프로세스가 0으로 끝나도 `--plan`이면 모델 검증이 실행된 것이 아니다. 실호출은 미완료/기준 미달 시 exit 1이다.
