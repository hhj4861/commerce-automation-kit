# 완료 훅: 이전 턴의 미응답 호출로 인한 후속 바인딩 실패

## 원인과 수정

`dispatch_context`와 `same_turn_batch_envelope`가 모든 턴의 미응답 outer 호출을 합쳐 유일성을 검사했다. 이전 턴의 중단 호출에 응답이 없으면 현재 턴의 정상 단일 호출도 바인딩되지 않았다. 실제 실행 전 승인 거절은 native 명령 종료 이벤트가 없으므로 이 누락이 완료 게이트의 추가 미확인 호출로 남았다.

현재 턴 ID가 확인된 호출만 바인딩 대상으로 삼는다. 턴 정보가 없는 호출은 계속 모호성으로 남기고, 같은 턴의 복수 호출은 거부한다. 기존 cross-turn wait 검사는 별도 경로로 유지한다. 이전 미확인 호출을 지우거나 종료로 간주하지 않는다.

이미 발생한 누락은 아래를 모두 증명할 때만 `declined`, `exit_code: null`로 복구한다.

- v19의 바인딩 없는 Bash Pre이며 파일 변경 경로·종료 증거가 없음.
- 원본 호스트 기록에 먼저 시작된 다른 턴의 미응답 호출이 실제로 존재.
- 현재 턴의 단일 literal 명령, 또는 명령 뒤의 빈 결과 조회 한 개인 형식.
- 유일한 요청·준비·응답 구간에 호스트의 실제 프로세스 생성 전 거절이 존재.
- 같은 구간의 다른 실행·Pre·완료 증거, 다른 사용자, 동적 소스, 성공·진행 중·일반 오류·취소는 거부.
- 원본 거절 파서를 재사용하며, 복구 후 파일 관찰·커밋·원격 확인은 기존 reconcile이 수행.

## 검증

`python3 -B tools/test-task-finish-hook-dispatch-turn.py`: 13개 통과. 정상 단일/후속 poll, 알 수 없는 턴·같은 턴 중복, 응답 누락·중복·다른 턴, 동적 소스, 실행 증거 충돌, 기존 바인딩·잘못된 시각·다른 사용자, 설치본 변경 거부를 확인했다.

실제 세션 transcript와 현재 상태를 읽기 전용으로 후보 코드에 대조했다.

- `exec-1529220f-dd6b-45fe-ab9a-fbc5ec75a777`: 원본 `call_6teARjKzaNoiSU6t8ERgZudt`의 실행 전 거절을 식별. `declined`, exit code null, step 0. 이 호출은 중단된 변수 등록이 아니라 사용자 구체적 승인 **이전**의 실제 승인 검토 거절이었다.
- `exec-7c2d308f-afb2-48a3-8f69-050f6f891e47`: 증거 없음으로 복구하지 않음. 원래 종료 코드는 여전히 미확인.
- 전역 설치본이 작업 중 다른 변경으로 갱신되자 SHA-256 검사가 설치를 거부했다. 추가된 restart-fetch/restart-decline 기능을 보존한 `6d60104f828543b7e6f1f4d0fbdbc98c6a5c524555b867d0b116ec46730ff51f`를 기준으로 재검증했다.
- 호스트 transcript가 읽는 도중 바뀌면 계속 거부한다. 실제 대조는 명령 종료를 기다려 안정된 원본 기록으로 수행했다. 로그나 증거 DB를 수동 편집하지 않았다.

## 적용 상태

현재는 구현·검증된 후보이며 전역 설치 전이다. 설치기는 검토한 입력 SHA와 커밋된 설치기 일치를 확인하고, 백업 후 원자적으로 교체한다. 실제 적용 및 공식 reconcile 결과는 아래에 후속 기록한다. 과거 종료 미확인 한 건을 완료로 만들거나 전체 훅 이력 정리가 끝났다고 보고하지 않는다.
