# Hanmadi 관리자 UI/UX 정리 — 2026-10-15

## 변경

관리자 전체의 탐색·작업 공간·공통 스타일을 정리한다. 기존 여덟 기능과 서버/API 계약을 유지하며 운영 데이터·인증·유료 호출 설정은 변경하지 않는다.

| 업무 영역 | 세부 작업 |
|---|---|
| 콘텐츠 준비 | 영상 찾기, 원문·작업 |
| 검수·반영 | 자료 만들기(편집·검수·게시), 번역 후보, 앱 반영 확인 |
| 학습 운영 | 학습 관리, 음악 관리 |

AI 진단은 상단 보조 도구로 옮겼다. 영역별 마지막 작업을 다시 열며, 기존 영상 검수·번역 후보 가져오기 같은 자동 이동은 해당 영역을 함께 선택한다. 실행 중 이동 차단은 유지했다. 번역 후보 0건 배지는 숨기고, 실제 후보가 있을 때만 표시한다.

- 큰 홍보 문구 대신 현재 작업의 제목과 다음 행동 안내를 제공한다. 원문 정리와 학습 자료 생성·게시를 혼동하지 않게 구분한다.
- 데스크톱은 왼쪽 업무 탐색과 넓은 본문, 모바일은 세 영역과 현재 작업만 표시한다.
- 학습 자료 현황은 조회에 성공한 실제 초안·게시·번역 대기 수다. 원문·음악 수를 합친 숫자로 표시하지 않는다. 실패 시 0건으로 보고하지 않는다.
- 공통 폼·상태·버튼·포커스와 음악/학습 관리의 제목을 정리했다. API·자료 생성·검수/게시 의미는 바꾸지 않았다.
- 원문 화면은 목록/상세 작업을 나누고, 빈 목록에 첫 등록 행동을 제공한다. 모바일의 긴 목록은 선택 상자로 바꿨다. 기존 원문에서는 새 버전 입력을 접어 결과·실패·시도 이력을 먼저 읽을 수 있다.
- 키보드 건너뛰기 링크, native button/select/details, 텍스트 상태 설명, 축소 동작 설정을 적용했다. WCAG 전체 인증이나 실제 보조공학 사용자 검증을 주장하지 않는다.

## 검증

- 단위 테스트 289개 통과(서버 로직 변경 없음).
- 전체 TypeScript·변경 파일 lint·Next production build 통과. 마지막 메뉴 이동 뒤 영향 검사와 관련 브라우저 회귀는 아래 최종 결과에 기록한다.
- 실제 Next 관리자 UI→API→파일 저장 브라우저에서 세 영역/여덟 화면 접근, 1440·390·320px 가로 넘침, 키보드 Enter·건너뛰기와 대표 화면의 CSS 200% 확대 배치를 확인했다.
- 같은 E2E에서 네 언어 원문 저장·정리·실패·수정 버전·재접속·삭제와 권한/Origin/입력/충돌 경계를 확인했다. 자체 fixture이며 운영 쓰기 검증이 아니다.
- 1차 시각 검토에서 모바일 원문 목록이 길고 입력 폼이 결과를 밀어내는 점을 발견해 선택 상자와 접는 폼으로 보완했다. AI 진단을 헤더로 옮겨 모바일 탐색 높이를 줄였다. 최종 desktop/mobile 캡처를 직접 확인했다.
- E2E helper는 숨은 메뉴를 우회하지 않고 관리자가 보는 업무 영역과 세부 작업을 실제 클릭한다. 기존 업무 판정/게시 단언을 유지한다.
- 최초 테스트 파일 작성·lint 실행에서 작업 디렉터리를 root/앱으로 잘못 잡아 경로·설정 오류가 발생했다. 올바른 cwd로 수정하고 검증했다. 실패를 통과로 보고하지 않는다.

증거는 지정 iCloud 작업 폴더 `commerce-automation-kit/20261015-admin-workspace/`의 `browser-1`, `browser-final`, `browser-reviewed`, `unit.log`, `build.log`, `v2.log`에 보관한다. 원본/로그는 자체 fixture이며 운영 인증정보를 복사하지 않았다.

## 최종 상태

원문·작업 브라우저와 전체 V2 E2E(영상 분석→초안→사람 검수·게시→학습 반영, 번역 후보, 학습 버전/평가/활성화 포함)가 통과했다. 외부 공급자는 fixture이며 실제 유료 학습을 수행하지 않았다. 최종 메뉴 배치의 타입·lint·build도 exit 0으로 확인했다. 본인 변경만 커밋·push하고 PR로 전달한다. 새 PR의 머지·운영 배포 전이며 기존 운영 UI를 변경했다고 보고하지 않는다.
