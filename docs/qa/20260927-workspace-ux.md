# Shopshorts 워크스페이스 UX

## 화면 역할

- 로그인 후 홈: AI 계정 연결 안내 → 제작 방식 선택. 연결 기능은 계정 연결 세션 소유.
- `/studio`: 새 제작의 자동/수동 선택. `/studio?mode=auto`는 기존 쇼핑쇼츠 자동 초안 요청, `/studio?new=1`은 카테고리·형식을 정하는 수동 제작.
- `/contents`: 자동 작업과 수동 프로젝트 및 아직 작성 중인 초안 요청을 함께 조회. 검색, 방식, 제작 상태로 필터. 각 작업의 원래 편집 화면으로 이어가기.
- 홈: 최근 미완료 작업 3개와 전체 콘텐츠 링크. 이어하기는 제작 단계가 아닌 저장된 작업을 여는 동작이다. 별도 메뉴로 중복하지 않는다.
- 트렌드 탐색과 블로그 POC는 독립 메뉴. 트렌드는 소재를 찾는 보조 도구이고 새 제작의 필수 통과 단계가 아니다.
- 기존 자동 작업의 승인·검수·발행은 홈의 접을 수 있는 작업 관리 영역에 유지. 콘텐츠에서 자동 작업을 열면 해당 관리 영역을 펼친다.

## 화면 구성과 디자인

기존 서비스의 서체와 색상을 유지하고 정보 계층을 개선한다. 바탕 `#f7f7f4`, 본문 `#242622`, 보조문구 `#73776f`, 강조 `#ff6b4a`, 진행상태 `#277e64`, 경계 `#e5e6df`. DM Sans와 Noto Sans KR, 제목 28–32px, 본문 14px. 왼쪽 정렬.

```
홈       계정 연결 안내 / 새 영상 만들기
         최근 작업 3개 → 콘텐츠 전체
         트렌드 탐색 | 블로그 POC
         ▸ 자동 제작 작업 관리
제작실   계정 연결 안내
         자동 생성 | 수동 생성
         콘텐츠에서 이어하기
콘텐츠   검색 / 제작방식 / 상태 / 정렬
         자동·수동 작업 통합 목록
```

검토: 숫자 통계와 동일 카드로 가득 찬 대시보드보다 '지금 어디서 시작하거나 다시 열 것인가'를 우선한다. 큰 시각적 강조는 제작방식 두 선택지에만 사용한다. 모바일에서는 한 열로 배치하고 기본 링크·폼 컨트롤의 키보드 동작을 유지한다.

## 계정 연결 세션과 통합 계약

대상: `개선해 쇼츠 영상 생성기` (`01a0b3ac-df1b-7293-a99c-74f3c6e650d0`). UX 세션은 index.html/studio.html의 배치를 담당하고, 상대 세션은 ai-account.js/css, llm-connection.js, 로그인과 계정 연결 로직을 담당한다.

예약 위치: 홈 hero 직후, 제작실 `#modes` 직전의 `[data-ai-onboarding]`; 공통 상단·모바일 `[data-ai-account]`. 연결 완료 후 제작방식 선택은 `/studio`; 진행 중 프로젝트 딥링크는 보존한다. 양쪽 HTML 변경은 통합 시 슬롯 단위로 유지한다. 발송과 실제 합의/검증은 구분해 아래에 기록한다.

## 데이터와 검증 원칙

- `/api/jobs`, `/api/studio`, `/api/hot-keywords`의 requests를 독립 조회한다. 한 소스 실패를 빈 목록으로 숨기지 않는다.
- 서로 다른 저장소 ID가 같아도 별개 콘텐츠다. 작성 완료된 요청은 별도 콘텐츠로 중복 표시하지 않는다.
- 미리보기만 있는 자동 작업은 완성으로 분류하지 않는다. 최종 렌더와 실제 업로드 완료를 구분한다.
- 자동 생성은 기존 승인/검수 절차를 유지한다. 새 계정 연결이 기존 자동 파이프라인의 인증 방식을 변경했다는 주장은 하지 않는다.
- 운영 데이터 생성·변경 없이 격리된 fixture에서 사용자 흐름을 검증한다.


## 통합과 검증 결과

- 계정 세션의 응답 문서 `docs/qa/20260927-editor-account-review.md` 최종 통합 계약을 수용했다. 해당 세션은 송신 도구 부재로 문서에 응답했고, UX 세션은 이를 직접 읽고 확인했다.
- 계정 모듈 커밋 `b55143c`(PR #36)를 작업 브랜치에 fast-forward 통합했다. 모듈을 중복 구현하지 않고 홈 hero 아래, 제작실 방식 선택 위, 양쪽 데스크톱·모바일 상단에 실제로 부착했다.
- 최종 `npm test -w @cak/app-shopshorts`: 261개 통과, 실패 0, 종료 코드 0. 계정·편집기·미디어·게시 회귀 테스트를 포함한다.
- 추가한 목록/초안 테스트 8건: 서로 다른 저장소의 동일 ID 보존, 요청 중복 제거, 미리보기/최종 영상/업로드 구분, 복합 필터, 일부 소스 실패, XSS 이스케이프, 자동 요청 검증·중복·401/503, 모듈 초기화 전 목록 렌더.
- Chrome 실제 클릭, 격리 서버 `http://127.0.0.1:5211`: 미연결 안내 → Codex 모달 → fixture 연결 완료 → 제작 방식 선택 → 자동 요청 → 통합 목록 반영을 확인했다. 실계정 OAuth나 구독 생성 시험은 아니다.
- 수동 시작 → 기획 입력·저장 → 시나리오 단계 → 콘텐츠 목록 → 기존 영상 이어하기에서 저장 ID와 시나리오 단계 보존을 확인했다.
- 자동·수동·작성 대기·업로드 완료 6개 콘텐츠 동시 노출, 제목 검색, 수동 방식 필터를 실제 화면에서 확인했다. HTTP 조회에서도 새 수동 프로젝트와 초안 요청의 저장을 확인했다.
- 브라우저에서 발견한 초기화 충돌: `id=contentLibrary`가 window에 노출되면서 초기 `window.contentLibrary.mount` 호출이 DOM 노드를 가리켰다. 컨트롤러를 `window.workspaceContent`로 분리하고 재현 회귀 테스트 및 브라우저 새로고침으로 해결 확인.
- 목록 일부 실패·복구: 실제 격리 HTTP 응답으로 수동 목록 503일 때 자동/대기 3개와 명시적 오류가 유지되고, 복구 후 6개가 반환됨을 확인했다. 실패 상태는 검증 후 원복했다.
- 데스크톱 홈·방식 선택·콘텐츠·이어하기 스크린샷을 확인했다. 모바일 반응형 스타일은 구현했으나 모바일 전환 시 Chrome 접근성/스크린샷 도구가 빈 응답을 반환하여 실제 모바일 화면 검증은 미확인이다.
- 운영 데이터·실계정 인증·유료 생성·발행을 변경하지 않았다. PR 승인 전 main 머지와 운영 배포는 하지 않는다.
