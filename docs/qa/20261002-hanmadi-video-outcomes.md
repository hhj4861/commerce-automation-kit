# Hanmadi 영상 분석 결과·진행 상태 개선

2026-10-02 KST. 대상: Hanmadi Admin 자료 준비 목록.

## 신고 원인 확인

- 신고 영상: [처음 본 일본인과 스몰토크 잘 하는 법](https://www.youtube.com/watch?v=71gMyqGhDCk).
- YouTube의 실제 플레이어에서 제목과 **28분 38초**를 확인했다. 영상·자막을 다운로드하지 않았다.
- 운영 코드의 영상 길이 한도는 900초(15분)이다. 이 오류는 `videoDetails`가 `analyzeVideo`의 모델 호출 전에 발생시키므로, 신고된 시도는 영상 정보 검사에서 중단됐고 내용 분석·JEV·저장을 시작하지 않았다.
- 기존 오류는 길이 초과, 비공개, 라이브, 누락된 정보를 같은 문장으로 처리했다. 클라이언트는 모두 ‘다시 시도 가능’으로 표시하고 저장 0건에도 ‘일괄 처리를 마쳤어요’라고 안내했다.
- 공식 API 필드 정의 참고: [YouTube videos resource](https://developers.google.com/youtube/v3/docs/videos). 로컬에 지정된 과거 `.env`는 읽기 시 빈 내용이 반환되어 이 조사에서 API 키를 확보하지 못했다. 따라서 영상 길이 실측은 API 실호출이 아닌 공식 YouTube 플레이어 확인 결과이다. 파일·키·운영 설정은 변경하지 않았다.

## 개선된 동작

1. 길이 초과는 실제 길이와 15분 한도를 표시한다. 비공개·라이브·조회 불가를 별도 원인으로 전달하며 `blocked`로 분류한다. 불완전한 정보나 API 장애는 재시도 가능한 실패로 남긴다.
2. 영상 정보 검사를 AI 호출 및 하루 50건 카운터보다 먼저 수행한다. 정상 영상의 메타데이터는 모델 호출에 넘겨 재조회하지 않는다. 10개 선택·3개 동시 처리·15분 길이 한도를 유지한다.
3. 소유자 인증과 기존 batch 검증을 거친 `status` 요청으로 실제 단계(영상 정보 확인 → 내용 분석 → 학습 가치 평가 → 저장)를 읽는다. 모델 호출은 없으며 실행 중인 목록만 최초 1.5초 후, 이후 앞선 조회 종료 5초 후 조회한다. 종료/언마운트 후에는 재조회하지 않고 늦은 응답이 최종 결과를 덮지 않는다.
4. 상단에서 저장된 초안 수, 분석 불가 수, 처리 중단·결과 확인 필요 수를 보여 준다. 영상별로 실행된 단계와 아직 실행하지 않은 단계를 명시한다. 연결 끊김·저장 응답 유실은 미저장이라고 단정하지 않는다.
5. 분석 불가 영상을 일괄 재시도에서 제외한다. 이 영상만 남으면 ‘분석 불가 영상 빼기’를 제공한다. 재시도는 기존 저장 초안과 분석 캐시를 먼저 확인한다.
6. 작업 시작 시 자료 설정을 접어 결과와 다음 행동을 먼저 보여 준다. 언어·상황·레벨을 변경하면 이전 설정의 화면 상태를 초기화한다. 저장된 자료 자체는 삭제하지 않는다.
