# 그림 중심 자동제작 검증 — 2026-09-30

## 변경

기존 자동제작의 주제 추천 → 자료 검색 → 대본 작성 → 사람 승인 → TTS/장면 생성 → 자막/최종 렌더 → 발행 검수 경로에 그림 중심 렌더러를 연결했다. 새 애니메이션 대본은 `presentation: illustrated`와 제한된 대상·표정·동작·배치를 선택한다. 코드나 외부 SVG를 실행하지 않는다.

`illustration-art.mjs`는 직접 제작한 Jev 영상의 원본 벡터 인물·사물에서 재사용 가능한 그림만 옮겼다. Jev 이름과 특정 영상의 장면 순서는 포함하지 않는다. `illustrated-animation.mjs`가 전달·이동·반응·비교 구성을 담당한다. 기존 저장 대본과 건축 원리 도해는 이전 렌더 경로를 유지한다. Higgsfield 선택도 유지한다.

## 검증 결과

- `npm test -w @cak/app-shopshorts`: **305 통과, 0 실패**. 최초 sandbox 실행은 tsx IPC 권한으로 실패했고, 권한 승인 후 전체 테스트가 통과했다.
- 27개 허용 대상 × 세로/가로 렌더, 결정적 프레임, 진행바를 제외한 실제 움직임, 입력 검증 및 XML escaping 확인.
- 자동제작 통합 테스트: 1.15배 음성 길이를 측정하여 장면 길이를 맞추고, 가운데 자막 및 오디오 트랙이 있는 1080×1920 MP4 완성. 중복 생성 방지와 Higgsfield 경로 검증.
- Chrome에서 격리 서버 `http://127.0.0.1:5231/studio/dashboard?mode=auto`를 통해 추천 → 자료 확인 → 대본 검토 → 승인 → 발행 검수까지 실제 UI/API/워커로 진행.
- 브라우저에서 최종 MP4 `readyState=4`, `paused=false`, `currentTime=0.257877`, 길이 3.266667초 확인. 최종 파일 전체 ffmpeg 디코딩 성공.
- 브라우저 검증은 검색/LLM/TTS 제공자 응답을 fixture로 대체했다. 실제 영상/자막/오디오 합성은 실행했고 TTS 소리는 검증용 톤이다. 실제 구독 LLM 호출 및 신규 유료 TTS 생성 검증으로 해석하면 안 된다.

## 운영 반영 상태와 다음 단계

이 변경은 작업 브랜치에만 있다. 기준 main은 b8adaae이며 기존 자동 제작 PR #80이 포함된다. 운영 사이트는 구 UI이고, 운영 제작 checkout은 1b8da461이다. Pages만 배포하면 계정 워커의 대본 지시문과 제작 워커 렌더러가 바뀌지 않는다.

2026-09-30 03:46 UTC 운영 `/api/studio/config`에서 HTTP 200, workerAt 03:46:07.017Z, heartbeat age 4.11초를 확인했다. 앞서 워커가 오프라인으로 보였으나 현재 연결은 회복됐다. 이 확인은 새 코드의 운영 배포를 의미하지 않는다. 작업 조회 시 queued/running 작업은 없었다.

승인된 PR 머지 후 Pages와 영구 운영 checkout의 계정·제작 워커를 같은 승인 SHA로 배포해야 한다. 현재 `deploy/shopshorts` 브랜치는 없으므로 자동 배포 활성화 완료라고 보고하지 않는다. 운영에서 새 프로젝트의 그림 대본 생성·최종 MP4까지 별도 실호출 검증이 남는다. 기존 사용자 프로젝트를 재생성하거나 자동 업로드하지 않았다.

## 한계

그림 종류와 동작은 검증된 목록으로 제한된다. 임의 주제에 맞는 새로운 그림을 LLM이 코드로 그리는 기능은 아니다. 긴 전문 설명은 기존 원리 도해 또는 Higgsfield를 선택할 수 있으며, 대본과 화면의 의미 일치는 사람 검토 단계에서 확인한다.
