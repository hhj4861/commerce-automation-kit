소스의 `apps/hanmadi/lib/auth.ts`는 소유자 PIN을 `TUTOR_PINS` 또는 기존 `TUTOR_PIN`에서 읽는다. 관리자 로그인 화면에는 PIN 찾기·재설정 기능이 없다. 자격 값은 조회·출력하지 않았고 운영 환경변수나 배포도 바꾸지 않았다.

## 이전 검증과 구분

배포·공개 경로 및 로컬/CI의 네 언어 회귀 결과는 [배포 기록](20261015-hanmadi-collected-music-production.md)에 있다. 외부 YouTube·LLM/JEV를 fixture로 검사한 결과를 이번 운영 실계정 E2E의 대체 증거로 쓰지 않는다. 이번에는 운영 런타임 로그·관리자 데이터·수집곡 게시·유료 생성 호출을 확인하지 못했다.

## 재개 조건

1. 소유자가 기존 관리자 PIN으로 로그인하거나, PIN 분실 시 운영 관리자 PIN 재설정 절차를 별도로 진행한다. PIN은 채팅·QA·로그에 남기지 않는다.
2. 관리자에서 실제 수집곡의 원문·검수·게시 상태를 확인한다. 영어 목록이 비었다는 사실만으로 모든 언어에 수집곡이 없다고 단정하지 않는다.
3. 검증용 학습 계정을 분리해 게시곡의 실제 재생 → 단어/회화 → 복습 → 새로고침 후 진도 복원을 검증한다.

이번 기록은 확인 범위와 차단 원인의 저장이며 제품 코드 수정이나 운영 E2E 완료를 뜻하지 않는다.

## PIN 재설정 후 보완 — 2026-10-15T03:17:04Z

사용자의 명시적인 재설정 승인 후 운영 관리자 PIN을 교체했다. 실제 HTTPS 로그인 API는 HTTP 200, `ok=true`, `role=owner`였고 같은 프로세스 메모리 세션으로 음악 관리자 GET 200을 확인했다. 응답은 `songs=0`, `collection=0`이었다. 최초 영어 화면 관찰보다 범위가 넓은 관리자 조회 결과이며, 당시 운영 저장소에는 등록곡과 수집 영상이 모두 없었다.

이 검사는 브라우저 E2E 성공을 뜻하지 않는다. 브라우저는 PIN 입력까지 확인했지만 클릭 제어가 응답하지 않아 로그인 화면 전환은 미확인이다. 수집 자료 등록·자막 연결·검수·게시 및 학습자 완료·복습·진도 저장도 여전히 미실행이다. PIN·세션 쿠키·개인 진도는 QA 산출물에 저장하지 않았다. 설정·배포 경과는 [PIN 재설정 기록](20261015-hanmadi-admin-pin-reset.md)에 별도로 적었다.
