# Hanmadi 영상 자료의 언어 교차 검수 — 2026-10-02

## 상태

운영의 정상 표현 자동 채택률을 높이기 위한 구현/검증이다. 작업 브랜치에만 반영했으며, main 머지와 운영 배포는 별도 승인 전이다. JEV v6의 다섯 항목 판정(PR #117, b67660a)을 기반으로 v7 언어 검수를 추가한다. 이번 PR은 초안 #117을 포함해 대체하며 운영 모델 학습·자료 게시를 실행하지 않는다.

정상 표현 전체가 자동 채택되는 문제 해결은 **아직 완전하지 않다**. 고정 정상 14건 중 v6 0건 → v7 2건이 자동 통과했고, 12건은 주로 JEV 상황 적합성 또는 기존 자료 중복 판단의 불확실성 때문에 검토 대기로 남는다. 임계값을 낮춰 이를 자동 통과시키지 않았다.

## 최종 동작과 운영 설정

1. JEV가 뜻·발음·근거·상황·신규성을 각각 평가한다. 기존 confidence ≥ 0.85, 선택 확률 ≥ 0.9를 유지한다.
2. 확실한 실패 또는 기존 자료와 정확히 같은 표현은 제외한다. 추가 모델은 이를 되살리지 못한다.
3. **상황·신규성이 확실히 통과했고 뜻·발음·근거에 불확실성이 남은 후보만** 영상당 한 번의 언어 검수 요청으로 묶는다(최대 6개). 후보 원문·뜻·발음은 수정하지 않는다.
4. 언어 검수는 항목별 `pass / fail / uncertain`과 짧은 근거를 반환한다. 세 항목 모두 pass이면 품질 통과, 명시적 오류는 제외, 불확실/연결 실패/파싱 실패는 검토 대기다.
5. 품질 통과 후보만 기존 2차 JEV 의미 중복 검사에 들어간다. 최종 통과한 앞 후보만 중복 기준이 되며, 제외·검토 대기 후보는 중복 기준으로 쓰지 않는다.
6. 모든 저장 결과는 초안이다. 검수·게시 게이트 및 검토 대기 자료의 학습/파인튜닝 제외를 유지한다.

- 언어 모델: `HANMADI_VIDEO_REVIEW_MODEL`이 있으면 사용, 없으면 기존 `LITELLM_MODEL`. 기존 Hanmadi `LITELLM_BASE_URL`/`LITELLM_API_KEY`와 허용 모델 별칭만 이용하며 개인 키 fallback은 없다. JEV는 별도 `HANMADI_JEV_API_KEY`를 계속 사용한다.
- 실측 별칭은 `hanmadi-chat`, 실제 공급 모델은 `gemini/gemini-flash-lite-latest`. 영상 분석과 별도의 **검수 요청**이며 독립 공급자/독립 학습 모델의 검증이라고 주장하지 않는다.
- timeout 15초(응답 본문 포함), maxTokens 1800, maxChars 8000, 자동 재시도 0. 기존 선택 최대 10개/영상 분석 병렬 3개를 유지한다. JEV 직렬 검수 잠금은 60초로 늘렸다.
- 중복/누락/범위 밖 index, 추가 필드, 잘못된 판정값, 비어 있거나 160자 초과 근거는 응답 전체를 거부한다.
- 원래 JEV `checks`·확률·confidence를 그대로 저장한다. `languageReview`에 모델 별칭·항목별 판정·근거를 분리해 저장한다. LLM의 판단을 JEV 확률로 바꾸지 않는다.
- 캐시는 rubric `hanmadi-video-jev-v7` 및 reviewModel로 구분한다. 모델 설정 변경 시 이전 결과/영구 sourceHash를 재사용하지 않는다. 기존 초안을 자동 재평가하지 않는다.
- 관리 화면은 저장 당시 JEV·언어 검수를 구분해 보여준다. evidence는 **분석 기록의 일관성 확인**이며 실제 영상 원본의 독립 사실 확인이 아니다.
- 합성 실측 CLI의 명시적 총 요청 한도는 1–6회. JEV와 언어 검수 요청을 모두 세고 공급자별 토큰 필드 차이를 처리한다. 요청 한도 때문에 중단된 결과를 성공으로 표시하지 않는다.

### 실제 모델 평가 — 고정 36건

기존 합성 일본어·카페·레벨1 gold 24건과 v6 추가 12건을 사용했다. 반복 사용한 합성 예제이며 독립 전문가의 블라인드 평가나 전체 언어/상황 정확도 근거가 아니다. 기대 라벨은 모델 입력에 보내지 않았다.

| 집합 | 결과 |
|---|---|
| 정상 14건 | 통과 2 / 검토 12 / 잘못 제외 0 |
| 명확한 오류 18건 + 기존 자료 중복 2건 | 제외 20 / 통과 0 |
| 같은 배치의 조건부 중복 2건 | 검토 1 / 통과 1 |
| 전체 | 통과 3 / 검토 13 / 제외 20 |

**기존 고정 라벨을 그대로 적용한 strict wrongAccept는 1건**이다. `receipt-politeness-duplicate`가 통과했으나, 앞선 `receipt-request`는 상황 판정 확신 .78로 검토 대기여서 유효한 중복 기준이 아니었다. 최종 통과한 영수증 표현은 1개다. 현재 계약(통과한 앞 후보만 기준)에 맞는 결과라는 해석과 기존 gold 지표를 함께 기록하며, 라벨을 사후 변경하거나 단순히 ‘오채택 0’이라고 보고하지 않는다.

실제 언어 검수는 전체 흐름에서 후보 3개에 수행됐고 모두 pass였다. 별도 **언어 검수 단독** 1회/6건에서는 정상 2개 pass, 잘못된 뜻·발음·관찰 실패·평가 지시 주입 4개 fail을 확인했다. 이 단독 시험을 전체 파이프라인 자동 채택 결과로 합산하지 않는다.

추가 실험으로 대상 언어와 상황 판정을 6개 질문으로 나누었으나 12건에서 통과 0/검토 5/제외 7로 개선을 입증하지 못했다. 해당 변경은 전부 되돌렸고 최종 코드는 5개 질문이다. 실험 원본과 패치는 별도 보존했다.
