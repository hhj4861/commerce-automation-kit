# Studio 미디어 생성 진행·실패 표시 — 2026-09-25

## 운영에서 확인한 사실

프로젝트 `19cf48bc-debc-459b-b7fc-a34332b64fd7`의 미디어 요청은 완료되지 않았다. 요청 `fc12ee4e-8de6-4afa-8ce4-7b24de0ea4c8`이 `2026-09-25T04:05:51.337Z`에 접수되고 `04:05:58.932Z`에 시작됐으며, `04:06:01.099Z` 저장 결과는 `failed` / `Google 생성 API 실패(401)` / 미디어 0개였다. 사용자가 선택한 세 장면의 유형은 모두 이미지였다.

계정·제작 실행기 연결은 정상이다. Cloudflare의 기존 `GEMINI_API_KEY`를 Google의 읽기 전용 모델 목록 API에 전달해 확인한 응답은 HTTP 401, `UNAUTHENTICATED`, `ACCESS_TOKEN_TYPE_UNSUPPORTED`였다. 로컬 프로젝트의 동일 설정도 일반 Google API 키 형식이 아니었다. 인증 값은 출력하거나 변경하지 않았다.

현재 `studio-runner.mjs`는 이미지에 Google 이미지 모델, 영상에 Google Veo를 사용한다. Codex·Claude 구독은 대본·추천 생성 경로에 연결돼 있다. 이번 변경이 Google을 새로 도입하거나 구독 토큰으로 이미지를 생성하게 하는 것은 아니다. 실제 생성 복구에는 기존 Google 인증 수정 또는 별도 생성 제공자 연결이 필요하며, 사용자에게 이 구조를 설명했다. 미디어 생성 성공을 주장하지 않는다.

## 변경

- 미디어 카드 바로 위에 단일 진행 영역 배치. 기존 상단 중복 안내는 미디어 작업에 한해 숨긴다.
- 버튼 클릭 즉시 접수 안내·활동 막대를 보여주고 중복 요청을 막는다. 접수 후에는 대기/생성 중/연결 확인/실패/완료를 구분한다.
- 진행률은 실제 저장된 장면 개수만 반영한다. 생성 시간이 지났다고 비율을 올리지 않으며, 전체 장면이 저장되기 전에는 완료로 표시하지 않는다.
- 각 카드에서 생성 전·요청 접수·생성 처리·차례 대기·준비 완료·중단을 구분한다. 실패 시 빈 미디어 문구 대신 인증 오류와 다음 조치를 결과 옆에 유지한다.
- 일부 실패 시 기존 결과를 유지하고 미완료 장면만 재요청한다. 작업이 종료됐더라도 결과가 누락됐다면 불완전 상태로 표시한다.
- 서버 인증 오류와 한도 오류의 설명을 구분하고, 제공자 원문이나 인증 값은 오류 문구에 포함하지 않는다. 대본 계정 재연결로 미디어 인증이 해결된다고 안내하지 않는다.
- 기존 Studio 글꼴과 여백을 유지한다. 진행 막대는 파랑(`#356c86`), 저장된 결과는 초록(`#347357`), 실패는 붉은 갈색(`#813626`)으로 구분한다. 단계/막대 이외 장식은 추가하지 않고, 동작 줄이기 설정을 존중한다.

## 검증

전체 Node 회귀 177개 통과. 신규 7개 테스트는 즉시 접수, 대기/진행, 실제 저장 개수, 부분 결과 보존, 인증 실패, 연결 확인, 종료 후 결과 누락, 오류 이스케이프와 제공자 비밀정보 제외를 검증한다.

Chrome에서 `127.0.0.1:5200`의 격리된 테스트 서버로 실제 UI와 `studioApi`를 연결했다. 제공자와 작업 진행만 테스트 대역이며 외부 유료 생성이나 운영 결과 수정은 수행하지 않았다.

- 버튼 클릭 직후 서버 응답 전에도 `생성 요청을 보내고 있어요`, 0/3 진행 막대, 비활성 버튼 표시 확인.
- 접수 후 대기 → 생성 중과 카드별 처리/차례 대기 표시 확인.
- 첫 장면 저장 후 미리보기가 표시되고 1/3으로 갱신됨. 이후 401 실패 시 해당 이미지를 유지하고 인증 실패·미완료 재시도 표시 확인.
- 새로고침해도 실패 원인과 1/3 결과가 유지됨. 재시도 클릭 직후 기존 장면을 유지한 접수 표시 확인.
- 재시도 완료 시 새로고침 없이 3/3, 세 이미지 미리보기, `모든 장면이 준비됐어요`, 활성화된 `편집하기` 버튼을 확인했다. 스크린샷으로 진행 영역과 결과가 함께 보이는 배치도 확인했다.

작업 브랜치에 구현하며, 후속 PR 머지 승인 전에는 운영 UI나 실행기 소스를 교체하지 않는다. 실제 미디어 인증 문제는 미해결 상태다.
