# 추천 반복 방지와 제작 이어하기

## 확인한 원인과 변경

새 추천 버튼은 새 작업 ID를 발급한다. 저장 결과 재열기는 알림 링크의 별도 경로다. 반면 기존 추천 이력은 알림용으로 보관될 뿐 추천 프롬프트에 전달되지 않았으며, 심리학 공통 지침에는 부모·아이 갈등 사례가 모든 주제에 포함되어 있었다. 이력이 없는 동일 입력과 특정 예시에 대한 편향이 반복 추천을 유발할 수 있는 구조였다. 운영 요청별 결과를 전수 비교하거나 실제 모델의 원인을 단정한 것은 아니다.

- Codex와 두 Claude 인증 실행 경로 모두 같은 소유자의 암호화 계정 기록에서 최근 완료 추천을 전달한다. 브라우저가 다른 사용자 이력을 지정하거나 인증정보를 프롬프트에 넣는 경로는 추가하지 않았다.
- 최근 최대 10개 기록, 기록당 최대 3개 후보의 주제·연출만 사용한다. 카테고리를 구분하고 분위기 추천은 해당 주제의 이전 연출을 제외한다. 기존 모델이 주제 제목을 재작성한 경우 원래 요청 주제로도 이력을 찾는다.
- 새 주제는 다른 하위 분야·상황·문제·핵심 메시지로 검색·제안하도록 지시한다. 부모·아이에 관한 지침은 관련 주제·요청사항이 있을 때 적용한다.
- 공백·문장부호·대소문자·유니코드 표기 차이를 정규화해 기존/동일 응답 내부의 같은 주제(분위기 추천은 같은 연출)를 검사한다. 중복이면 최대 한 번 재생성한다. 실패 시 고정된 중복 안내를 양쪽 제공사에 표시한다. 검색 근거·출처 검증과 취소는 유지한다.
- **의미가 비슷하지만 문구가 다른 기획은 프롬프트의 자체 검토에 의존한다. 의미 중복을 완전히 보장하는 결정적 검사는 아니다.** 실제 구독 모델의 연속 실호출 품질 검증은 이번 오프라인 검증에 포함하지 않았다.

## 이어하기 UX

대시보드와 제작실 첫 화면에 미완성 영상 중 최근 저장된 영상을 강조한다. 미리보기(이미지 없는 경우 기본 도형), 제목, 저장 시각, 제작 단계, 상태에 맞는 이어하기 버튼을 표시한다. 나머지 미완성 영상은 목록으로, 완료 영상은 접힌 영역으로 분리한다. 대시보드는 최근 3개와 전체 목록 링크를 제공한다. 편집 화면에서도 ‘내 영상 · 이어하기’로 돌아갈 수 있다.

오류·생성 대기/실행·완료 상태는 별도 문구로 표시하며, 실제 진입 단계는 기존 `resumeStep`과 일치한다. 로딩 오류를 빈 목록으로 오인시키지 않고 다시 불러오기 또는 로그인 동작을 제공한다. 새 프로젝트·알림 결과·기존 프로젝트 직접 링크에서는 이어하기 목록을 표시하지 않는다.

## 검증

- 앱 전체: 217개 통과, 실패 0 (13.2초). 기존 인증·알림·시나리오·미디어·음성·실제 ffmpeg 렌더 회귀 포함.
- 마지막 분위기 이력 보완 후 추천/두 제공사 실행 경로 테스트 43개 통과, 실패 0. 최종 테스트 파일에는 전체 실행 이후 추가된 이력 경계 테스트 1개가 포함된다.
- `git diff --check`, 브라우저 모듈 구문 검사 통과.
- 네이티브 Chrome, `node apps/shopshorts/test/studio-resume-browser.mjs`로 127.0.0.1:5207 격리 서버에서 확인:
  1. 대시보드 첫 화면에 최근 작업과 이어하기 표시.
  2. 이어하기 클릭 → 동일 프로젝트 ID의 4단계 편집 화면 복원.
  3. ‘내 영상 · 이어하기’ → 제작실 상단 최근 작업과 완료 영상 분리.
  4. Chrome 500% 확대의 좁은 CSS 화면에서 전체 폭 버튼/줄바꿈 확인 후 100% 복원. 실제 모바일 기기 검증은 아님.
  5. `/studio?new=1`은 목록 없이 새 영상 기획 화면 표시.
- UI fixture는 메모리 프로젝트와 합성 SVG만 사용한다. 운영 프로젝트·인증·유료 생성 호출·업로드는 사용하지 않았다.
