# 대본 불합격 근거 보존

- 목표: 실패한 실제 대본/검토 사유를 로그인한 생성 계정만 확인. 불합격 대본으로 유료 제작 금지.
- 담당/범위: Codex 단독, scenario-review-feedback worktree / fix/shopshorts-rejected-scenario-evidence. 다른 세션 파일 변경 없음.
- 기준: #215 구현 a76251a (main 머지 #215, 운영 #216). 보완 횟수·품질 기준·예산 불변.
- 완료 기준: 생성→실패→암호화 보존→닫았다 재열기→소유자 조회, 다른 계정/프로젝트 차단, HTML 이스케이프, 거부 초안이 승인 장면에 섞이지 않음 검증.
- 설계: 공유 프로젝트 목록에 원문을 추가하지 않는다. 기존 계정 Vault의 요청별 시나리오 기록에 보존하고, 소유자와 프로젝트/요청 ID가 일치하는 별도 GET으로 조회한다. 일반 계정 상태/로그에는 포함하지 않는다. ACK 후에도 검토 근거만 남는다.
- 현재: 구현 및 로컬 검증 완료. 운영 미반영. 이전 실패 원문은 복원할 수 없음. 새 PR 승인 후 운영 생성/검토 원문 확인을 진행해야 함.
- 배포 경계: Pages + 계정 워커 + credential-broker의 시나리오 보존/ACK 변경이 모두 필요하다. 다른 broker 바인딩/자격은 변경하지 않는다.

## 검증

- Node20.19.3, 운영 Node20용 의존성을 읽기 전용 참조. 시나리오 생성/보완/검토, 계정 워커/암호화 Vault, 소유자 HTTP 경계 포함 67검사 통과.
- 실제 scenarioBrief의 최종 불합격 → 워커 failed 저장 → 프로젝트 실패 상태 동기화/ACK → 새 추천 요청/계정 해제 → 원 계정 GET 조회가 유지됨. 다른 계정/다른 프로젝트/null 인증/외부 Origin 차단. 승인 장면 배열과 일반 계정 상태 및 로그에 원문이 섞이지 않음 확인.
- digest/실제 인용이 검증된 부정 검토만 보존. 임의 최상위 속성은 제거. 보관 한도 112,000 UTF-8 bytes. 초과/검증 실패는 기존 내용 불합격 상태를 유지하며 상세 자료 미보관 문구로 알림.
- Chrome 로컬 5227에서 실제 자동 제작 UI의 ‘대본과 보완 이유 보기’ 클릭 후 2개 검토 항목/해당 원문, ‘검토받은 대본 전체 · 3장면’ 펼치기 확인. 화면 캡처로 가독성 확인. 고정 테스트 대본이며 실 LLM 품질 검증 증거가 아님. 최초 DOM 클릭 타임아웃 후 새 AX 상태의 동일 버튼으로 확인 완료.
- XSS성 대사/검토 사유는 텍스트로 이스케이프. 해당 패널에는 제작 승인/유료 생성 버튼 없음.
- 실제 운영 재생성, 유료 미디어/TTS/최종 렌더는 이번 변경 검증에서 실행하지 않았다. 전체 실생성 E2E는 여전히 미완료.
