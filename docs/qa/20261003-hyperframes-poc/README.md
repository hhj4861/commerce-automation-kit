# HyperFrames P0 PoC — 설명용 모션 템플릿 3종

2026-10-03. Codex 리드(영상제작실-편집-개선)가 승인한 **P0 범위만** 수행했다. 이 PoC는 영상제작실 기능 통합(P1), 배포, 머지를 포함하지 않는다.
제작실 코드·Pages·워커는 바꾸지 않았다. 유료 API는 호출하지 않았다.

## 무엇을 확인했나

[HyperFrames](https://github.com/heygen-com/hyperframes)(HeyGen 오픈소스)는 HTML/CSS와 GSAP로 만든 장면을 렌더러 내장 Chrome으로 프레임 단위 캡처하고, FFmpeg로 MP4를 만든다.
쇼츠 본문의 설명·강조·전환 장면을 이 방식으로 만들 수 있는지 확인했다. 기준은 9:16, 30fps, 한글, 자막 안전영역, 재현성, 렌더 시간이다.
비교 대상은 main에 이미 있는 SVG→resvg→FFmpeg 설명 애니메이션 렌더러(`apps/shopshorts/studio-animation.mjs`)다.

- **도입부는 계속 Higgsfield로 만든다.** 아래 템플릿은 본문용이며 도입부를 대체하지 않는다.
- 참고 영상의 「프롬프트 88개」는 움직임을 부르는 이름을 정리하는 데만 참고했다. 템플릿, 도형, 코드는 모두 직접 작성했다. 타인의 영상·에셋은 사용하지 않았다.

## 템플릿 (`project/`)

| 파일 | 길이 | 내용 | 변수 |
|---|---|---|---|
| `chapter.html` | 3.5초 | 본문 챕터 전환. 지면 선이 그어지고 지층 단면이 열린다. 굴착 링이 회전하며 들어온 뒤 퇴장한다. | chapterNo, title, accent, showSafe |
| `countup.html` | 5초 | 숫자 비교·카운트업. 같은 축척의 깊이 막대 두 개가 내려가며 숫자가 오른다. 마지막에 차이를 괄호와 함께 강조한다. | heading, labelA/B, valueA/B, unit, note, showSafe |
| `summary.html` | 5초 | 그림 중심 핵심 요약. 고정 아이콘 라이브러리(shield·ring·train·building·layers)의 선이 그려지며 순서대로 연결된다. | heading, icon1-3, label1-3, showSafe |

- 색상(크림 바탕 #f5efdc, 잉크 #3b3932, 4색 팔레트)과 나눔고딕은 기존 렌더러와 같다. 그래서 기존 장면 사이에 끼워도 화면 톤이 튀지 않는다.
- 입력은 **변수 값만** 받는다. 임의의 HTML·SVG·스크립트 입력은 받지 않는다. `summary`의 아이콘도 키로만 고른다.
- `countup`의 기본값 20m/35m는 화면 확인용 **예시값**이다. 첫 숫자가 나오기 전부터 끝까지 "예시값 · 실제 수치 아님"이 함께 표시된다. 실제 공법이나 깊이를 사실로 확인한 값이 아니다.

## 실행

```bash
# 도구: Node 22+, ffmpeg, hyperframes@0.8.114, gsap@3.14.2 (HF_TOOL의 node_modules)
# 저장소 node_modules에서 @resvg/resvg-js를 해석할 수 있어야 기준 렌더러를 실행할 수 있다
POC_OUT=<출력 폴더> HF_TOOL=<hyperframes·gsap 설치 폴더> node docs/qa/20261003-hyperframes-poc/verify-poc.mjs
POC_OUT=<같은 출력 폴더> node --test docs/qa/20261003-hyperframes-poc/checks.test.mjs
```

`verify-poc.mjs`는 아래 순서로 검증한다.

1. 템플릿마다 2회 렌더하고 디코드 프레임 해시(framemd5)를 비교한다.
2. 안전영역 오버레이판을 렌더한다.
3. 제작실의 실제 `captionFilter`로 기본 하단 자막을 입힌 최종본을 만든다.
4. 기존 렌더러로 같은 메시지의 장면을 2회 렌더한다.

판정 규칙은 `checks.mjs`에 있다. 해상도, fps, 프레임 수, 재현 프레임 수, 자막 띠 침범, 자막 존재 중 하나라도 어긋나면 `failures`에 기록하고 **exit 1**로 끝난다.
`checks.test.mjs`는 일부러 잘못된 데이터를 넣어 검사기가 실제로 실패하는지 확인한다. 크기·fps·프레임 수 불일치, 1프레임 해시 차이, 재렌더 프레임 누락, 자막 띠 침범, 자막 누락, 그리고 서로 다른 실제 렌더 두 개를 비교하는 경우를 다룬다.

- **회귀 테스트:** `checks.test.mjs`의 7개 테스트가 모두 통과했다. 실제 렌더 비교에서도 `chapter`와 `chapter-safe`의 0/105 동일을 실패로 판정했다.
- **한글:** 나눔고딕을 `@font-face`로 프로젝트에 포함했다. 미리보기 시트에서 제목·라벨·숫자·자막이 대체 글꼴 없이 표시되는 것을 확인했다(`evidence/*.png`).
  다만 HyperFrames 쪽 글꼴 적용 여부를 자동으로 판정하는 검사는 아직 없다.
- **대비(WCAG):** 잉크 대 바탕 10.05:1. countup 숫자색 3.55:1·3.29:1, chapter 강조색은 #c95d47로 바꿔 3.55:1이다. 모두 대형 텍스트 기준 3:1 이상이다.
  처음 쓴 강조색 #e57962는 2.52:1이라 기준 미달이었고 이번에 교체했다.
- **렌더 시간:** 기존 렌더러보다 약 1.5~2.3배 느리다. 그래도 5초 장면 하나가 10초 이내에 끝난다.
  단색 위주 화면은 HyperFrames가 프레임을 빈 화면으로 오인해 워커를 1개로 줄이는 경고가 난다(`drawElement blank-frame suspect`). 렌더 결과에는 영향이 없었다.
- **재현성의 범위:** 같은 머신, 같은 Chrome(headless-shell 148), 같은 입력에서만 확인했다. 머신이나 Chrome 버전이 바뀌어도 같은 결과가 나오는지는 확인하지 않았다.
  HyperFrames는 이를 위해 Docker 모드를 권장하는데, 이 머신에는 Docker가 없다.

### 콘텐츠 이해도 평가 — 미평가 (별도 과제)

위 결과는 **템플릿이 의도대로 렌더되는지**에 대한 검증이다. 시청자의 이해도가 좋아지는지는 증명하지 않는다.

- `summary`는 아이콘 세 개를 순서대로 나열한 화면이다. 구조 이해도가 기존 방식보다 높다는 근거는 없다.
- 기존 렌더러 대비 가독성은 같은 프레임을 눈으로 비교한 의견일 뿐이다(`evidence/final-caption-vs-baseline.png`).
  수치 비교에서 막대 길이 비율이 값과 같고 차이가 명시된다는 점, 글자가 더 크다는 점은 확인할 수 있다. 그러나 시청 반응이나 이해도는 측정하지 않았다.
- 실제 영상 한 편에 넣었을 때 내레이션 타이밍과 맞는지, 장면 전환이 자연스러운지도 확인하지 않았다.
