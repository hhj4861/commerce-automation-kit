# Hanmadi 콘텐츠 준비 → 학습 운영 E2E 감사 — 2026-10-17

## 결론과 다음 순서

운영 화면에서 검색·기존 원본 조회·자막 연결 사전 안내는 동작했다. 그러나 확인한 음악 원본은 원문이 없어 자료 생성으로 넘어가지 못했다. 검색 결과에도 자동으로 가져올 수 있는 자막 경로가 없었다. 따라서 **실제 음악을 수집해 검수 후 학습 앱에서 공부하는 전체 운영 흐름의 성공은 아직 확인하지 못했다.**

우선 원문 확보 경로를 수집 단계에서 확정하고, 원문 준비 상태로 후보를 구분해야 한다. 그다음 선택한 원본을 유지하는 메뉴 이동과 남아 있는 자동 분석 안내를 정리한다. 이번 작업은 감사·문서화이며 코드·운영 설정·게시 자료를 변경하지 않았다.

- 기존 로그인된 Chrome 관리자 화면에서 탐색했다. 기존 일본어 음악 원본 1건의 상세를 조회하고 검색 1회를 실행했다. 검색어는 `back number ヒロイン`이며 화면에 결과 5개가 표시됐다.
- 첫 검색 결과를 준비 목록에 선택했다가 해제했다. 공통 원본 수집·원문 저장·업로드·AI/JEV 호출·게시·삭제·학습 진도 변경은 실행하지 않았다.
- 조회 당시 현황: 초안 2, 게시 0, 번역 후보 0. 기존 음악 원본은 원문 버전 0, 처리 이력 없음이었다.

## 실제 운영 흐름의 확인 범위

| 경계 | 결과 | 근거 |
|---|---|---|
| 관리자 화면 접근 | 확인 | 기존 로그인 세션으로 콘텐츠 준비 메뉴 표시 |
| 검색 → 결과 표시 | 확인 | 검색 1회로 5개 결과와 제목·채널·원문 준비 안내 표시 |
| 기존 원본 조회 → 상세 표시 | 확인 | 기존 일본어 음악 원본·원문 버전 0·작업 없음 표시 |
| 자막 미연결 → 실행 차단 | 확인 | `YouTube 직접 가져오기 사용 불가`, 자막 확인 버튼 비활성 |
| 원문 확보 → 정리 | 막힘 | 선택 원본에 원문이 없고 자동 가져오기 연결도 없음; 파일 등록은 이번 감사에서 실행하지 않음 |
| 정리 → 음악 자료 만들기 | 진입 불가 | 최신 원문 정리가 필요하다는 안내와 비활성 버튼 |
| 생성·검수·게시 → 학습 앱 | 이번 운영 감사에서 미실행 | 앞 경계가 막혀 정상 성공을 주장하지 않음 |

회화·음악 공통 준비 화면을 점검했으며 실제 검색과 원본 상세 재현은 일본어 음악 기준이다. 네 언어 전체의 실제 원문 공급이나 학습 진도 저장을 이번 운영 감사에서 검증한 것으로 확대하지 않는다.

## 개선점

### 1. 우선: 수집 전에 실제 원문 확보 경로를 확정해야 한다

**재현:** 기존 `back number - 히로인(ヒロイン) [가사/발음/해석]` 원본에서 원문 버전 0과 자막 가져오기 비활성을 확인했다. 이후 검색한 5개 영상 모두 `자막 파일 준비 필요 · 자동 가져오기 불가`로 표시됐다. 검색·메타데이터 수집이 가능해도 곧바로 음악 학습 자료를 만들 수 있는 것은 아니다.

**영향:** 이전의 실패 요청은 사전 안내로 바뀌었지만, 사용자가 원한 ‘영상 찾기에서 시작해 학습 자료로 연결’하는 핵심 준비 단계는 여전히 외부 원문 확보에 의존한다. 이는 서버 장애나 모든 영상의 자막 부재를 뜻하지 않는다. 이번 환경에 사용할 자동 공급 경로가 연결되지 않았고 이 원본에 원문이 없다는 관찰이다.

**제안:** 검색 후보와 공통 원본에 `원문 준비 완료 / 직접 가져오기 조건 확인 필요 / 파일 필요`를 구분한다. 수집 전에 사용할 경로(권한 있는 채널 연결 또는 이용 근거가 있는 파일)를 선택하고, 확보 대기는 별도 작업으로 남긴다. 실제 확보·정리된 원본만 ‘학습 자료 만들기 가능’으로 필터링한다. 단순 공개 CC 표시만으로 다운로드 가능하다고 판단하지 않는다.

**인수 조건:** 권한 있는 실제 자료 1건으로 원문 확보 → 정리 → 음악 초안 → 검수 → 게시 → 학습 앱 표시까지 확인한다. 미확보 후보는 준비 가능 후보로 표시되지 않고, 대기 이유와 다음 행동이 한 곳에 보인다.

### 2. 다음: 다른 메뉴에 다녀오면 선택한 원본 상세가 풀린다

**재현:** 기존 음악 원본 상세를 연 상태에서 `영상 찾기`로 이동했다. 검색 결과를 선택·해제한 뒤 `원문·작업`으로 돌아오자 원본 목록은 남았지만 선택이 해제됐고 `선택한 원문을 이곳에서 관리해요`가 표시됐다. 원본을 다시 찾아 선택해야 했다.

**영향:** 검색과 원문 준비를 오가는 반복 작업에서 맥락이 끊긴다. 소스 코드에서도 `MediaAdmin`의 선택 ID가 컴포넌트 내부 상태임을 확인했다. 편집 중 미저장 입력까지 사라지는지는 이번 운영 화면에서 재현하지 못했으므로 확정 결함으로 분류하지 않는다.

**제안:** 선택한 원본 ID를 상위 상태나 URL에 보관하고, 준비·검수 이동도 동일한 원본으로 돌아오도록 연결한다. 미저장 입력 유지 또는 이탈 확인은 별도 회귀 시험을 추가한다.

**인수 조건:** 원본 A 선택 → 영상 찾기 → 원문·작업 복귀 시 A 상세가 그대로 열린다. 초안 입력 후 메뉴 이동의 보존/경고 동작도 별도로 검증한다.

### 3. 함께 정리: ‘3개씩 분석’ 안내와 실제 수집 동작이 모순된다

**재현:** 운영 검색 결과의 전체 선택 영역에 `페이지를 넘겨 최대 10개까지 담아요. 한 번에 3개씩 분석해요.`가 표시됐다. 같은 화면은 수집이 영상 정보만 저장하며 자막·AI 생성·평가·게시를 자동 실행하지 않는다고 안내한다.

**영향:** 선택하거나 수집하면 바로 분석된다고 오해하기 쉽다. 현재 통일된 준비 → 검수 흐름과 이전 안내가 섞여 있다.

**제안:** 준비 목록 최대 10개 선택·영상 정보 저장만 설명하고, 분석은 원문 준비 후 검수·반영 단계에서 시작한다고 안내한다. 관련 소스는 `apps/hanmadi/components/youtube-video-search.tsx`의 전체 선택 안내다.

**인수 조건:** 선택·수집 버튼 주변에서 분석 자동 실행을 암시하는 문구가 사라지고, 실제 요청·다음 단계와 안내가 일치한다.

## 기존 자동 E2E와 이번 감사의 차이

[배포 검증 기록](20261017-hanmadi-caption-preflight-production.md)과 [기능 검증 기록](20261016-hanmadi-caption-preflight.md)에 단위 290개, lint·타입·build, 원문/음악 fixture E2E 및 CI 결과가 있다. 관리자 런타임이 일치하는 기존 증거이며 이번 감사에서 해당 전체 검사를 재실행한 것은 아니다.

기존 fixture E2E는 파일 등록·원문 정리·오류 복구·검수·게시·학습 흐름을 시험한다. 실제 외부 자막 공급의 성공이나 임의 공개 곡의 확보 가능성을 입증하지 않는다. 이번에는 실제 운영 자료·검색 결과를 이용해 그 간극을 확인했다.

## 제한과 종료 상태

- 브라우저 연결 지연 후 복구했으나 마지막 상세 재선택 시 연결이 사용 불가 상태가 됐다. 미저장 입력 이탈 시험은 시작하지 못했다. 도구 연결 실패를 제품 결함으로 세지 않는다.
- 이번 감사의 운영 스크린샷을 파일로 보관했다고 주장하지 않는다. UI 근거는 직접 읽은 접근성 트리와 화면 문구다.
- 전체 운영 런타임 로그·드레인은 조회하지 않았다. 이 문서는 화면에 관찰된 증상과 관련 코드 확인의 범위를 구분한다.
- 새로운 학습 콘텐츠를 게시하지 않았으며, 실제 앱 학습 성공은 미검증으로 남긴다. 개선안은 제안이고 운영 반영본이 아니다.
