# Studio 전체 메뉴 UI/UX 개선

- 목표: 홈 → 제작 방식 → 작업 이어하기 → 검수의 다음 행동을 명확하게 하고 모든 메뉴의 접근·가독성을 통일한다.
- 담당: 현재 Codex 단독. worker/Claude OFF. 범위는 public UI, 관련 검증 fixture와 테스트. 생성 엔진·계정 자격·업로드 게이트는 변경하지 않는다.
- 기준: origin/main 8439de3, 구현 worktree studio-workspace-ux / feat/studio-workspace-ux.
- 완료 조건: 운영 메뉴 감사, 격리 로컬 브라우저의 desktop/mobile 전체 메뉴 이동, 실패/완성 상태 분리, 관련 회귀 테스트, 본인 변경 커밋·push·PR. 운영 적용은 PR 명시 승인 후 별도 수행.

## 운영 확인

홈, 자동/수동 제작 관리, 기획, 콘텐츠, 트렌드, 블로그, 성과, 제휴 링크, 알림함, 설정, 게시 문구 추천을 실제 브라우저에서 읽었다. 운영 자료는 읽기 전용으로 확인했으며 신규 과금 생성/발행/삭제하지 않았다.

- 완성본도 ‘업로드 단계 / 이어서 만들기’라 검수할 결과가 있는지 구분 어려움.
- 성과는 기존 쇼핑쇼츠 jobs만 집계하여 Studio 작업이 빠짐.
- 설정의 운영 서버 ‘정상’은 하드코딩이고 실제 제작 워커는 오프라인.
- 기획 페이지 상단 AI 버튼은 필요한 onboarding DOM이 없어 ‘AI 확인 중…’에서 멈춤.
- 편집기 로고는 링크가 아니고 알림함 메뉴 누락. 모바일에서 성과/설정 누락.
- 게시 문구 추천은 다른 페이지와 별도 메뉴 구조.
- 10~12px 설명/버튼, 긴 제목과 약한 다음 행동, 큰 제작 현황 영역으로 이어하기 가시성 저하.

## 디자인 계획과 검토

색: canvas #f4f6f8, surface #ffffff, ink/sidebar #202c35, muted #596772, success #216b57, 기존 브랜드 coral #ff6b4a 유지. Noto Sans KR/DM Sans 기존 서체 유지, 본문 14~15px, 보조 최소 12~13px, 제목 25~30px. 콘텐츠는 좌측 정렬. ‘창작물을 찾고 다음 제작 행동을 한다’는 목적에 맞춰 콘텐츠 목록을 중심에 둔다.

배치: `공통 메뉴 | 페이지 제목 → 필요한 필터 → 작업 행 [대상 / 상태 / 다음 행동]`. 자동·수동 현황은 압축한다. 모바일은 가로로 숨은 메뉴 대신 펼치는 전체 메뉴. 카드·통계 장식을 늘리는 초안 대신 목록·실제 상태·행동을 강조하도록 조정했다. 모션은 사용자 상호작용에만, reduced motion 유지.

## 구현·검증

로컬 구현과 브라우저 검증을 수행했다. 로컬 fixture는 인메모리 테스트 데이터만 사용하고 외부 생성/발행을 실행하지 않는다. 이전 실생성의 CODEX_TIMEOUT 수정 PR #201/#202 머지 및 운영 작업 상태 조회는 별도 승인 대기다.


### 브라우저 결과

- 데스크톱과 모바일(390×844)에서 10개 메뉴 이동, 제작실 자동/수동 전환, 신규 기획과 기존 프로젝트 편집 복원 확인. 모바일 가로 넘침 없음.
- 콘텐츠 7개 fixture에서 제목 검색 → 새로고침 유지 → 필터 초기화 → 실패 작업 필터, 완성 영상 검수 CTA를 확인했다.
- 성과는 Studio·기존 jobs·초안 요청을 합쳐 7개 집계. 설정은 제작 서버 오프라인과 AI 계정 연결 모달을 정확히 표시했다. 실제 계정 연결은 실행하지 않았다.
- 제작실 조회 503을 주입하면 나머지 2개를 유지하고 ‘일부 콘텐츠 조회 실패’, 조회된 기준이라는 설명과 재시도 버튼을 표시했다.
- 게시 문구 추천에도 공통 메뉴를 제공한다. 블로그·제휴 링크·트렌드·알림함의 빈 상태, 입력 라벨과 다음 행동을 확인했다.
- 편집기 음성 생성/최종 합성/업로드는 실행하지 않았다. 실제 자동 생성 E2E와 UI fixture 검증을 혼동하지 않는다.

현재 적용 범위: 작업 브랜치. 운영 미반영. PR 머지 승인 후 배포와 운영 화면 확인 필요.

회귀 검사: 43개 중 기존 완성본 상태 문구 기대값 1건이 새 UX와 달라 수정했다. 기능 실패를 숨기지 않고 기존 분기·링크 검증은 유지했다. 전체 재실행 결과는 PR에 기록한다.
