# Hanmadi 음성 시작 지연·학습 품질 수정

2026-10-01. 기준 브랜치 `origin/main`의 `63e8dff`에서 독립 worktree `fix/hanmadi-voice-learning-quality`로 구현했다. 운영 E2E에서 발견한 오류를 수정하는 변경이며, PR 머지와 운영 배포는 별도 승인 단계다.

## 변경한 동작

- 일본어 발음 104곳: 한국어 단어 혼입, 빠진 음절, 잘못 읽은 단어를 수정했다. 예: 韓国から → 캉코쿠카라, ここで → 코코데, 週末 → 슈우마츠, 市場 → 이치바. 원문·한국어 뜻·나머지 언어 필드는 바꾸지 않았다.
- 한국어 입력을 외국어로 바꾸는 `learnerTurn`에서 관찰된 ‘얼음 없는 커피’ 오류를 검사한다. 커피/얼음 제외/명시된 한 잔을 보존하고, 요청하지 않은 단맛·온도 조건을 추가하면 같은 선택 모델로 한 번 재생성한다. 계속 실패하면 변환문을 표시·저장하지 않는다. 정상 AI 상대 답변은 유지한다.
- 일본어 乾杯의 `칸바이`, 스페인어 Algo más의 `알골 마스` 등 확인된 동적 발음 오류를 거부하고 재생성한다. 임의의 모든 문장을 검증하는 범용 번역/발음 판정기는 아니다.
- 카페 역할과 이미 정한 조건을 유지하도록 프롬프트를 강화했다. 관찰된 영어의 iced 확정 후 hot/iced 재질문, 일본어의 no-ice 재확인, 스페인어 점원이 손님 주문을 그대로 말하는 응답을 제한적으로 검출한다.
- 음성 서버가 공급자 오디오 조각을 바로 전달한다. 브라우저는 MP3 MediaSource 지원 시 전체 다운로드 전에 재생을 시작한다. 지원하지 않거나 MSE 초기화/버퍼 추가가 실패한 경우 같은 요청의 완성 파일을 사용하며 TTS를 다시 호출하지 않는다.
- 기존 탭 내 메모리 캐시와 요청 합치기, 로그아웃 시 캐시 삭제, 들은 적 없는 문장 최대 2개 미리 받기 제한을 유지한다. 이미 진행 중인 미리 받기에 재생이 합류해도 앞부분 조각을 놓치지 않는다.
- 서버 공용 캐시는 코드에 포함된 공개 수업 원문과 언어가 정확히 일치할 때만 적용한다. 모델/서버/목소리/언어/문장을 키로 구분한다. 최대 12MB/160개/1시간, 완료된 응답만 저장한다. 개인 대화·번역·관리자 추가 문장을 공유 캐시에 적재하지 않는다. HTTP 응답은 계속 `no-store`이고 인증·Origin 검사·사용량 제한도 유지한다.
- 캐시는 프로세스 메모리이므로 재시작·스케일아웃 시 비어 있을 수 있다. 전 문장 음성 사전 생성이나 영구 CDN 저장을 구현했다고 주장하지 않는다.
- 음성 응답은 5MB 상한과 타임아웃/취소 처리를 유지한다. 중간 실패는 표시하고 불완전한 응답은 캐시하지 않는다. 다른 문장 재생/화면 종료 시 이전 재생을 중단한다.
- 여행 번역 음성은 보통 속도(1.0배), 스터디·AI 대화는 기존 학습 속도(0.85배)로 재생한다.

## 검증

- 전체 단위 테스트: **119개 통과**. 새 의미/발음/대화 회귀, 스트리밍 조각 전달, 프리페치 합류, 캐시 상한·TTL·모델 분리, 개인 음성 비공유, 중간 실패·초과 크기·취소 포함.
- TypeScript: Next 라우트 타입 생성 후 검사 통과.
- 변경 TS/TSX 린트: 오류·경고 없이 통과.
- 프로덕션 빌드: 통과.
- 한마디 전체 UI E2E: 네 언어 1,280문장, 8상황/4레벨/10문장, 양방향 번역, AI 대화, 사용자 말 학습 저장·재조회·삭제, 로그인/계정 연결, 음성 재생, 모바일 레이아웃 회귀 통과. 외부 AI/STT/TTS는 fixture를 사용한다.
- 추가 통합 E2E: 인증된 수업 음성 API의 서버 캐시 적중과 TTS 추가 호출 0건, 태국어 의미 재생성 실패 시 learnerPhrase=null/learning=unavailable/저장 개수 불변을 확인했다. 두 E2E 실행 모두 서버 종료·격리 데이터 삭제까지 확인했다.
- 실제 MP3 브라우저 테스트: 전체 다운로드 전 재생, 클라이언트 캐시, 서버 공개 캐시, MSE 미지원 대체 경로, 스트림 실패 후 재시도, 취소 통과. Chrome이 실제로 오디오를 디코딩하고 currentTime이 진행하는 것을 확인했다.

### 스트리밍 측정 — 로컬 지연 fixture, 운영 실측 아님

동일한 원본 합성 MP3를 250ms 후 첫 조각, 이후 200ms 간격으로 제공했다.

| 항목 | 측정 |
|---|---:|
| 전체 파일 수신 | 2.467초 |
| 스트리밍 재생 시작 | 0.533초 |
| 탭 내 반복 재생 | 0.017초 |
| 클라이언트 캐시 삭제 후 공개 수업 서버 캐시 | 0.019초 |
| MSE 미지원 대체 재생 | 전체 수신 후 재생 시작 |
| 브라우저 JavaScript 오류 | 0건 |

공급자가 첫 오디오 바이트를 늦게 주면 그 지연은 남는다. 실제 운영에서 기존 2~4초가 위 수치로 단축됐다고 주장하지 않는다. 배포 후 운영 첫 재생/반복/다음 문장, 모바일 Safari와 Chrome을 다시 측정해야 한다. 이번 환경에는 기존 프로젝트의 `.env`가 이전되지 않아 수정 프롬프트의 신규 실공급자 호출은 수행하지 않았다.

[MDN SourceBuffer.appendBuffer](https://developer.mozilla.org/en-US/docs/Web/API/SourceBuffer/appendBuffer)의 지원 범위·비동기 updateend/error 처리와 설치된 Next의 Route Handler 스트리밍 문서를 확인했다. 실제 Safari 실기기 청음과 언어 전문가 전수 검수는 별도이며, 이번 결과를 모든 발음·대화 의미의 완전성으로 해석하지 않는다.

## 재현 및 산출물

앱 디렉토리 `apps/hanmadi`에서 실행한다.

```sh
npm test
node node_modules/next/dist/bin/next typegen
node node_modules/typescript/bin/tsc --noEmit --incremental false
npm run build
# 아래 경로는 사용자 지정 iCloud 산출물 하위 폴더로 지정
HANMADI_VOICE_QA_DIR='<산출물 경로>' npm run test:voice
HANMADI_E2E_DATA_FILE='<새 테스트 데이터 파일>' HANMADI_E2E_SCREENSHOTS='<캡처 경로>' npm run test:v2
```
