# Hanmadi 콘텐츠 준비 → 검수·반영 → 학습 운영 — 2026-10-16

## 사용자 결과와 범위

이전 관리자 UI는 메뉴를 세 영역으로 묶었지만 음악 수집·원문 등록·생성·게시가 학습 운영에 남아 있었다. 이번 변경은 회화·음악 모두 같은 콘텐츠 준비함을 시작점으로 삼고, 검수·반영에서 초안 생성·사람 검수·게시를 수행하며, 운영에서는 앱에 게시된 자료와 반영 상태를 관리한다.

구현 브랜치: `feat/hanmadi-unified-content-flow`, 기준 `origin/main`의 `2e6999c`. 담당은 이 Codex 세션이다. 새 PR의 머지·운영 배포는 아직 수행하지 않는다.

## 단계별 계약

| 단계 | 하는 일 | 다음 단계 |
|---|---|---|
| 콘텐츠 준비 | 공통 YouTube 검색 또는 주소 입력, 원문 언어와 회화/음악/양쪽 용도 지정, 원문·사용권 보관, 공식 자막 권한 확인/가져오기, 파일 연결·시간 정리 | 같은 영상과 원문 snapshot을 검수로 전달 |
| 검수·반영 | 영상 분석 또는 보관한 원문으로 회화 자료 생성, 음악 초안과 구간 생성·JEV 평가, 사람 검수 후 게시 | 앱에 공개된 수업·곡 |
| 학습 운영 | 게시 수업·음악, 앱 반영 확인, 원문 수정/미게시 자료는 해당 앞 단계로 이동 | 게시 내리기 후 다시 검수 |

- 공통 준비함 저장만으로 AI 호출·게시가 실행되지 않는다. 새 음악 수집 검색은 별도 운영 메뉴가 아니라 공통 YouTube 검색을 쓴다.
- 한 영상은 준비함에 하나만 저장하고 용도를 추가할 수 있다. 기존 제목·원문 버전·이력은 덮어쓰지 않는다. 이미 다른 원문 언어로 등록된 영상은 409로 명확히 알린다.
- 원문·음악의 자료 복제는 자동 게시가 아니다. 준비한 원문을 읽기 전용으로 전달하고 음악 초안 준비 및 AI 처리 권한을 다시 확인한다. 기존 음악/회화 저장소와 검수·게시 API 계약은 유지한다.
- 음악은 최신 원문 정리 완료 후 넘어간다. 회화는 영상 정보만 준비해 분석하거나, 정리된 원문을 사용할 수 있다. 생성 실패·JEV 재시도·제외 구간의 게시 금지는 기존 계약을 따른다.
- 예전 음악 수집함과 캡션을 보존하고 콘텐츠 준비에서 연결한다. 자막 파일/수정본은 사용권 확인 후 공통 원문 버전으로 보관한다. 공식 자막을 미리 가져온 것만으로 공통 원문 버전이 저장되지는 않는다.
- 공식 자막 접근 제한을 우회하거나 타인 음원/가사를 다운로드하는 기능은 추가하지 않는다.

## 검증 현황

- 단위 테스트 290개 통과. 원문 용도 추가가 저장된 원문/이력을 바꾸지 않고, 다른 원문 언어는 거부함을 검증했다.
- 전체 TypeScript와 변경 lint 통과.
- `media-foundation-e2e`: 네 언어 원문 저장·정리·실패·복구·재접속·충돌·삭제, 세 업무 영역과 도구 이동, 320/390/1440px 및 대표 200% 배치 통과.
- `owned-music-e2e`: 공통 원문 파일/시간 편집 → 음악 검수, JEV 실패 후 생성 반복 없이 평가 재시도, 사람 검수/제외 구간 게시 차단, 게시/게시 내리기, 네 언어 기존 음원 재생·진도·저장 회귀 통과. 로컬 공급자 생성 1회·평가 2회이며 실제 유료 호출이 아니다.
- `music-collection-e2e`: 공통 검색에서 양쪽 용도로 1개 원본 저장, 공식 자막 403 후 성공·동의 전 미저장, 기존 캡션 캐시 재사용, 원문 버전 전달 → 음악 생성·JEV·사람 게시 → 네 언어 실제 학습 화면·복습·저장·진도·게시 내리기 통과. 검색 2회·자막 다운로드 1회, HTTP/player/LLM/JEV fixture.
- 전체 V2 회화/학습 E2E도 통과했다(영상 공통 수집→일괄 분석/재시도→초안 검수, 원문 준비→회화 생성/게시→학습, 번역 동의/회수, 기존 검색·모델 적용 회귀 포함). 이후 분류만 최종 조정해 번역 후보를 준비, 검색·모델 신규 적용 도구를 검수에 옮기고 기존 수집함은 원문 화면의 보조 행동으로 남겼다. 최종 명칭·영역 이동은 `media-reviewed/`에서 재검증했고 production build도 통과했다. 회화 검수·음악 검수·검색/모델 적용은 검수 영역, 번역 후보는 준비 영역, 기존 음악 수집함은 원문 화면의 보조 행동이다.

실제 Next 라우트·권한·로컬 파일 저장소·브라우저를 사용했다. 공급자 응답만 fixture이며 운영 쓰기·유료 호출·운영 설정 변경은 하지 않았다. 게시된 음악이 실제 학습 화면에 나타나는 연결 검증과 공급자 결과의 실제 품질 평가는 구분한다.

## 실패와 보완

- 기존 의존성 폴더 심볼릭 링크는 Turbopack의 프로젝트 root 제한으로 거부됐다. 본인 링크만 제거하고 lockfile 정상 설치로 해결했다. 타 세션 의존성은 변경하지 않았다.
- 전용 Playwright 브라우저 캐시가 없어 설치된 Chrome의 격리 headless 프로필을 사용했다.
- 첫 타입 생성은 cwd를 루트로 잡아 실패했다. 앱 cwd에서 route type 생성 후 검사했다. 파일 연결 핸들러의 JSX 오류는 별도 함수로 정리한 뒤 검증했다.
- 공통 자막 적용 뒤 원문 입력 라벨이 값에 영향을 받는 문제가 있어 명시적 접근성 이름을 부여했다.
- 기존 음악 전용 검색 fixture의 category/embeddable 기대값과 빈 캡션 선택자, 중복 다운로드 기대값은 공통 검색·캡션 캐시 재사용이라는 새 실행 상태에 맞춰 변경했다. 기존 권한/실패/게시/학습 단언은 유지했다.

산출물은 지정 iCloud 작업 폴더 `commerce-automation-kit/20261016-unified-content-flow/`에 보관한다. 증거는 `unit.log`, `media-reviewed/`, `owned-1/`, `collection-5/`, `v2-1/test.log`다. 앞선 실패 실행 폴더를 통과 증거로 표시하지 않는다.
