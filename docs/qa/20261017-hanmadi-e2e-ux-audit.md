로컬 서버 로그에서 Error/TypeError/ReferenceError/HTTP 500 패턴을 발견하지 않았다. 운영 브라우저의 관측 구간 error/warn 로그도 비어 있었다. 이것이 모든 운영 요청의 오류 부재를 보장하지는 않는다.

추가로, 선택한 ‘낯선 길을 찾을 때’ 단어 묶음은 보관함 왕복과 음악 왕복 후 유지됐다. 단어 묶음 상태가 사라지는 문제로 기록하지 않는다.

## 추가 관찰과 미검증 범위

- 오래 열려 있던 운영 탭에서는 커피 장식 이미지가 보이지 않았지만 새로고침 후 정상 표시됐다. 공개 PNG는 HTTP 200, 1,165,396 bytes이며 로컬 원본과 바이트가 동일했다(SHA-256 `94f9e528f2b88504f28ba74979023a8b92aededa20f760a94ff72834bff8326b`). 캐시·업데이트 시점·렌더링 중 무엇이 원인인지는 확정하지 않았다. 배포 후 기존 탭을 유지한 상태의 자산 갱신 시험을 추가할 가치가 있다.
- 점검 도중 Chrome 연결이 끊겨 재연결한 동일 검증 탭을 이어 사용했다. 320px 선택창 추가 수동 검사는 도구 dispatch 지연으로 끝까지 확인하지 않았으며 앱 장애로 분류하지 않는다. 기존 자동 390px 선택창 검증은 통과했다.
- 실제 Google 계정 재로그인, 운영 유료 AI·음성 공급자, 실제 스마트폰 소프트 키보드, 네이티브 앱 실기기는 이번 E2E에서 검증하지 않았다. 첫 레이어의 장애를 우회하거나 실제 공급자 성공으로 fixture 결과를 대신하지 않았다.
- 운영에서는 화면 탐색·임시 선택만 수행했다. 계정 설정·저장 자료·학습 완료 상태는 수정하지 않았고, 종료 시 회화 화면 및 viewport를 복원했다.
