# 제작 방식별 작업 관리와 이어하기

## 화면 역할과 사용자 흐름

- 홈: 새 영상 시작, 계정 연결 안내, 최근 작업 바로가기, 탐색 도구. 승인·검수 큐는 홈에 표시하지 않는다.
- `/studio`: 자동·수동 제작 선택. 각 선택은 해당 제작 대시보드로 들어간다.
- `/studio/automatic`: 자동 제작 관리. 새 초안 요청, 현황, 제작 단계별 큐, 대본 승인·후반 작업·발행 검수 상세를 한 화면에 둔다.
- `/studio?mode=manual`: 수동 제작 관리. 새 기획, 진행/생성/확인 필요/업로드 완료 현황, 제목·카테고리 검색, 영상 형식과 제작 단계 필터, 저장 작업 목록.
- `/studio?new=1`: 새 수동 기획. `/studio?id=...`: 기존 작업의 저장 상태에 맞는 편집 단계.
- `/contents`: 자동·수동 전체 목록. 홈과 콘텐츠의 바로가기도 동일한 대시보드 상세 또는 편집 단계로 연결된다.
- 이어하기는 독립 메뉴나 추가 단계가 아니다. 자동 작업은 승인·검수할 상세를 열고, 수동 작업은 `resumeStep`이 가리키는 시나리오/미디어/편집/업로드 단계로 바로 연결한다.
- 기존 `/?job=...`, `/?request=...`, `/studio?mode=auto` 링크도 자동 제작 화면으로 연결한다.

## 디자인

기존 Shopshorts의 DM Sans/Noto Sans KR, 바탕 #f7f7f4, 본문 #242622, 보조 #73776f, 경계 #e5e6df, 강조 #ff6b4a, 진행 #277e64를 유지한다. 제목 26–30px, 본문 13–15px, 왼쪽 정렬. 현황 버튼은 실제 필터이며 장식용 통계를 추가하지 않는다. 작업 목록의 제목·현재 단계·다음 동작을 우선한다. 모바일은 현황 2열, 입력/목록은 폭에 맞춰 줄바꿈한다.

```text
홈 → 영상 제작실 → 자동 제작 관리 → 새 요청 / 진행 작업 승인·검수
                 → 수동 제작 관리 → 새 기획 / 저장한 편집 단계
홈 최근 작업 ─────────────────────→ 같은 작업
전체 콘텐츠 ──────────────────────→ 같은 작업
```

기존 제작 관리 화면의 사람 승인·실제 발행 전 확인 절차는 유지한다. 계정 연결 모듈은 수정하지 않으며, 홈과 제작 방식 선택의 안내 및 공통 상단 버튼을 사용한다.

## 데이터와 오류 처리

자동 큐는 기존 jobs/requests API와 승인 동작을 재사용한다. 같은 slug의 요청이 실제 작업으로 바뀌면 중복 표시하지 않고 해당 작업을 연다. 대기 요청을 선택했을 때 다른 작업 상세가 남는 현상을 제거한다. 작업/대기 목록 실패는 마지막 조회 상태와 함께 명시한다.

수동 대시보드는 `/api/studio`만 조회하므로 자동 큐 장애에 영향을 받지 않는다. 업로드 완료와 렌더 완료는 별개이며, 실패/진행 중 작업도 기존 편집기와 같은 복귀 단계를 사용한다. 갱신 실패 시 마지막 목록을 보존하고, 최초 조회 실패를 '작업 없음'으로 표시하지 않는다. 갱신 후에도 선택한 필터를 유지한다.

Cloudflare rewrite와 로컬 서버 모두 자동 대시보드를 제공한다. 로컬 서버에서 새 브라우저 모듈이 누락되지 않도록 public의 JS/CSS/폰트를 기존 로그인 보호 뒤에서 제공한다.

## 검증

- 격리된 메모리 fixture에서 실제 Chrome 클릭으로 홈 → 제작 방식 선택 → 자동 대시보드, 자동 초안 요청 → 같은 큐에 대기 요청 추가를 확인했다.
- 수동 대시보드의 진행/완료 필터, 기존 프로젝트의 시나리오 단계 복원, 새 수동 기획 저장을 확인했다. HTTP 조회로 새 기획과 자동 요청의 저장을 확인했다.
- 수동 목록 HTTP 503 상태가 화면에 표시되고 복구 후 자동 갱신으로 새 프로젝트까지 다시 표시됨을 확인했다.
- 자동·수동 데스크톱 및 390px 수동 대시보드 스크린샷을 검토했다. 모바일 자동 화면은 브라우저 연결 중단으로 확인하지 못했다. 검증용 탭과 서버는 종료했다.
- 콘텐츠 분류·대시보드·기존 링크·요청→작업 전환·오류 복구 관련 18개 테스트 통과. 로컬 HTTP 경로/정적 모듈 제공 검사 통과. JS 구문 및 diff 검사 통과.
- 전체 회귀 272개 중 271개 통과, 로컬 영상 승인 API 검사 1개 시간 초과. 순차 실행에서는 269개 통과, API 1개와 렌더 2개 시간 초과. 판정 실패는 없었으며 시간 제한을 늘리지 않았다.
- 같은 기준 커밋(83e7413)의 API 검사와 변경 브랜치 단독 재실행 모두 통과했다(각 20.1초/17.5초). 전체 회귀를 한 번에 통과한 결과로 보고하지 않는다.
- 시간 초과했던 렌더 2개도 원래 제한 시간 그대로 단독 재검증에서 모두 통과했다(27.8초/15.9초).
- 운영 데이터, 실제 OAuth, 유료 생성·발행을 사용하지 않았다.

## 다른 세션과의 통합 계약

`개선해 쇼츠 영상 생성기` 세션의 `/private/tmp/cak-automatic-category-workflow/docs/qa/automatic-category-workflow.md`에서 다음 계약을 확인하고 메시지로 회신했다.

- 자동 진입은 `/studio/automatic`, 별도 자동 제작 LNB 메뉴를 추가하지 않는다.
- 새 모듈 `mountAutomaticCreation(host,{fetcher,connect})`는 `{ready,refresh,destroy}`를 반환한다.
- 새 자동 프로젝트는 `project.automation.version === 1`, 수동 프로젝트는 automation이 없다. 수동 대시보드에서 자동 프로젝트를 제외하고 전체 콘텐츠는 자동으로 분류한다.
- 새 모듈은 `automaticView` 상단의 펼친 host에 연결한다. 기존 쇼핑 작업 큐는 하단에 유지한다. 프로젝트/추천 이어하기는 각각 `?project=...`, `?recommendation=...`이다.
- 이 PR은 기존 쇼핑 자동 요청·승인 큐를 옮기고 수동 대시보드를 구현한다. 상대 세션의 미커밋 자동 생성 엔진은 포함하지 않았다. 이 변경을 먼저 통합한 뒤 상대 세션이 index/studio/server/content-library/automatic-creation 충돌을 조정하고 새 엔진을 연결해야 한다.
