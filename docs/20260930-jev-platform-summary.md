### 리뷰에서 확인한 결함과 조치

- **위치 필드 모순**(사례 B의 최종 보류 원인): 초안 프롬프트는 "위치 미확인" 기재를 지시하는데, 검수는 근거 있는 위치를 필수로 요구했다. v2.7에서 위치 근거가 없는 lead는 생략한다. 필수 검사는 유지한다(#161).
- **native 재검수 승격**: JEV가 저신뢰 `uncertain`을 낸 사실 필드를 인용 없이 `not_applicable`로 바꾸면 통과하던 경로를 차단했다. 대상명만 인용한 경우도 근거로 인정하지 않는다(#161).
- **실패 원인 합쳐짐**: Shopshorts 화면은 JEV 장애·검수 보류·근거 부족을 구분해 표시한다. 워커 로그에는 요청 ID와 고정 코드만 남는다(#161).
- **진단과 운영 안정성**: 취소 뒤 잠금 해제, 요청별 JEV 모델 고정, `researchDiagnostics`로 사례 A의 검색 실패와 초안 실패를 구분했다(#161).
- **Hanmadi**: LLM 교차 검수로만 통과한 표현 수를 화면에 표시하고, 판정 잠금 TTL을 60초에서 120초로 늘렸다. 쓰지 않는 vendored tgz를 지우고 CI에 tgz·소스 일치 검사를 추가했다(#162).
- **Festa**: 4회 상한 경로에서도 종료 점검을 실행하고, 미해결 제약을 코드로 `unknowns`에 넣는다. shadow는 `waitUntil`로 응답 지연에서 분리했다(venture-studio#69).

## 구조·완료 조건

- 공통 판단 경로는 **앱 서버 → JEV SDK → 기존 LiteLLM → TypeSafe**다. 공용 주제 추천은 **앱/워커 → 공통 추천 서버(JS/Python 클라이언트)**가 검색·판정을 조합하고, 생성은 기존 계정 런타임이 담당한다. 추천 서버가 생겼다는 사실을 별도 범용 JEV 서버가 필요하다는 뜻으로 해석하지 않는다.
- 기능별 품질·비용을 확인하며 off → shadow → on으로 확대한다. 현재 모드·마지막 확인 시점과 실제 채택 여부를 구분한다.
- 기능별 입력·선택지·rubric·모드·시간/비용 한도·저신뢰/오류 처리·채택 기준을 명시한다. 추천 서버의 요청 ID·멱등성·계정 범위·취소 검증을 모든 신규 기능의 검증 완료로 확대하지 않는다.
- 정상 오차단·잘못된 통과·검수자 일치도·전체 성공률·p50/p95·복귀율·생성/재시도를 포함한 총비용을 비교한다. 소표본, 다른 시간 측정 경계, 구독 호출의 미확인 금액으로 ROI를 확정하지 않는다.
- 사람 승인·사용권·게시·동의·권한·확정값 계산은 유지한다. 실패를 통과로 바꾸거나 다른 키로 제한을 우회하지 않는다. 계획서 수정은 추가 유료 호출·예산 확대·배포·새 PR 머지의 실행 승인이 아니다.
