2026-10-05 현행화 | 2026-09-30의 49개 영역 계획에 최신 소스·머지·운영·평가 증적 반영

**공통 JEV 연결과 추천 v2.2 개선 코드는 머지됐다. 전체 플랫폼의 품질 검증·운영 적용은 미완료다.** 다음은 근거가 있는 문구의 불필요한 보류를 확대 검증하고, 전체 후보와 실제 앱 흐름에서 적용 여부를 결정하는 것이다.

사용자 방향은 **문맥·의미 판단에 가급적 JEV를 활용**하는 것이다. 생성 전에 방향·필요 정보를 판단하고, 생성 후에만 확인할 수 있는 오류는 필요한 단계에서 검사한다. 생성·권한·날짜·쿼터·게시 승인을 JEV로 대체하지 않는다. 아래 ‘완료’는 표시된 범위에만 적용한다.

## 다음 실행 순서와 완료 기준

1. **판단 품질:** [세 시설 21문항 확대 평가](qa/20261005-jev-location-expansion.md)까지 실행했다. 두 모델 모두 잠정 라벨과 선택이 일치했지만, JEV는 근거 있는 12개 중 4개를 보류했고 맞는 위치 연출 제안은 세 시설 모두 보류했다. 다음은 동일 필드·선택지에서 사실/제안 문구만 바꾸는 비교다. 독립 라벨 검토·상충 출처·모호한 참조·사업 사례는 남아 있다. 초기 12개와 새 21개를 독립 표본으로 합산하거나 정확도 100%로 보고하지 않는다. 임계값은 유지한다.
2. **전체 추천·운영 전환:** 준비된 원래 근거/위치 추가 근거 대조군 6개는 아직 미호출이다. 개별 필드와 전체 후보 판정을 분리하고 실제 검색→구독 생성→JEV→결과 저장을 확인한다. 동일 조건의 JEV 사용/미사용 품질·총비용 비교 후 최신 서버와 일치하는 클라이언트를 배포·검증한다. Shopshorts 로그인 경로·선택한 Codex/Claude 경로·블로그 Actions는 각각 확인한다.
3. **Hanmadi:** 새 실제 영상으로 v10 운영 API→Redis 초안 저장·별도 재조회·재진입·미게시 자료 격리를 검증한다. v9 영상 E2E와 v10 합성 사례/격리 저장을 합쳐 완료로 계산하지 않는다.
4. **Festa:** 현재 모드를 먼저 재확인하고 shadow 평가를 확대한다. 기존 LLM 대비 조기 종료·반복 질문·추가 지연·총비용을 확인한 뒤 on 여부를 결정한다.
5. **인접 업무·Replay 확대**, 이후 **모델 자동 선택**을 별도 평가한다. 입력·정답 기준이 준비되지 않은 기능은 API부터 붙이지 않는다.

## 구조·완료 조건

- 공통 판단 경로는 **앱 서버 → JEV SDK → 기존 LiteLLM → TypeSafe**다. 공용 주제 추천은 **앱/워커 → 공통 추천 서버(JS/Python 클라이언트)**가 검색·판정을 조합하고, 생성은 기존 계정 런타임이 담당한다. 추천 서버가 생겼다는 사실을 별도 범용 JEV 서버가 필요하다는 뜻으로 해석하지 않는다.
- 기능별 품질·비용을 확인하며 off → shadow → on으로 확대한다. 현재 모드·마지막 확인 시점과 실제 채택 여부를 구분한다.
- 기능별 입력·선택지·rubric·모드·시간/비용 한도·저신뢰/오류 처리·채택 기준을 명시한다. 추천 서버의 요청 ID·멱등성·계정 범위·취소 검증을 모든 신규 기능의 검증 완료로 확대하지 않는다.
- 정상 오차단·잘못된 통과·검수자 일치도·전체 성공률·p50/p95·복귀율·생성/재시도를 포함한 총비용을 비교한다. 소표본, 다른 시간 측정 경계, 구독 호출의 미확인 금액으로 ROI를 확정하지 않는다.
- 사람 승인·사용권·게시·동의·권한·확정값 계산은 유지한다. 실패를 통과로 바꾸거나 다른 키로 제한을 우회하지 않는다. 계획서 수정은 추가 유료 호출·예산 확대·배포·새 PR 머지의 실행 승인이 아니다.
