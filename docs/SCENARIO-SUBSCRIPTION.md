# 연결한 구독 계정으로 시나리오 생성

시나리오는 사이트에 로그인한 사용자가 연결한 Codex 또는 Claude 계정으로 생성한다.
제공사는 서버에 저장된 연결에서 선택하며 요청 본문의 owner/provider 값은 사용하지 않는다.
추천과 동일한 계정 실행기·공식 CLI·인증 갱신 경로를 재사용한다. 계정별로 요청 하나씩 실행한다.
이미지·영상·내레이션·렌더·업로드 경로와 사람 검수 단계는 유지한다.

## 요청과 저장

- 시나리오 요청 전에 로그인, 연결 계정, 실행기 heartbeat, 시나리오 지원 여부를 확인한다.
  실패하면 프로젝트를 대기 상태로 만들지 않는다. 구버전 실행기에는 시나리오 작업을 전달하지 않는다.
- 프로젝트 revision CAS로 예약한 뒤 같은 task ID를 계정 작업 ID로 사용한다.
  예약 뒤 통신이 끊긴 경우에도 4분의 저장된 마감 시간으로 무한 대기를 막는다.
- 계정 실행기가 창과 독립적으로 생성 결과를 암호화 저장한다. 프로젝트 조회·목록 조회 시
  해당 프로젝트와 task ID를 검증하고 결과를 CAS 저장한다. 다음 추천이나 계정 해제 전에
  미수령 결과를 별도 암호화 레코드에 보존하므로 나중에 창을 열어도 결과를 받는다.
- 원본 계정 revision으로 보존 순서를 비교한다. 늦은 취소 요청이나 다른 창의 응답이
  더 최신의 생성 결과를 덮어쓰지 않는다. 프로젝트 저장 성공 뒤 결과를 수령 확인한다.
  수령한 보존 레코드는 결과 본문 없이 revision만 남겨 오래된 쓰기를 막는다.
- 토큰은 기존 credential vault에만 암호화 저장한다. 시나리오 보존 레코드는 토큰을 포함하지 않는다.
  일반 계정 상태 응답에는 시나리오 본문을 반환하지 않는다.
- 제목, 장면, 목표 길이, 결과 크기를 검증한다. 시나리오 요청에 Gemini API 키는 사용하지 않는다.
  이전 제작 큐의 Gemini 시나리오 요청은 명확한 실패 안내 후 새 경로로 다시 요청해야 한다.

## 적용 순서

PR 머지 승인 후 동일한 통합 revision으로 다음을 적용한다.

1. credential broker 배포. 이전 추천 실행기와 호환되며 새 시나리오 기능은 실행기 지원 확인 전 거절한다.
2. 실행 중인 계정 요청이 끝난 것을 확인하고 `studio-account-worker.mjs`를 새 revision으로 교체한다.
   기존 `CAK_RUNNER_KEY_FILE`과 연결 계정을 그대로 사용한다. 구버전 워커를 중복 실행하지 않는다.
3. Pages UI/API 배포. 연결 상태의 `scenarioAvailable: true`를 확인하고 기존 실패 프로젝트에서
   시나리오 생성을 다시 요청한다. 실계정 생성, 창 닫기·다시 열기, 결과 저장을 확인한다.

## 검증

`node --test apps/shopshorts/test/*.test.mjs apps/credential-broker/test/*.test.mjs`

계정·제공사 격리, 오프라인/구버전 실행기, 요청 충돌, 취소와 늦은 결과의 경합,
창이 닫힌 뒤 결과 보존, Gemini 호출 차단, Codex 인증 갱신, Claude 연결 토큰 사용,
암호화 대용량 결과 및 기존 인증·알림·제작 흐름을 검증한다.
제공사 호출은 테스트 대역으로 검사하며 실제 구독 계정 생성은 운영 적용 후 별도로 확인한다.
Pages Functions build 및 broker deploy --dry-run은 배포하지 않고 번들 호환성만 확인한다.
