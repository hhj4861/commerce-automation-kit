적용: **다음 제작부터**. 이미 완성된 영상은 수정·재생성하지 않는다. 기본 웹툰, 사용자가 정한 음성·배속·예산을 유지한다.

## 왜 설명이 빠졌는가

5탄 `docs/videos/20261005-optical-episode-5/story.json`(제작 브랜치 `bb47c53`)은 광연결의 필요성부터 변조기·수신기·WDM·CPO까지 24개 비트로 소개했다. 숏폼은 `hook/electrical/conversion/wdm/ending` 다섯 비트를 추출했다. 각각의 소개 문장은 남았지만 하나의 데이터가 어떤 조작을 거쳐 전달되는지 구체적으로 따라갈 사례가 약해졌다. 웹툰 재제작은 기존 음성을 재사용하면서 내용 검토를 다시 하지 않았다.

수동 제작기는 웹 제작실의 대본 생성기를 통하지 않았다. 공통 생성기도 깊이에 관한 프롬프트는 있었지만, 실제 검사는 길이·형식·연출·도입/핵심/결말 인용의 존재와 순서에 집중했다. '항목이 있다'와 '시청자가 이해할 만큼 설명됐다'를 혼동한 것이 원인이다. 글자 수나 상영 시간을 늘리는 것만으로 해결되지 않는다.

## 제작 순서와 통과 조건

1. 질문을 먼저 정하고 답에 필요한 선행 설명을 적는다. 롱폼은 각 핵심 소주제의 **필요성 → 구체적인 작동 과정 → 같은 대상을 따라가는 예 → 결과·일상 영향·한계**를 내레이션과 화면에 연결한다. 기업은 확인된 사례로 짧게 언급한다.
2. 숏폼은 별도 대본으로 **한 질문·한 메커니즘·한 예·완결된 답**을 만든다. 롱폼의 여러 절에서 한 문장씩 붙이지 않는다. 자산은 재사용해도 설명의 연결을 다시 검토한다.
3. 기본 30~45초(기본 선택값 45초)는 실험 구간이다. 명시적인 목표 길이는 유지하고, 시간이 부족하면 부수 주제를 덜어낸다. 인과·예시·결말을 삭제하거나 추가 배속으로 해결하지 않는다. 명시적 길이 제한 없는 롱폼은 필요한 설명을 기준으로 길이를 정한다. 모든 롱폼을 8~10분으로 강제하지 않는다.
4. 첫 1~2초에 질문과 의외의 현상을 보여준다. 무음으로도 핵심 대상과 짧은 질문이 보이게 한다. 본문은 행동→변화→결과를 이어 보여주고 긴 서론·반복만 줄인다. 결말에서 답한 뒤 처음 대상을 새롭게 이해하게 한다. 미완성 문장·답 숨기기로 루프를 만들지 않는다.
5. 완성 대본을 별도 LLM 호출로 검토한다. **focus/why/mechanism/example/payoff/pacing/visuals** 각각 판정 이유와 실제 대본·화면 설명 인용이 필요하다. 실패 시 한 번 보완하고 재검토한다. 다시 실패하거나 검토가 없으면 **TTS·유료 미디어 생성 전에 중단**한다. 수동 제작에서도 반드시 이 게이트를 거친다.
6. 영상·음성/스타일을 재사용해도 현재 대본과 화면 설명으로 재검토한다. 검토 digest가 바뀌면 이전 판정은 무효다. 드라마·광고는 동기→행동→결과와 구체적인 사건/제공된 제품 사실로 검토하며 억지로 강의화하지 않는다.

## 수동/CLI 제작과 공통 검토

구현 브랜치의 `apps/shopshorts/lib/explanation-depth.js`가 웹 시나리오와 아래 CLI의 단일 검토 기준이다. 기존 수동 렌더 스크립트를 자동으로 가로채지는 않는다. **새 제작 스크립트의 TTS/미디어 실행 전에 아래 검증 명령 성공을 필수 조건으로 연결**한다. 현재 main에 명령이 없으면 해당 기능 PR의 머지 여부를 확인하고 검증된 구현 worktree를 사용한다.

`draft.json`: `{brief:{category,topic,format,duration,...},title,scenes:[{id,narration,prompt,duration,...}],research?}`. 수동 `beats[].text`는 `scenes[].narration`으로, 실제 화면 계획은 `prompt`로 옮긴다. 숏폼과 롱폼은 별도 입력/검토 파일을 만든다. 작업 파일은 지정 작업 산출물 폴더에 둔다.

```sh
node apps/shopshorts/studio-script-review.mjs --project "$TASK_ARTIFACTS/draft.json" --prompt
# 출력된 프롬프트를 연결된 LLM의 새 검토 요청으로 전달하고 JSON 응답을 review.json에 보관한다.
node apps/shopshorts/studio-script-review.mjs --project "$TASK_ARTIFACTS/draft.json" --review "$TASK_ARTIFACTS/review.json"
# exit 0일 때만 TTS/미디어 생성으로 진행한다. 수동으로 pass:true를 채우지 않는다.
```

검토 파일은 SHA-256으로 brief/title/scenes/research와 묶인다. 임의 인용·빠진 항목·이전 대본 검토는 거부한다. 해시는 서명/인증 수단이 아니다. LLM 판정은 확률적이고 정확성을 보장하지 않으므로 출처 확인과 사람 검수, 실제 렌더 후 자막·화면·말속도 검증을 유지한다. 화면 프롬프트 합격은 완성 영상의 이해도나 첫 2초 후킹 실측이 아니다.

## 조회수 피드백 해석과 다음 실험

사용자가 제공한 '약 1,200회 정체, 계속 시청함 약 50%, 일부 APV 35~45%/160% 이상'은 이번 세션에서 Analytics 원자료를 직접 조회한 수치가 아니다. 1,200회가 고정 노출 상한이거나 70%/80%가 확산 합격선이라고 단정하지 않는다. YouTube는 시청 선택, 평균 지속시간·조회율, 만족도 신호 외에도 주제 관심도·경쟁·계절성을 설명한다. [공식 검색·발견 안내](https://support.google.com/youtube/answer/11914225?co=YOUTUBE._YTVideoType%3Dshorts&hl=ko)

다음 영상은 같은 분야·유사 길이의 영상끼리 게시 후 같은 기간(예: 24시간/7일)과 Shorts 피드 유입을 맞춰 비교한다. 노출/피드 표시 수, 계속 시청함, 참여 조회수, 평균 시청 초·조회율, 유지율 이탈 지점을 함께 기록한다. 첫 화면 개선과 본문 개선을 구분한다. 160% 조회율 하나로 전체 피드 시청자가 몰입했다고 판단하거나 30초 영상과 90초 영상을 비율만으로 비교하지 않는다. 데이터가 충분하지 않으면 원인은 가설로 남긴다.
