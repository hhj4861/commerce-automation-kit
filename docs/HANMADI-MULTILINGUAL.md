# Hanmadi 다국어 학습과 LiteLLM 회화

기존 한국어 팩·학생 기록을 유지하면서 `/learn`에 한국어·태국어·일본어 입문 회화를 추가한다. 언어별 인사·카페 주문·길 묻기 3개 수업, 표현과 발음 보조 표기, 퀴즈, 브라우저 진도 저장을 제공한다. 설명은 한국어다. 기존 한국어 팩은 영어 설명을 유지한다. 새 콘텐츠는 입문용이며 완전한 문자·문법·성조 커리큘럼은 아니다.

## 사용 흐름

1. 헤더의 언어 학습 또는 학생 포털의 Language practice를 연다.
2. 언어와 수업을 선택해 표현·퀴즈를 연습한다. 진도는 언어 및 학생 링크별로 브라우저에 저장된다.
3. ‘이 주제로 AI와 대화하기’를 누른다. 입문/중급 난이도로 최대 10회 주고받고 새 대화를 시작한다. AI는 목표 언어로 응답하고 한국어 풀이·교정을 제공하도록 지시받는다. 모델의 지시 준수는 보장되지 않는다.

회화는 **음성 + 텍스트**를 지원한다. ‘마이크로 말하기’ → 최대 45초 녹음 → LiteLLM 음성 인식 → 인식된 문장 확인·수정 → 보내기 → AI 답변과 자동 음성 재생 순서다. 자동 듣기를 끄거나 마지막 답변을 다시 들을 수 있다. 녹음 취소·권한 거부·미지원 브라우저·타임아웃은 화면에 안내하고 텍스트 입력을 유지한다. 마이크는 HTTPS 또는 localhost에서만 사용할 수 있다.

발음 채점과 대화 기록의 영구 저장은 포함하지 않는다. 대화·녹음·답변 음원은 현재 탭의 메모리에서 처리되며 새로고침하면 사라진다. 실패하면 입력을 보존하고 다시 보내기 안내를 표시한다. 음성 모델은 한국어 설명과 학습 언어가 섞인 답변을 합성할 수 있어야 한다.

## 서버 설정

앱의 비공개 `.env.local` 또는 배포 서비스의 Secret 환경변수에 설정한다. `NEXT_PUBLIC_` 접두사를 사용하지 않는다.

```dotenv
LITELLM_BASE_URL=https://your-litellm-gateway.example/v1
LITELLM_API_KEY=<앱 전용 가상 키>
LITELLM_MODEL=<LiteLLM에 등록한 model_name>
LITELLM_STT_MODEL=<음성 인식용 model_name>
LITELLM_TTS_MODEL=<음성 합성용 model_name>
LITELLM_TTS_VOICE=<합성 모델이 지원하는 voice>
```

모델명은 앱에서 고정하며 클라이언트가 바꾸지 못한다. `/v1`이 없는 주소도 정규화한다. 원격 연결은 HTTPS, 로컬 개발은 `http://localhost:4000`을 허용한다. 앱에서 LiteLLM 서버를 자동 설치하거나 실행하지 않는다. API 키·모델·서버 주소가 없으면 설정 대기 안내를 표시한다. 음성 모델만 없으면 해당 버튼을 비활성화하고 텍스트 회화는 유지한다. 별도 런타임 SDK 의존성 없이 서버 `fetch`로 공식 OpenAI 호환 `POST /v1/chat/completions`, `/v1/audio/transcriptions`, `/v1/audio/speech`를 호출한다. 서버 주소는 브라우저가 아니라 **앱 서버에서 접속 가능해야** 한다.

운영 환경은 기존 Upstash Redis(`UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` 또는 KV 대응 변수)가 필요하다. 서버리스에서 파일 저장소로 비용 한도를 우회하지 않도록 production + 파일 저장소이면 회화 요청을 거부한다. 로컬 개발은 기존 `.data/tutors.json`을 사용한다. 테스트에 운영 키나 학생 데이터를 복사하지 않는다.

## 접근 및 비용

- 유효한 튜터 세션 또는 저장소에 등록된 학생의 비공개 slug로 접근한다. 기존 학생 포털의 bearer-link 모델을 따른다. 공개 샘플 학생 데이터만으로는 유료 회화를 호출할 수 없다. 포털 링크 유출 시 해당 링크를 가진 사람도 접근 가능하다.
- 요청마다 세션 폐기/학생 존재를 재확인한다. 같은 출처 요청과 실제 본문 크기 64KB를 검사한다. 메시지는 2,000자, 누적 16,000자, 10회 대화로 제한한다.
- Redis 원자 카운터로 UTC 일일 사용자당 대화·전사·합성 각각 30회, 서비스 전체 세 종류 합산 300회 시도를 제한한다. 실패한 호출도 횟수를 소비한다. 호출 횟수 제한은 금액 상한이 아니므로 LiteLLM 가상 키의 예산·모델 허용목록도 운영자가 설정해야 한다. 일별 카운터는 기존 저장소 방식에 따라 보존한다. 음성 업로드는 multipart 포함 3MiB, 합성 응답은 5MiB 이하이며 클라이언트는 45초에 녹음을 끝낸다. 서버의 파일 크기 제한은 음원 재생시간을 보장하지 않으므로 공급자 측 예산 제한도 필요하다.
- 대화 내용·실제 키·상위 서버 오류 본문을 앱 로그에 남기지 않는다. LiteLLM 및 모델 제공업체의 로깅·보관은 별도 설정이며, 앱에서 저장하지 않는다는 설명이 제공업체의 무보관을 뜻하지 않는다.
- 30초 상위 요청 제한, 재시도는 사용자가 수행한다. 미설정·인증·한도·타임아웃·빈 응답은 성공으로 위장하지 않는다.

## 화면 방향

기존 paper `#fff9f2`, ink `#2b2420`, soft `#75655a`, accent `#d9480f`, line `#f0e2d3`, card `#ffffff` 토큰과 Gowun Dodum 제목/IBM Plex Sans KR 본문을 유지한다. 왼쪽에 실제 학습 순서, 오른쪽에 큰 원문·발음 보조·뜻을 둔다. 모바일은 위아래로 쌓인다. 새 카드 대시보드를 늘리는 대신 문장 목록과 퀴즈를 중심에 둔다.

```text
언어 선택
수업 순서 | 오늘의 표현
진도      | 발음 보조 / 뜻
          | 확인 퀴즈 → 이 주제로 AI 회화
```

## 검증

앱 디렉터리에서 `npm ci --workspaces=false`, `npm test`, `npm run lint`, `npm run build`로 재현한다. `npm run test:conversation`은 `.env*`와 `.data`가 없는 격리된 checkout에서 실행하며 ffmpeg가 필요하다. 테스트는 3187/4198 포트의 앱·모의 LiteLLM 서버와 테스트 전용 파일 저장소를 사용한다. `node scripts/conversation-smoke.mjs --serve`는 검사 후 화면 검증용 서버를 유지한다. 운영 키와 학생 데이터는 사용하지 않는다.

2026-09-26 확인:

- 순수 로직 테스트 8개: 언어·역할·길이·모델 설정·타임아웃·응답 검증·음성 요청 계약.
- 격리 HTTP 통합 검사: 세 언어, 튜터/등록 학생 접근, 무인증 차단, 출처/크기 검사, 오류·빈 응답 처리, 31개 동시 요청에서 30회만 허용, 전사 및 바이너리 합성 응답, 기존 라이브러리.
- Chrome 실제 UI: 일본어 퀴즈 완료·새로고침 복원, 태국어 진도 분리, 튜터 로그인, 문장 전송·답변 표시·테스트 음원 자동 재생, 실패 시 입력 보존.
- 실서비스 LiteLLM 연결·실제 마이크 녹음·한국어/태국어/일본어 전사·발음 품질은 미검증이다. 모델 주소·키·모델명·음성을 설정한 뒤 실제 기기로 확인해야 한다. 테스트 음원은 짧은 합성 신호이며 자연어 음성 품질의 증거가 아니다.

## 실제 연결 점검 (2026-09-26)

- 로컬 앱 환경변수와 Vercel `hanmadi` Production 환경변수 목록에 `LITELLM_*` 설정이 없다. `localhost:4000`도 응답하지 않았다. 다른 주소의 미공유 서버가 없다는 뜻은 아니다.
- 프로젝트 루트 `.env`의 ElevenLabs 키: 공식 사용자 조회 API HTTP 200.
- `apps/hanmadi/.env.local`의 ElevenLabs 값: HTTP 400, `api_key_id_used_as_api_key`. 공통 키와 서로 다른 값이다. 운영 Vercel 값은 내려받지 않았으므로 동일 여부·유효성은 미확인이다.
- 프로젝트 루트 Gemini 설정: 모델 목록 조회에서 HTTP 401 `UNAUTHENTICATED` / `ACCESS_TOKEN_TYPE_UNSUPPORTED`.
- 확인은 읽기 전용이며 키 교체·Vercel 환경변수 변경·유료 음성 생성·운영 배포는 수행하지 않았다. 실제 연결에는 LiteLLM 서버, 유효한 대화 모델 인증, 전사·합성 모델과 음성 설정이 필요하다.
