# 건축학 실제 사례 주제 발견 — 2026-09-30

## 동작

자동 제작의 건축학 주제 추천과 수동 제작의 LLM 주제 추천에 공통 적용한다. 실제 장소·건축물·시설 → 눈으로 보고도 궁금한 현상 → 이유와 원리 → 첫 장면과 질문 순서로 조사한다. 고정된 유명 사례 목록은 프롬프트에 넣지 않는다. 국내 요청은 관심사에 `국내의 신기한 실제 건축 사례`처럼 입력한다.

각 후보의 `caseStudy`는 대상, 위치, 의외의 사실, 핵심 원리, 첫 장면, 검색 출처 참조를 담는다. 필수 항목이나 sources 연결이 빠지면 한 번 재생성한 뒤 명시적으로 실패한다. URL 형식·출처 연결 검증은 주장 자체의 진실성 검증이 아니다. 1차 출처 확인은 검색 지침이며 최종 대본 사람 검토를 유지한다.

기존 계정 소유 추천 이력 최대 10개를 이용한다. 동일 대상(정규화·접두/접미 이름 포함)과 동일한 핵심 원리 문자열을 거절한다. 이전 메타데이터가 없으면 주제에 동일 대상이 있는지 확인한다. 의미가 같지만 표현이 다른 원리·별칭의 완전한 탐지는 보장하지 않으며 모델 자체 검토도 함께 요청한다. 이전 저장 결과는 계속 사용할 수 있다.

두 화면의 추천 카드에 실제 사례, 의외성, 첫 장면을 표시한다. 자동 제작 선택 시 브라우저가 보낸 기획을 믿지 않고 소유 계정에 저장된 결과에서 해당 후보를 읽어 프로젝트의 automation.caseStudy에 보존한다. 주제와 연출에는 사례·핵심 답·그림 흐름을 포함하도록 하고 시나리오의 건축학 편집 지침도 이를 유지한다.

## 검증과 운영 반영

- 관련 Node 테스트 34개 통과: 두 provider 공통 계약, 출처 누락/위험 URL 거절, 재생성·취소, 중복, 과거 결과 호환, HTML 이스케이프, 소유 계정 선택, 실제 HTTP 정적 자산·로컬 워커.
- 실제 Chrome의 격리 서버에서 건축학 선택 → 국내 관심사 입력 → 추천 카드 → 후보 선택 → 프로젝트 생성·새로고침 후 저장 복원 확인. provider 결과는 명시적인 테스트 fixture이며 실제 LLM 성공 증거가 아니다. 기존 브라우저 fixture의 후속 시나리오는 현재 검증 스키마에 맞지 않아 실패를 표시했다. 이번 UI 검증은 추천·선택·저장 범위다.
- 실제 Codex 기본 180초 호출은 CODEX_TIMEOUT으로 실패했다. 진단용 360초 호출은 약 180초에 실제 검색을 마쳐 여수 엑스포 주제관, 문화비축기지 T6, 경주 석빙고를 생성했다. 이 결과를 보고 건축학의 최근 30일 뉴스 의무 검색을 제거하고 사례·설계 근거가 확보되면 추가 행사 검색을 멈추도록 보완했다. 최종 프롬프트는 기본 180초 제한에서 149초에 성공했으며 영도대교·이화캠퍼스복합단지·장경판전을 반환했다. 운영 timeout 설정은 변경하지 않았다.
- PR 머지 전이며 운영 미반영. 변경 소스만으로 완료라고 판단하지 않는다.
- 머지 승인 후 동일 승인 리비전으로 Pages와 실제 Codex/Claude 계정 워커를 함께 갱신하고 운영 로그인 계정의 새 추천을 검증해야 한다. Pages만 배포하면 계정 워커의 추천 프롬프트는 갱신되지 않는다.
- 확인 시 origin에 deploy/shopshorts 브랜치가 없었다. GitOps 설정 파일 존재를 자동 배포 활성화 증거로 간주하지 않는다. 운영 배포 전 최신 배포 리비전과 다른 세션 변경을 확인하고 기존 승인 배포 경로를 사용한다.
