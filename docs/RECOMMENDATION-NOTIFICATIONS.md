# 추천 백그라운드 실행과 완료 알림

추천 패널의 X·Escape·닫고 계속하기는 화면만 닫는다. 생성 취소 버튼만 서버 작업을 취소한다. 닫힌 패널은 완료되어도 다시 열리지 않으며 입력란의 진행 보기 또는 알림함에서 사용자가 연다.

이미 접수된 요청은 입력 수정·화면 이동·새로고침 후에도 실행기가 계속 처리한다. 클라이언트 감시가 끊기거나 네트워크 오류가 나도 취소 요청을 보내지 않는다. 명시적 취소는 서버 응답까지 확인하며 실패를 숨기지 않는다. OAuth 연결 화면의 연결 취소 동작은 별도다.

## 저장과 권한

- Credential Broker가 추천 작업의 `done`/`failed` 상태를 저장할 때 결과·입력·알림 읽음 상태를 같은 암호화 계정 레코드에 한 번의 CAS 갱신으로 기록한다. 브라우저가 열려 있을 필요가 없다.
- 작업 ID로 중복을 막는다. 새 작업·계정 연결 해제 후에도 결과는 남는다. 읽음 상태는 실행기가 보낸 이전 사본으로 덮어쓰지 않는다.
- 최근 최대 10개를 보관한다. 실행기 요청 크기 제한을 지키기 위해 결과 이력 합계가 120KB를 넘으면 오래된 항목부터 줄인다.
- `/api/studio/llm/notifications`, `recommendation`, `notification-read`는 기존 로그인에서 서버가 결정한 계정 소유자만 사용한다. 클라이언트가 보낸 소유자 값으로 조회할 수 없다. 토큰은 응답에 포함하지 않는다.
- 기존 알림함은 작업 알림과 개인 추천 알림을 함께 표시한다. 읽음·안 읽음·모두 읽음·설정의 숫자 표시를 동일하게 적용한다. 스튜디오에도 알림함과 안 읽음 숫자를 표시한다.
- 알림에서 `/studio?new=1&recommendation=<작업 ID>`로 이동하면 서버에 보관된 입력과 결과를 복원한다. 적용은 사용자가 선택하며 결과 조회로 새 추천을 생성하지 않는다. 보관 범위를 벗어난 결과는 찾을 수 없다는 안내를 표시한다.

## 검증·배포

계정 격리, 중복 완료, CAS 충돌, 읽음 상태 유지, 이력 제한을 Node 테스트로 확인한다. 실제 로컬 HTTP·암호화 SQLite·큐 워커와 Chrome을 연결해 닫은 후 완료, 알림함 열기, 읽음 처리, 새로고침 복원, 입력 수정·화면 이동 중 생성 지속을 확인한다. 제공사 인증·생성은 테스트 fixture다.

머지 승인 후 Credential Broker → Pages 순서로 배포한다. 테이블 추가나 시크릿 변경은 없다. 실행기의 완료 저장 요청은 기존 계약을 그대로 사용한다. 이 문서는 작업 브랜치 구현 범위를 설명하며 운영 반영 증거를 대신하지 않는다.
