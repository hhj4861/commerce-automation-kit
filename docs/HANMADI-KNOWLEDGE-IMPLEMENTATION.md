# 한마디 콘텐츠 스튜디오 구현·운영 인수

2026-09-29 최초 구현, 2026-09-30 영상 검색 UX 추가. [학습 구조·계획](HANMADI-KNOWLEDGE-PLAN.md)을 작성한 뒤 [관리자 HTML 시안](hanmadi-admin-mockup/index.html)을 만들고 기능을 연결했다. 구현 위치는 Hanmadi 2.0의 기존 소유자 전용 `/study/admin`이다. 별도의 관리자 작업 화면이며 별도 서버·도메인 배포는 아니다.

## 구현된 흐름

- **영상 찾기**: YouTube 공식 검색으로 페이지당 최대 5개를 표시한다. 현재 페이지 전체 선택/해제, 페이지 간 선택 유지, 중복 제거, 영상별 자료 준비 목록을 제공한다. 선택한 영상의 출처·언어·상황을 새 자료에 연결한다.
- **자료 만들기**: 사용권 있는 원문 입력, AI 초안 생성, 언어/레벨/상황 지정, 뜻·한글 발음·개인정보·권리 검수, 게시·게시 내림. 게시 전 목표 언어와 한글 발음을 서버에서도 검사한다.
- **번역 후보함**: 학습자가 해당 번역 요청에 공용 제공을 명시적으로 동의했을 때만 일반 표현을 받는다. 기존 개인 복습 동의와 별도다. 동의 체크는 번역 완료 후 해제된다. 후보는 비공개이며 관리자가 반려하거나 AI로 교재 초안을 만든다.
- **앱 반영**: 게시된 교재를 레벨별/상황별 수업에 노출한다. AI 대화는 같은 언어·레벨·상황의 표현을 최대 4개 참고한다. 번역은 같은 언어에서 입력 어휘와 관련된 게시 예시만 참고한다. 현재 검색은 단어·CJK/태국어 인접 글자 비교이며 벡터 검색이나 가중치 학습은 아니다.
- **적용 미리보기**: 관리자 화면에서 앱과 동일한 검색 함수로 전달될 게시 예시를 확인한다. 모델 API를 호출하지 않는다.
- **회수**: 학습자가 제공한 공용 후보와 그 후보에서 만든 교재를 함께 제거한다. 늦게 도착한 번역 저장과 교재 생성도 CAS/제공 세대로 차단한다. 다른 사용자의 자료는 회수하지 못한다.
- **이력**: 교재 버전과 초안 저장/게시/게시 내림/반려/회수 이력을 보관한다. 이력은 최근 500개다. 사용자 회수 시 해당 후보·교재의 이력도 제거하고 개인정보 없는 회수 사건만 남긴다.

번역 원문 전체, 원음, 대화 기록, 입력 대본은 이 학습 저장소에 보관하지 않는다. 후보에는 삭제 연결을 위한 서버 측 가명 actor를 보관하며 관리자 API에서 제외한다. 완전 익명화가 아니며 표현의 개인정보 가능성은 게시 전 사람이 확인해야 한다. 사용자에게 이미 전달한 AI 답변과 공급자 로그를 소급 삭제하는 기능은 없다.

## 저장 계약과 배포 전 필수 확인

기존 Redis `hanmadi:v2` 해시의 `curriculum` 필드 하나에서 후보·교재·제공 세대·이력을 CAS로 갱신한다. 구형 배열은 읽기 호환되고 **첫 변경 요청 때 `version: 1` 객체로 전환**된다. 이번 작업에서 실제 운영 Redis를 변경하지 않았다.

**구형 앱은 새 객체 형식을 읽지 못하므로 운영에서 구형/신형 쓰기 요청을 혼합하지 않는다.**

운영 반영 절차:

1. 승인된 배포 전 기존 `curriculum` 값을 제한된 운영 백업에 저장한다. Git·일반 로그·채팅에는 출력하지 않는다. 복구 담당자와 보관/삭제 정책을 정한다.
2. 쓰기 중지 구간 또는 요청 드레인으로 구형 배포의 교재/번역 요청을 종료한다. 전체 앱을 새 버전으로 전환하고 구형 배포 URL로 같은 운영 DB에 쓰는 요청을 차단한다.
3. 새 버전의 owner/학습자 권한, Redis CAS, 게시→앱 수업→실제 LiteLLM 추론, 회수→검색 제외를 운영 테스트 계정으로 확인한 뒤 쓰기를 재개한다.
4. 전환 이후 데이터가 생겼다면 과거 백업을 덮어써 복구하지 않는다. 회수한 자료가 되살아날 수 있다. 새 스키마를 읽는 수정 버전으로 전진 복구한다. 구형 바이너리로 단순 롤백은 지원하지 않는다. 역마이그레이션은 동시 쓰기 중지와 현재 후보/철회 상태 보존을 포함하는 별도 검토 작업이다.

기존 서버 환경변수만 사용한다. `AUTH_SECRET`, 소유자 `TUTOR_PINS`, Redis REST 설정, LiteLLM 기본 모델/앱 키, 선택적 `YOUTUBE_API_KEY`. 새 인프라나 gateway DB migration은 없다. 운영 Redis가 없으면 기존 정책대로 파일 폴백을 거부한다.

## 한도와 실패 표시

교재 200개, 후보 전체 500개·사용자별 50개, 참고 예시 최대 4개. 기존 AI 요청 예산과 관리자 생성 한도를 유지한다. 후보함 가득 참, 안전한 일반 표현 없음, 저장 실패, 제공 철회는 번역 결과와 별도 상태로 표시한다. 저장 실패를 학습 성공으로 표시하지 않는다. 후보의 반려 상태도 보관 한도에 포함된다. 운영상 대량 유입이 생기면 보관 만료/정리 작업과 분할 저장을 추가해야 한다.

참고 표현은 신뢰할 수 없는 데이터라는 지시와 함께 JSON으로 전달하며 기존 모델 선택·출력 스키마·응답 언어 검사를 유지한다. 프롬프트만으로 모든 지시문 주입을 막는다는 보장은 하지 않는다. 운영 전 고정 평가셋에서 실제 공급자 응답 품질을 검증한다.

## 검증 범위

- 단위 테스트 65개 통과. 신규 8개는 구형 데이터 보존, 언어/상황/레벨 검색 격리, 관련 없는 번역 제외, 제공자별 중복/삭제, 철회 경합, 출처 변경 차단, 오래된 버전 충돌, 모델 프롬프트 전달을 검증한다.
- `npm run lint`: 오류 0. 변경 전부터 있던 범위 밖 unused 경고 4개 유지.
- `next typegen` 후 `tsc --noEmit`: 통과.
- `npm run build -- --webpack`: 운영 번들·타입·47개 페이지 생성 통과. 기본 `npm run build`의 Turbopack은 로컬 실행 환경의 임시 포트 bind `EPERM`으로 실패했다. 코드가 기본 빌드에 통과했다고 바꿔 보고하지 않는다. webpack 실행에서도 기존 middleware/Edge 관련 경고가 있다.
- 브라우저 E2E: 격리된 Next API·파일 저장소와 **테스트용 AI 응답 서버**를 사용한다. 기존 가입·번역·언어·회화·개인 모델·관리자 권한 회귀 흐름과 신규 공용 자료 제공→검수→게시→수업/추론 입력→회수를 검사한다. 실제 사용자 데이터·실제 AI 과금·운영 Redis·YouTube OAuth는 사용하지 않는다.

실제 서비스의 언어 교육 품질·원어민 감수, 개인 연결 공급자의 로그 보존, OAuth 자막 수집, 파인튜닝 비용·지원 모델은 미확인이다. [계획 문서](HANMADI-KNOWLEDGE-PLAN.md)의 후속 인수 조건으로 남긴다.

## 영상 검색 UX 추가 — 2026-09-30

`feat/hanmadi-video-search-selection`에서 영상 검색을 관리자 첫 탭으로 분리했다. 검색 결과와 자료 준비 목록을 나란히 배치하고 모바일에서는 세로로 연결한다. 모바일 준비 목록 바로가기, 선택 개수 안내, 일부 선택 상태, 키보드 선택, 오류 재시도, 썸네일 실패 시 대체 표시를 제공한다.

- 실제 페이지 이동은 공식 API의 `nextPageToken`을 사용한다. [YouTube search.list 문서](https://developers.google.com/youtube/v3/docs/search/list)에 따라 근사치인 `totalResults`로 전체 페이지 수를 만들지 않는다. 결과가 5개 미만이거나 비어 있어도 다음 토큰이 있으면 이동할 수 있다.
- 확인한 페이지로 돌아가면 메모리 캐시를 사용한다. 새 검색은 페이지를 1로 되돌리되 선택 목록을 유지한다. 검색 실패 시 기존 결과·선택을 보존한다. 기존 하루 20회 검색 예산은 유지하며 새 페이지 조회도 1회로 계산한다.
- 선택 목록과 검색 결과는 열린 화면의 메모리에만 존재한다. 새로고침 시 비워지며 서버·로컬 스토리지에 YouTube 메타데이터를 축적하지 않는다.
- 목록의 ‘자료 만들기’는 영상별 새 자료를 준비한다. 작성 중인 내용이 있으면 교체 확인을 받고, 사용권·원문·검수 상태는 영상마다 새로 입력한다. 일괄 선택만으로 AI 생성·저장·게시하지 않는다. 영상·자막 자동 수집은 추가하지 않았다.
- YouTube 검색 어댑터 테스트 5개를 포함해 단위 테스트 72개 통과. 변경 파일 린트 오류/경고 0, 전체 린트의 기존 경고 4개 유지. 타입 검사와 기본 Turbopack 운영 빌드 통과.
- 공식 YouTube API 실호출에서 첫 페이지 5개, 다음 페이지 5개와 공식 썸네일 주소를 확인했다. 브라우저 회귀 검증은 검색·썸네일만 고정 응답으로 대체하고 실제 소유자 권한/관리자 API/자료 편집기를 사용한다. 운영 AI·Redis 데이터는 변경하지 않는다.

이 절의 변경은 작업 브랜치 구현 기록이다. 해당 PR의 별도 머지 승인과 배포 전에는 운영 반영으로 간주하지 않는다. 위의 최초 구현 검증·배포 전제 기록과 구분한다.
