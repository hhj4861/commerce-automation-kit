# Hanmadi 영상 검색 → 일괄 자료 만들기

2026-09-30. 검색 결과 수, 모든 페이지 선택, 준비 목록의 영상별 일괄 초안 생성.

## 사용자 흐름

1. 검색 결과에 `검색 결과 약 N개`를 표시한다. YouTube가 개수를 제공하지 않으면 확인 불가로 표시한다. 한 페이지에는 최대 5개를 유지한다.
2. `이 페이지 모두 선택`은 현재 5개만, `모든 페이지 전체 선택`은 아직 열지 않은 페이지까지 확인해 준비 목록에 담는다. 영상 ID로 중복을 제거한다. 다른 검색에서 담은 항목은 유지한다.
3. 준비 목록에서 공통 레벨과 전체 원문에 적용되는 사용권 근거를 입력한다. 영상별로 원문을 붙여 넣거나 파일을 연결한다. 여러 파일은 `영상 ID.txt`, `.srt`, `.vtt` 이름으로 자동 연결한다. 이름이 다르면 각 영상의 원문 파일 입력을 사용한다.
4. 모든 대상 영상에 원문이 있고 사용권을 확인하면 `전체 자료 만들기`가 활성화된다. 클릭 한 번으로 영상마다 별도 초안을 순서대로 생성·저장한다. 영상별 출처 URL, 언어, 상황, 원문 해시를 유지한다.
5. 완료한 영상에는 `초안 검수`를 제공한다. 완료 항목은 다음 일괄 실행에서 제외한다. 생성된 초안은 기존 콘텐츠 목록에 들어가며, 기존 사람 검수·게시 이후에만 앱에 반영한다.

영상 하나씩 편집 화면으로 이동해 생성하던 동작은 준비 목록의 공통 실행으로 교체한다. 원문 없이 검색 메타데이터만으로 생성하거나 영상·자막을 자동 다운로드하는 경로는 추가하지 않는다.

## 화면 구성

기존 파랑 `#3157D5`, 본문 `#182B49`, 보조 `#64748B`, 배경 `#F5F7FC`, 종이 `#FFFFFF`, 완료 `#166A55`와 한글 시스템 글꼴을 유지한다. 왼쪽은 5개씩 비교하는 검색 목록, 오른쪽은 공통 설정 → 영상별 원문·상태 → 일괄 실행으로 구성한다. 모바일에서는 준비 목록이 검색 아래로 이어진다. 현재 페이지 선택과 전체 페이지 선택을 별도 영역으로 표시해 범위를 구분한다.

## 결과 수와 검색 경계

[YouTube 공식 search.list 문서](https://developers.google.com/youtube/v3/docs/search/list)에 따르면 `pageInfo.totalResults`는 추정치다. 이 값으로 페이지 수나 완료 여부를 계산하지 않는다. `nextPageToken`이 없어질 때까지 확인하며, 빈 페이지에 다음 토큰이 있어도 계속 진행한다. 반복 토큰은 감지해 중단한다.

전체 선택 중에는 확인한 페이지 수와 선택 수, 중지 버튼을 표시한다. 오류·기존 일일 검색 예산(서버 전체 20회)에 도달하면 부분 선택임을 표시하고 이미 담은 항목을 유지한다. 재실행은 현재 화면에서 마지막 성공 페이지 다음부터 진행한다. 예산을 늘리거나 우회하지 않는다. 추정 결과 전부를 가져올 수 있다고 보장하지 않는다.

## 생성과 실패 처리

- 기존 소유자 전용·동일 출처 검증이 있는 `/api/study/admin`의 `generate`를 영상별로 순차 호출한다. 서버의 원문 길이(20~12,000자), 사용권 확인, 표현 검증, 일일 콘텐츠 작업 한도는 유지한다.
- 입력하지 않은 원문을 조용히 건너뛰지 않는다. 원문이 빠진 수를 표시하고 실행 전 연결하도록 한다. 연결할 수 없는 파일명·형식·길이도 표시한다.
- 처리 중에는 준비 목록과 검색, 다른 관리자 메뉴를 잠근다. 중지는 현재 영상의 응답까지 받은 다음 남은 작업을 시작하지 않는다. 실행 중 새로고침·페이지 이탈은 브라우저 확인을 표시한다.
- 성공 응답을 받은 영상은 다시 생성하지 않는다. 명확한 입력 오류는 해당 영상에 표시하고 나머지를 진행한다. 인증·한도 오류는 더 진행하지 않는다. 실패 항목과 아직 시작하지 않은 항목은 명시적인 다음 실행 대상이다.
- 네트워크 단절·응답 유실·서버 오류는 저장 여부를 단정할 수 없으므로 `완료 여부 확인 필요`로 남기고 중단한다. 자동 재시도하지 않으며 콘텐츠 목록에서 저장 여부를 확인한다. 서버 백그라운드 작업이나 영구 생성 작업 큐를 추가한 것은 아니다.
- 준비 목록·입력 원문·진행 상태는 현재 브라우저 화면에만 있다. 저장 완료한 초안은 기존 서버 저장소에 남는다. 새로고침하면 준비 중인 목록이 사라짐을 화면에 안내한다.

## 검증 범위

단위 검증: API 결과 수 파싱, 0과 미제공·잘못된 값 구분, 공식 5개 검색 요청과 토큰 전달.

브라우저 검증: 실제 Next API·소유자 인증·저장소를 사용한다. YouTube 응답과 LLM 응답만 fixture로 제공한다. 기존 페이지 선택·캐시·5개 표시, 총개수, 미방문 페이지 전체 선택, 중단·재개, 한도 오류 뒤 이어 선택, 중복·빈 페이지, 파일 일괄 연결과 누락 차단, 영상별 별도 초안·출처 해시, 현재 영상 완료 후 중지, 실패 항목만 재시도, 서버 저장 후 응답 유실의 재생성 차단, 검수 화면 연결과 모바일 화면을 확인한다. 실제 운영 자료 생성·게시·학습은 검증에 포함하지 않는다.

로컬 확인 결과: 단위 테스트 86/86, TypeScript, 변경 파일 ESLint, 기본 Turbopack 운영 빌드 통과. 전체 브라우저 E2E에서 위 신규 흐름과 기존 학습·번역·모델 연결·학습 관리 흐름 통과. 8개 영상의 개별 초안과 서로 다른 원문 해시를 실제 테스트 저장소에서 확인했다. 미저장 편집의 취소·보존과 응답 유실 후 콘텐츠 목록의 이전 필터 초기화도 확인했다. 운영 머지·배포 전 작업 브랜치의 검증이며 실제 공급자 호출은 하지 않았다.
